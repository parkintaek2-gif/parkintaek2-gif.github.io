## 1부. 🔴 먼저 — 내가 틀린 것을 물린다

오늘 오전에 나는 사장님과 전 유닛에 이렇게 말했다.

> 「한국저작권위원회_공유마당 **만료저작물 738,714건** … 이미지가 없어 못 만들던 지면이
>  여럿이었는데, **이미지 제약을 푸는 길**일 수 있습니다」

**틀렸다.** 자료를 실제로 받아 보니 두 자료가 전혀 다르다.

| 자료 | 총건수 | 그림 주소가 있는 것 | 무엇인가 |
|---|---:|---:|---|
| 공유마당 **사진** | 331,259 | **1,000 / 1,000** | ✅ 진짜 이미지다 |
| 공유마당 **만료저작물** | 738,714 | **0 / 991** | ⛔ 이름·설명뿐인 «목록»이다 |

만료저작물의 첫 항목은 이렇게 생겼다 —

```
TITLE   '관'자가 새겨진 주칠 대접('官'銘朱漆大楪), 안압지(雁鴨池) 바닥면(底部外面)
FORMAT  Text          ← 그림이 아니다
IMAGE_OBJECT  (빈칸)
ISSUED_DATE   통일신라
```

⛔ **큰 수를 보고 「이미지가 73만 장」이라 읽은 것이 잘못이다.**
   자료 «이름»만 보고 내용을 짐작했다. 받아 보기 전에 말한 것이 원인이다.

⭐ 그래도 결론은 산다 — **쓸 수 있는 이미지는 331,259장이다.** 적지 않다.

## 2부. 이용허락 — **표본 25건이 다 「제1유형」이었다**

⛔ **이 API 에는 라이선스 칸이 없다.** 그래서 항목 지면을 열어 재는 수밖에 없었다.

```
표본        25건 (씨앗 20260904 — 다시 재면 같은 표본이 나온다)
결과        25건 «전부» 제1유형 (출처표시만 · 상업적 이용 가능)
95% 구간    86.7% ~ 100.0%   (윌슨)
```

⛔ **「전부 제1유형」이라 말하지 않는다.** 25건으로 33만 건을 말할 수는 없다.
✅ 잰 것은 **「적어도 87%」**다. 표본을 늘리면 이 아래 끝이 올라간다.

⚠ 그리고 앞서 내가 낸 「공공누리 제1유형 **610,526장**」은 **누리집 화면 필터**로 센 수다.
   그 필터는 «이미지 전체»(1,389,260장)를 대상으로 하고, 우리가 API 로 받는 «사진»
   331,259건과 같은 모집단이 아니다. **두 수를 같은 것으로 쓰지 않는다.**

## 3부. 이미지를 실제로 받는 법 — **덫이 셋이다**

### 덫 1. `http` 로 부르면 **503** 이다

API 가 돌려주는 `IMAGE_OBJECT` 는 `http://` 로 시작한다. 그대로 부르면 503 이 온다.

```
http://gongu.copyright.or.kr/…/wrtFileImageView.do?…   → 503
https://gongu.copyright.or.kr/…/wrtFileImageView.do?…  → 200
```

### 덫 2. **referer 가 없으면 막힌다**

항목 지면을 먼저 열어 세션을 얻고, 그 지면 주소를 `referer` 로 실어야 200 이 온다.

### 덫 3. 🔴 「thumbAt 을 빼면 원본」이 **아니다** — 오히려 작아진다

```
thumbAt=Y&thumbSe=t_thumb   →   61KB   (작은 섬네일)
thumbAt 을 뺀 것             →   19KB   ⛔ 더 작다. 내가 「원본」이라 짐작한 것이 이것이다
thumbSe=b_tbumb             →  670KB   ⭐ 이것이 큰 판이다
```

⚠ **`b_tbumb` 는 오타처럼 보이지만 그쪽 서버가 쓰는 «실제 값»이다.**
  `b_thumb` 로 고쳐 쓰면 안 된다.

### 원본 파일 자체는 «동의»가 필요하다

지면에 이런 경고가 있다 — 「이용 범위 확인 후 동의해 주셔야 다운로드가 가능합니다」.
⬜ 그 동의를 거친 «원본 파일» 경로는 **아직 안 재 봤다.**
✅ 다만 `b_tbumb` 670KB 는 동의 없이 열리고, 웹 지면에 쓰기에 충분한 크기다.

## 4부. 그래서 네 사이트가 무엇을 할 수 있나

우리 CLAUDE.md 가 못박아 둔 것 —
「소속사 사진처럼 **언론 관행에 기대는 이미지 사용을 하지 않는다**」.

```
✅ 쓸 수 있다   공유마당 «사진» 331,259장 · 큰 판 670KB 안팎 · 표본상 제1유형(출처표시)
✅ 붙일 것      출처를 지면에 적는다 — 「한국저작권위원회 공유마당, 공공누리 제1유형」
⬜ 못 쟀다      항목별 유형을 33만 건 다 재지는 않았다 (표본 25건 · 적어도 87%)
⛔ 쓰지 않는다   만료저작물 738,714건 — 그림이 없다. «목록»이다
```

⚠ **쓰기 전에 그 항목의 유형을 한 번 더 본다.** 표본이 87%라는 것은
   **100건 중 열 몇 건은 다를 수 있다**는 뜻이다. 그 열 몇 건이 하필 우리가 고른 것일 수 있다.

## 5부. 재는 법

```bash
node scripts/collect-kcisa-gongu.mjs --재기                 # 자가시험 14가지
node scripts/collect-kcisa-gongu.mjs --갈래=photo --pages=10 # 표본
node scripts/collect-kcisa-gongu.mjs --갈래=photo            # 전량 3,313쪽
```

⚠ `.env` 에 `KCISA_GONGU_PHOTO_KEY` · `KCISA_GONGU_EXPIRED_KEY` 가 필요하다.
  **키는 자료마다 다르다** — 하나로 둘을 부르면 401 이 온다.
  그리고 `numOfRows=1` 은 504 를 돌려준다. 5부터 200 이 온다.

## 6부. 이 일에서 배운 것

⭐ **큰 수를 먼저 말하지 않는다.** 「738,714」가 눈에 띄어서 받아 보기 전에 결론을 냈다.
   받아 보니 그 수는 이미지가 아니라 유물 목록이었다.

⭐ **자료 «이름»은 내용의 근거가 아니다.** 「만료저작물」은 저작권 상태를 말할 뿐,
   그 항목이 그림인지 글인지는 말해 주지 않는다.

⭐ **짐작한 이름으로 주소를 만들지 않는다.** `thumbAt` 을 빼면 원본일 것이라 짐작했는데
   오히려 3분의 1로 작아졌다. 진짜 큰 판의 값은 `b_tbumb` 라는 «오타 같은 값»이었다.
   지면에 있는 주소를 다 긁어 **크기를 재서** 찾았다.
