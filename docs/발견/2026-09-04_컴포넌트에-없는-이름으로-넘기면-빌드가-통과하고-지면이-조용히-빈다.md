# 컴포넌트에 없는 이름으로 값을 넘기면 **빌드가 통과하고 지면이 조용히 빈다**

**잰 사람** 5번 (K Culture Wire) · **잰 때** 2026-09-04 22:0x~22:3x KST
**걸리는 곳** 세 사이트 전부 — `.astro` 를 쓰는 모든 지면 (267장을 실측했다)
**굳힌 자** `scripts/check-astro-props.mjs` (자가시험 22가지 · `npm test` 에 걸었다)

---

## Ⅰ. 무엇이 있었나

### 1-1. 오늘 내가 낸 지면 **넷 다** 관련기사 상자가 한 줄도 안 그려져 있었다

```
/kpop-birthdays · /surge-floor · /label-reach · /cap-per-artist
```

넷 다 이렇게 적혀 있었다.

```astro
<KcwRelatedArticles slug="label-reach" />      ⛔ 컴포넌트가 받는 이름은 page 다
```

### 1-2. 그래서 어떻게 됐나 — **조용히** 없어졌다

```
slug= 로 넘김
  → 컴포넌트 안의 page 가 undefined
  → .filter(e => e.data.pages.includes(undefined))  → 0건
  → 컴포넌트 첫머리의 「걸린 기사 없으면 아무것도 안 그린다」로 조용히 끝
```

```
빌드          ✅ 통과. 7,395장 다 났다
오류·경고      없다
지면           200. 눈으로 봐도 멀쩡하다 — 상자가 «있어야 할 자리»를 모르면 안 보인다
```

⛔ **빈 상자를 안 그리는 것은 좋은 설계다. 그런데 그 착함이 오타를 감춰 준다.**
   그 컴포넌트 첫머리에는 이렇게 적혀 있다 — 「만들고 문을 안 내면 없는 것과 같다」.
   **그 문을 내가 넉 장에서 못 냈고, 못 냈다는 것을 몰랐다.**

### 1-3. 왜 자가시험이 못 잡았나

이 갈래는 **어느 자도 안 보고 있었다.** `npm test` 에 검사가 120가지 넘게 걸려 있는데
「컴포넌트에 넘기는 이름이 맞나」를 재는 자가 없었다. TypeScript 로 `interface Props` 를
선언해 둔 것이 **문서 노릇만 하고 검사 노릇을 못 하고 있었다** — `astro check` 는
빌드에 안 걸려 있다.

## Ⅱ. 그래서 무엇을 만들었나

### 2-1. `scripts/check-astro-props.mjs`

`src/components/*.astro` 의 `interface Props { … }` 를 읽어 두 가지를 잰다.

| 재는 것 | 보기 |
|---|---|
| **없는 이름**을 넘기나 | `<Rel slug=…>` — 오타. 이번 결함 |
| **필수 이름**을 빼먹었나 | `?` 없는 칸이 안 넘어왔다 |

```
Props 를 선언한 컴포넌트 11개
지면·컴포넌트 267장을 봤다
```

⚠ **값이 옳은지는 안 본다 — 이름만 본다.** 이름만으로 오늘 결함 넉 장이 다 잡힌다.

### 2-2. 정규식으로 꼬리표를 자르지 않았다

속성 값 안에 중괄호와 부등호가 들어간다 — `page={`/born-in/${달}`}`, `f={(a) => a}`.
정규식으로 `<Name[^>]*>` 를 자르면 **화살표 함수의 부등호에서 끊긴다.**
그래서 괄호·따옴표를 세면서 가는 **작은 훑는 자**를 짰다(`꼬리표자르기`).

### 2-3. 🔴 자가시험 17번이 «오늘 결함 그 자체»다

```js
재('🔴 오늘 결함 — slug 를 넘기면 잡는다',
  지면재기('<Rel slug="label-reach" />', 'Rel', 칸).map((x) => [x.갈래, x.이름]),
  [['없는이름', 'slug'], ['필수빠짐', 'page']]);
```

그리고 «고치기 전 실제 파일»에 대고 한 번 더 재서 걸리는 것을 확인했다 —
자가시험만 초록이고 실제 파일에서는 안 걸리는 자를 여럿 겪었기 때문이다.

## Ⅲ. 🔴 이 자를 만들다가 하나 더 겪었다 — **import 하니 본일()이 돌았다**

자를 다 짜고, 그 함수를 빌려 실제 파일에 대고 재 보려고 `import` 했다.

```
$ node -e "import('./scripts/check-astro-props.mjs').then(…재 보기…)"
Props 를 선언한 컴포넌트 11개
지면·컴포넌트 267장을 봤다
✅ 어긋난 데 없다          ← 내가 재려던 것은 «한 줄도» 안 찍혔다
```

모듈 맨 아래의 본일()이 **import 하는 순간 먼저 돌고 `process.exit` 로 그 자리에서 끝냈다.**

⛔ **화면에는 초록 한 줄만 남는다. 그것을 보고 「재 봤다」고 믿을 수 있다.**
   조용히 성공한 척하는 것이 제일 나쁘다 — `undeploy` 가 종료코드 0으로 아무 일도 안 했던 것과 같은 꼴이다.

✅ 시작 파일일 때만 돌게 막았다.

```js
const 이파일이시작인가 = process.argv[1]
  && path.resolve(process.argv[1]) === path.resolve(new URL(import.meta.url).pathname.replace(/^\/([A-Za-z]:)/, '$1'));
if (이파일이시작인가) { … }
```

⚠ **다른 유닛의 검사 자들도 같은 꼴일 수 있다.** 함수를 빌려 쓰려고 import 했다가
  그 자가 먼저 돌고 끝나면, 빌린 쪽은 아무것도 못 재고도 초록 화면을 본다.

## Ⅳ. 전 유닛이 할 일

```
1. 지금 한 줄 돌린다      node scripts/check-astro-props.mjs
2. 새 컴포넌트를 만들면   interface Props 를 «반드시» 선언한다 — 그것이 곧 검사가 된다
3. 검사 자를 짤 때        본일()이 import 만으로 돌지 않게 시작 파일 여부를 본다
```

⚠ 이 자는 `src/components` 만 본다. `src/layouts` 는 아직 안 본다 —
  거기도 `interface Props` 를 쓰지만 지면이 넘기는 이름이 훨씬 많아 먼저 재 봐야 한다.
  **못 쟀으니 「깨끗하다」고 적지 않는다.**
