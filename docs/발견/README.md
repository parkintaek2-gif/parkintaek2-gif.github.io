# 발견 — 재서 «확인된» 것만 여기 둔다

> 사장님 지시 (2026-09-03): 「1. 오늘처럼 여러 세션들이 모두 나서 **함께** 일하니 얼마나
> 좋은지 모르겠다. **계속 이렇게 작업하며 스스로 발전하라** 2. **새롭게 확인된 것들은
> 문서로 작성해서 다 공유하라**고 지시해」

---

## 이 폴더가 왜 있나

⛔ **`docs/세션간-메모.md` 에 한 줄 적는 것은 «공유»가 아니다.**
그 파일은 이미 **17만 줄이 넘는다.** 오늘 알아낸 것이 내일이면 아무도 못 찾는다.
실제로 그렇게 잃은 것이 여럿이다 — 「이벤트 캘린더가 이미 있는데 안 보고 콘텐츠 기획을
새로 썼다」(2026-08-02)가 그 꼴이었고, 사장님이 「히스토리 안 찾지」로 두 번 지적하셨다.

✅ 그래서 **찾을 수 있는 자리**에, **제목이 결론인 파일**로 둔다.

---

## 무엇이 「발견」인가

```
✅ 재서 알아낸 것            돌린 명령이 있고, 다른 사람이 다시 재면 같은 수가 나온다
✅ 앞선 결론을 뒤집은 것      틀렸다는 것을 알아낸 것도 발견이다
⛔ 짐작                     「그럴 것 같다」는 발견이 아니다
⛔ 남이 한 말을 옮긴 것       출처를 옮긴 것은 자료이지 발견이 아니다
⛔ 그날 한 일                그것은 업무보고에 적는다. 여기는 «알아낸 것»만 둔다
```

## 문서에 반드시 들어가는 다섯 가지

우리 강령이 이미 정해 놓은 꼴이다. `node scripts/check-findings.mjs` 가 이 다섯을 잰다.

```
1. 결론을 제목에            「노출 470건이 우리 404 로 샜다」처럼 제목이 결론이다
2. 어떻게 쟀나              돌린 명령·본 파일·표본 수. 다음 사람이 다시 잴 수 있게
3. 잰 것과 판단을 갈라 적기   실측은 실측으로, 내 생각은 내 생각으로
4. 못 잰 것을 「못 쟀다」로    0 으로 채우지 않는다
5. 틀렸으면 «물린다»고 적기   앞선 진단을 뒤집었으면 그 사실을 문서 안에 남긴다
```

⭐ **5번이 특히 중요하다.** 2026-09-03 하루에 5번은 같은 주제로 진단을 **두 번 물렸다.**
물린 기록이 남아 있어야 다음 사람이 옛 결론을 되살리지 않는다.

```
3. 두 메모 채널에 «어디에 무엇을 적었다»를 남긴다
   docs/세션간-메모.md  ·  ../klifemap/docs/1번-4번-메모.md
4. 사장님께 드릴 것이면 PDF 로 만든다 — 마크다운은 표가 깨져 못 보신다
```
