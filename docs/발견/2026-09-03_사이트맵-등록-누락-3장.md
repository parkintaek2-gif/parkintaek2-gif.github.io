# 새로 낸 고정 지면 3장이 sitemap.xml.ts 등록을 빠뜨려 통째로 발견 경로에서 빠져 있었다

발견 2026-09-03 16:0x KST · 3번(100yearmap)

> 사장님: 「콘텐트 목표를 달성했는데 순방문자 1명이면 뭔가 잘못됐다고 느끼고 이유를
> 찾아서 고쳐야지.」

---

## 1부. 결론

**지면은 라이브(200)였는데 사이트맵엔 아예 없어서, 구글이 그 지면의 존재 자체를 몰랐다.**

```
/cardiac-arrest   /fall-injury   /volunteer
```
셋 다 오늘 새로 만든 고정 지면이고, curl로는 200이 뜨는데 `src/pages/100y/sitemap.xml.ts`의
하드코딩된 정적-지면 배열에 세 줄 추가하는 것을 빠뜨렸다.

⛔ 이건 **처음 겪는 결함이 아니다.** `/after`·`/region`·`/pets` 등에서 2026-08-06~08-23
사이에 최소 8번 같은 실수가 기록돼 있다. 검사자(`check-100yearmap-launch.mjs`)가 이미
있는데, **오늘 세션 전체에서 이 검사자를 한 번도 돌리지 않아서** 놓쳤다.

---

## 2부. 어떻게 쟀나 — 다른 유닛도 그대로 할 수 있다

```bash
node ... # 사장님 지적("방문자 1명") 이후 처음으로 실행
npm run check:100y:launch
```
결과: `⛔ 연 지면이 사이트맵에 없다 — 3건: /cardiac-arrest, /fall-injury, /volunteer`

이 검사자는 ①canonical·OG 카드 누락 ②사이트맵-라이브 불일치(「검색엔 열렸는데 사이트맵엔
없다」) ③자산 존재 여부 ④반올림 비교 뒤집힘 등을 한 번에 재는 자다. **새 고정 지면을 낼
때마다 배포 전에 반드시 돌려야** 이 결함이 다시 반복되지 않는다.

## 4부. 잰 것과 제 판단을 갈라 적는다

```
실측   npm run check:100y:launch 결과 — 사이트맵에 3건 없음 → 수정 후 0건
실측   curl -s https://100yearmap.com/sitemap.xml | grep -c "cardiac-arrest|fall-injury|volunteer" → 3
제 판단  이 사이트맵 누락이 「방문자 1명」의 «전부»는 아니다 — 5번의 검색노출-병목-2026-09-03.md
        6부(GSC 28일 교차비교)에 따르면 3번은 이미 넷 중 클릭률 1위(2.04%)라 이 표의
        결론과는 «별개» 문제로 다룬다. 겹쳐서 하나의 원인처럼 말하지 않는다.
```

## 5부. ⬜ 못 잰 것

- 사이트맵에 없던 3장이 사이트맵에 들어간 뒤 실제로 노출·클릭이 늘었는지는 **아직 못
  쟀다** — GSC 데이터가 쌓이는 데 며칠~28일이 걸린다. 다음 창에서 재야 한다.
- `check-100yearmap-launch.mjs`가 오늘 함께 잡은 다른 결함(canonical 2장·OG카드 2장·
  자산 누락 1건·반올림 비교 뒤집힘 70건)은 **오늘 것이 아니라 이전부터 있던 것**으로
  보이며, 이 문서는 그것까지 고친 것은 아니다 — 별도로 손대야 한다.

## 6부. 재발 방지 — 규칙으로 못박음

새 고정 지면을 낼 때 배포 전 체크리스트에 `npm run check:100y:launch` 실행을 반드시
넣는다. 지금까지 `check-100y-basis.mjs`·`check-100yearmap-copy.mjs`·`check-100y-broken-links.mjs`
등은 매번 돌렸지만 이 검사자는 빠져 있었다 — 검사자가 «있다»와 «돈다»는 다른 것이다.
