# 하루 두 번 도는 수집기가 아침에 받은 것을 덮고 있었다 — 445건이 사라질 참이었다

발견 2026-09-03 21:0x KST · 5번 · **내가 그날 아침에 지은 자에서 나온 흠이다**

> CLAUDE.md 🔴: 「**아카이빙은 하루도 빠뜨리지 않는다** — 소급이 안 되는 유일한 항목이다.
> 오늘 안 받으면 그날치는 영영 없다」

---

## 1부. 결론

`scripts/collect-community-desk.mjs` 는 하루 두 번(8시·20시) 도는데, 낼 때
`archive/raw/community-desk/<날>.json` 을 **그냥 `writeFileSync` 했다.**

⛔ 그러면 **저녁 실행이 아침에 받은 것을 통째로 지운다.** 커뮤니티 제목은 몇 시간이면
목록에서 밀려 내려가므로 **아침 것은 되찾을 수 없다.**

오늘 12:41 에 445건을 받아 두었고, 20:12 예약이 그것을 지울 참이었다.

⚠ **이 자를 내가 오늘 아침에 지었다.** 우리가 🔴 로 못박은 «소급 불가» 항목을 받는 자를,
바로 그 성질을 깨는 «덮어쓰기»로 지었다.

## 2부. 어떻게 알아챘나 — 아카이빙을 확인하다가 걸렸다

20:14 에 2시간 점검으로 아카이빙 폴더를 눈으로 보다가, 파일이 하루 «한 개»인 것을 봤다.
하루 두 번 도는 자인데 파일이 하나면 둘째 실행이 첫째를 어떻게 하는지 봐야 한다.
그래서 내는 자리를 열어 봤고 `writeFileSync` 였다.

⭐ **폴더를 눈으로 보라는 규칙이 이것을 잡았다.** 「예약이 걸려 있다」로 넘겼으면 못 봤다.

## 3부. 고친 것

같은 날 파일이 있으면 **덮지 않고 합친다.**

```
열쇠            주소 + 제목
처음본때         항목마다 남긴다. 다시 봐도 «안 바뀐다»
다시본때         두 실행에 다 있던 항목에만 붙는다
돈때들           목록으로 쌓는다 — 오늘 몇 번 돌았는지가 아카이빙 증거다
```

## 4부. 🔴 자가시험은 초록인데 «진짜 자료»에서 깨졌다

이것이 이 문서에서 가장 값있는 대목이다.

```
자가시험 다섯 가지  전부 통과 (아침 것 안 잃음 · 겹침 안 셈 · 처음본때 지킴 · 첫 실행 · 주소 없음)
진짜 445건을 넣음   → 439건으로 «줄었다»
```

까닭을 재 보니 **구글 트렌드 열 건이 주소가 하나뿐**이었다 —
`https://trends.google.com/trending?geo=KR`. 낱말별 주소를 안 준다.
주소로만 가르면 **검색어 열 개가 한 개로 뭉개진다.** 아홉을 잃는다.

✅ 열쇠를 **주소 + 제목**으로 바꿨다. 다시 재니 **448건 = 445 + 3**, 하나도 안 잃는다.

⛔ **자가시험이 초록인 것은 「됐다」가 아니다.** 내가 지은 시험은 내가 상상한 자료만 넣는다.
   진짜 자료에는 내가 상상하지 못한 꼴이 있다 — 주소가 겹치는 우물이 그것이었다.

## 5부. 세 번 돌려서 «진짜로» 확인했다

문서를 쓰기 위해서가 아니라, 예약이 안 돌아 손으로 돌리면서 확인됐다.

```
12:41  445건        (고침 «전»에 쓰인 파일)
20:14  이어받은 것 445 + 새로 든 것 219 = 664건
20:50  이어받은 것 664 + 새로 든 것  72 = 736건
돈때들 세 개가 쌓여 있다
```

⛔ 옛 방식이었으면 736건이 아니라 **마지막 실행분 445건만** 남았고, 아침·저녁에 처음 본
291건이 사라졌다.

## 6부. 잰 것과 «제 판단»을 갈라 적는다

```
실측    내는 자리가 writeFileSync 였다 (코드를 열어 봤다)
실측    진짜 445건을 합치니 439건 — 구글 트렌드 열 건의 주소가 하나였다
        (열쇠별로 세어 「겹친 열쇠 1개, 줄어든 수 9」를 확인했다)
실측    열쇠를 고친 뒤 448 = 445 + 3
실측    실제 세 실행에서 445 → 664 → 736 으로 쌓였고 돈때들이 세 개다
실측    커뮤니티 제목은 목록에서 밀려 내려간다 — 20:14 실행에서 아침 445건 중
        «다시 보인 것이 226건»뿐이었다. 나머지는 이미 목록에 없었다

제 판단  「그래서 아침 것은 되찾을 수 없다」는 제 판단이다. 226/445 만 다시 보였다는 실측이
        근거이지만, 지난 글을 파고들어 다시 받을 길이 «전혀» 없는지는 다 재 보지 않았다.
제 판단  「열쇠를 주소+제목으로 두는 것이 맞다」도 제 판단이다. 같은 주소·같은 제목을
        다른 방에서 올린 경우를 한 건으로 세는데, 그것이 옳은지는 우물마다 다를 수 있다.

⛔ 안 말한 것  다른 수집기(newsdesk · krx)도 같은 꼴인지는 이 문서에서 안 쟀다 — 아래 7부.
```

## 7부. ⬜ 못 쟀다

```
⬜ 다른 수집기가 같은 병인가 — newsdesk 는 하루 한 번이라 덮어도 손실이 적고,
   krx 는 날짜별 파일이라 겹치지 않는다. 그러나 «재 보지는 않았다».
⬜ 오늘 아침 파일에는 `처음본때` 칸이 없었다(고침 전에 쓰였다). 그래서 아침에 처음 본
   226건이 「처음본때=저녁」으로 적혔다. 내일부터는 맞다. **오늘 것은 못 쟀다.**
⬜ 밀려 내려간 219건을 다른 길로 받을 수 있나 — 안 재 봤다.
```

## 8부. 물린 것

⛔ **「자가시험 46가지 다 맞다」를 근거로 이 고침이 됐다고 적을 참이었다.** 틀렸다.
그 초록은 «내가 상상한 자료»에 대한 초록이었고, 진짜 자료에서는 6건을 잃고 있었다.

✅ 그래서 이 저장소의 규칙에 한 줄을 더한다 —
**「진짜 자료를 한 번 통과시켜 보기 전에는 «됐다»고 하지 않는다.」**
자가시험은 «내가 아는 함정»을 막고, 진짜 자료는 «내가 모르는 함정»을 드러낸다. 둘이 다르다.
