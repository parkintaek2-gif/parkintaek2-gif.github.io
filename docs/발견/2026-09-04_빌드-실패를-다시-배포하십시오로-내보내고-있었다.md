# 빌드가 깨졌는데 「다시 배포하십시오」라고 내보내고 있었다 — 한 유닛이 여섯을 다 막는다

**잰 날** 2026-09-04 06:0x KST · **잰 유닛** 5번(K Culture Wire) · **고친 자** `scripts/deploy.mjs`

---

## 1부. 결론 — 세 줄

1. **세 사이트(SeoulMarkets · K Culture Wire · 백년지도)는 «한 빌드»다.**
   한 유닛의 frontmatter 한 줄이 잘못되면 **세 사이트 전부** 영영 안 나간다.
2. 그런데 배포 자가 그 빌드 실패를 **삼키고 배포를 계속했다.**
   사람이 보는 것은 「Running · 라이브 200」과 **「몇 분 기다린 뒤 다시 배포하십시오」**뿐이었다.
3. 그 안내를 따르면 **영영 헛돈다.** 다시 배포해도 같은 빌드가 같은 자리에서 또 깨진다.

⛔ 「라이브가 옛 것이다」를 보면 **먼저 빌드를 돌려 본다.** 다시 배포하는 것이 아니다.

```bash
node scripts/build-once.mjs   # 종료코드가 0 이어야 한다
echo $?                       # ⚠ 파이프를 붙이지 말 것 — tail 의 코드를 읽게 된다
```

---

## 2부. 어떻게 드러났나

### 2-1. 겪은 것

6번째 기사를 커밋하고 배포했다. 두 번 돌렸고 두 번 다 이렇게 끝났다.

```
  20초 · Building
  40초 · Building
  60초 · Running
✅ Running · 라이브 200

# 라이브가 지금 내 HEAD 와 같은가 (배포 도장으로 견줌)
  🔴 K Culture Wire   다르다 — 내 c1f8f8e1 · 라이브 27753810
🔴🔴 라이브가 아직 옛 것이다. … ⭐ 몇 분 기다린 뒤 다시 배포하십시오.
```

### 2-2. 「다시 배포」를 따르기 전에 잰 것 — 이것이 갈랐다

**두 배포의 «걸린 시간»이 달랐다.**

```
5번째 기사 배포   Building 420초 → Deploying → Starting → 480초 만에 라이브 200   ← 진짜 구웠다
6번째 기사 배포   Building 40초 → Running                                          ← 2,775장을 구울 시간이 아니다
```

그래서 「다시 배포」 대신 **기다리기만 하는 감시**를 걸고, 동시에 왜 dist 가 안 바뀌는지 쟀다.

```
$ ls -l dist/index.html
2026-09-04 05:40:02      ← 6번째 기사(05:47 커밋) «전» 것이다
```

### 2-3. 그리고 빌드를 직접 돌렸다

```
$ node scripts/build-once.mjs
[InvalidContentEntryDataError] kcwArticles → chart-credits-buy-a-level-not-a-direction
  dek: Too big: expected string to have <=240 characters
⛔ 06:01 빌드 실패
```

**내 dek 이 318자였다.** 한계는 `src/content.config.ts:24` 의 `z.string().max(240)`.
Cloudtype 도 같은 저장소를 같은 명령으로 굽는다 — 그쪽도 똑같이 죽어 있었다.

## 3부. 자의 어디가 잘못돼 있었나

`scripts/deploy.mjs` 가 빌드를 부르는 자리다.

```js
// 옛 코드
try {
  execFileSync(process.execPath, [.../build-once.mjs], { stdio: 'ignore', cwd: 뿌리 });
} catch {
  console.log('⚠ 빌드가 안 됐다 — 지면 판정을 쓰지 않고 옛 방식으로 돈다.');
  return [];                    // ⛔ 그리고 «배포를 계속했다»
}
```

세 곳이 겹쳐서 사고가 됐다.

| 자리 | 무엇이 잘못됐나 |
|---|---|
| `stdio: 'ignore'` | 빌드가 낸 오류 글을 **버렸다.** 어디가 잘못됐는지 아무도 못 본다 |
| `catch { … return [] }` | 「구울 수가 없다」를 **「판정을 못 한다」로 낮춰 읽었다** |
| 그 뒤 | 판정할 새 지면이 없으니 Running 을 보자마자 끝냈고, **배포는 그대로 나갔다** |

⭐ 그 결과가 「Running · 라이브 200」 + 「다시 배포하십시오」다.
   **두 줄 다 참인데, 둘을 합치면 사람을 무한히 헛돌게 한다.**

## 4부. 어떻게 고쳤나

### 4-1. 빌드가 깨지면 «배포하지 않는다»

`빌드실패` 라는 갈래를 따로 두어, 다른 오류와 구별되게 했다.
잡는 자리에서 오류 글을 **잃지 않고** 위로 올리고, 맨 위에서 사람에게 짚어 준다.

```
🔴🔴 **빌드가 깨졌다 — 배포하지 않았다.**
   Cloudtype 도 같은 저장소를 같은 명령으로 굽는다. 여기서 깨지면 거기서도 깨진다.
   ⛔ 다시 배포해도 소용없다. **고쳐야 나간다.**

   어디가  content/*/zz-temp-guard-test.md 의 frontmatter
   무엇이  dek: Too big: expected string to have <=240 characters
   묶음    kcwArticles

   🔴 세 사이트가 **한 빌드**다. 이것을 고칠 때까지 6번·3번의 배포도 안 나간다.
```

### 4-2. ⛔ 그 자리에서 「다시 배포하십시오」라고 말하지 않는다

그 말이 오늘 나를 두 번 헛돌게 했다. 빌드가 깨진 것은 다시 배포해서 풀리는 것이 아니다.

### 4-3. 못 짚으면 «못 짚었다»고 낸다

오류 글에서 「어디가·무엇이」를 못 뽑으면 `null` 을 낸다.
그러면 부르는 쪽이 **원문 마지막 25줄을 그대로** 보여 준다. 억지로 지어내지 않는다.

## 5부. 재서 확인한 것

```
자가시험 49개 전부 통과 (6개 새로 넣음)
```

⭐ **시험에 「진짜로 겪은 오류 글」을 넣었다.** 지어낸 글로 시험하면 진짜가 왔을 때 못 짚는다.
   `[InvalidContentEntryDataError] kcwArticles → chart-credits-…` 을 색코드까지 그대로 옮겼다.

⭐ **관문이 «정말 서는지» 끝에서 끝까지 쟀다.** 늘 통과만 하는 검사는 검사가 아니다.

```
일부러 dek 274자짜리 파일을 하나 넣고  node scripts/deploy.mjs --probe
  → 종료코드 1 · 배포 안 함
  → 「어디가 content/*/zz-temp-guard-test.md 의 frontmatter」
     「무엇이 dek: Too big: expected string to have <=240 characters」
파일을 지운 뒤  node scripts/build-once.mjs  → 종료코드 0
```

⚠ `--probe` 는 배포도 락도 건드리지 않는다. 그래서 이 시험이 남의 배포를 안 해친다.

## 6부. 내가 또 걸린 옛 덫

```
$ node scripts/build-once.mjs | tail -15
$ echo $?
0                    ← build-once 가 0 을 냈다고 읽었다
```

**틀렸다. 그 0 은 `tail` 의 것이다.** 파이프 없이 다시 재니 `1` 이었다.
`build-once.mjs` 는 원래대로 잘 동작하고 있었다.

⛔ **종료코드를 파이프 뒤에서 읽지 않는다.** 이것을 내가 오늘 또 했다.
   하마터면 「build-once 가 실패하고도 0 을 낸다」는 **틀린 진단**을 문서에 적을 뻔했다.

## 7부. 전 유닛이 지킬 것

### 7-1. 라이브가 안 바뀌면 — 순서

```
1. node scripts/build-once.mjs   ← 파이프 없이. 0 이 아니면 여기가 원인이다
2. 0 인데도 안 바뀌면 그때 배포를 다시 본다
```

### 7-2. 글을 낼 때 — 미리 걸리는 한계

| 칸 | 한계 | 어디에 |
|---|---|---|
| `dek` | 240자 | `src/content.config.ts:24`(KCW) · `:86` |

⚠ **글자 수는 눈으로 세지 않는다.** 한 줄로 잰다.

```bash
node -e "const s=require('fs').readFileSync(process.argv[1],'utf8');console.log(s.match(/^dek: \"(.*)\"\$/m)[1].length)" content/kculturewire/<이름>.md
```

### 7-3. 남의 배포를 막고 있을 수 있다

세 사이트가 한 빌드다. **내 글 하나가 6번·3번의 배포까지 세운다.**
그래서 발행 뒤에는 «내 지면이 떴나»만이 아니라 **빌드가 0 인가**를 본다.
