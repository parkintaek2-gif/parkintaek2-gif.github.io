## 0. 먼저 아는 것 — 길은 **하나도 안 고칩니다**

```
윈도는 길에서 대소문자를 안 가린다
  → 코드에 박힌 C:\Users\USER\... 가 C:\Users\User 에서 **그대로 작동한다**
  → 접합점(mklink)도, 길 고치기도 필요 없다
```
🔴 **갈리는 것은 딱 하나 — 대화록 폴더 «이름»** 입니다. 그것만 cwd 글자를 그대로 씁니다.
```
노트북   C--Users-USER-Desktop
새 PC    C--Users-User-Desktop     ← 다른 폴더로 본다 → 「대화가 없다」
```
✅ 그래서 풀기 자가 **두 이름에 다 깔아 둡니다.** 어느 쪽으로 열려도 찾습니다.

## 2. 차례

```
[노트북]  ① node 로 저장소 커밋·push 를 다 비운다
          ② powershell -File scripts/서버이사-싸기.ps1            ← 굳은 짐 (이미 했음)
[새 PC]   ③ 계정 User 로 로그인 · Node 24.18 · git · Claude Code 설치
          ④ 원드라이브 로그인 → _서버이사 폴더가 내려올 때까지 기다린다
             ⛔ 「파일 온디맨드」로 구름에만 있으면 안 된다. 폴더를 열어 «내려받기»를 시킨다
          ⑤ git clone 넷 → npm ci
[노트북]  ⑥ powershell -File scripts/서버이사-싸기.ps1 -대화록    ← 옮기는 날, 창 닫기 직전
[새 PC]   ⑦ powershell -ExecutionPolicy Bypass -File scripts/서버이사-풀기.ps1
          ⑧ Chrome 로그인 다섯(admin·u2~u6) · Cloudtype 로그인
          ⑨ 00_세션입구 에서 창 여섯을 더블클릭
          ⑩ 「auto mode 를 기본으로?」 → **2** (keep bypass)
          ⑪ 각 자리가 **매시 예약을 다시 건다**
[노트북]  ⑫ 창을 다 닫는다   ⛔ 이게 마지막이다
```
⛔ **⑫를 먼저 하지 마십시오.** 새 PC 가 돌기 전에 노트북을 끄면 그 사이 일이 멈춥니다.
⛔ **두 기계에서 같이 돌리지 마십시오.** 같은 저장소에 두 벌이 밀면 메모가 부딪칩니다.

## 3. ⭐ 추가 조치 — 제가 넣은 것 (사장님이 「있으면 해라」 하신 것)

### ① 지킴이를 **윈도 예약작업**으로 등록합니다

```
지금    지킴이가 «어느 세션의 매시 예약»으로 돈다
문제    그 창이 죽으면 지킴이도 같이 죽는다 → 죽은 자리를 아무도 안 깨운다
실측    8/21 에 9·10번이 지킴이 표에 없어 **다섯 시간** 방치됐다
고침    풀기 자가 「자리지킴이」라는 예약작업을 만든다 — 15분마다 · **세션 밖에서** 돈다
```

### ② 대화록을 **두 폴더 이름에 다 깔아** 둡니다 (위 0번)

### ③ 자리마다 **제 설정폴더를 못 박습니다**

```
8/21 19:3x 실측 — 한 세션의 대화록이 «두 갈래»로 갈라져 자라고 있었다
  .claude-u2  96,646,377   /   .claude  96,681,132
까닭 — 지킴이의 깨움이 설정폴더를 안 정해 줘서 «예전 계정»으로 돌았다
⛔ 오류가 안 난다. auth status 는 팀 계정을 내고 창도 멀쩡하다. 기록만 갈라진다
고침 — 2~6번 → .claude-uN · 1번만 .claude (9월 2일에 옮긴다)
```

### ④ 원격 데스크톱을 **새 PC 에** 다시 깝니다

휴대폰에서 부르시려면 그 기계에 있어야 합니다. `remotedesktop.google.com/access`.
⛔ Workspace 계정은 막혀 있었습니다 — **개인 구글 계정**으로 하십시오(8/21 실측).
