## 3. 🔴 `/person` — **색인이 문제가 아니다**

여기서 내가 처음 세운 가설이 틀렸다. 「제목에 실명·수가 없어서 안 뜬다」였다.

지면을 손님으로 열어 보니 **제목이 이미 물음에 정확히 답하고 있었다.**

```
물음   woo do hwan netflix
제목   Woo Do-hwan movies and TV shows — 87 countries on Netflix
설명   … appears in 6 Korean titles that reached a Netflix weekly top 10 …
우리 자리   68위
```

그리고 색인도 문제가 아니었다 — 어제(9/07) 잰 표본이 이렇다.

```
/person 표본 25장   색인됨 13 · 기다림 12   → 색인 52%
/title  표본 25장   색인됨  6 · 기다림 18   → 색인 24%
```

⭐ **`/title` 은 색인이 절반인데 노출은 `/person` 의 열 배가 넘는다.**
  그러니 「담기지 않아서」가 아니다. **담겼는데도 못 이기는 것**이다.

⛔ 배우 이름 물음에는 IMDb·위키백과·넷플릭스·MyDramaList 가 이미 서 있다.
  지금 우리 권위로는 그 자리를 못 가져온다. 우리 자리는 33~92위였다.

⚠ **그러니 `/person` 지면을 고치는 데 시간을 쓰지 않는다.** 지면은 이미 옳다.
  ⭐ 다만 «지우지도 않는다» — 안쪽 문 노릇을 하고, 권위가 오르면 뜰 자리다.

## 4. 왜 `/born-on` 은 되고 `/tag`·`/born-year` 는 안 되나

나이 탓이 아니다. 만든 날이 사흘 차이인데 결과가 갈렸다.

```
/born-on   2026-08-22 에 냄 → 73.6%
/tag       2026-08-25 에 냄 →  0.0%
/from      2026-08-26 에 냄 →  0.0%
```

가른 것은 **「사람이 그렇게 검색하는가」** 하나다.

```
✅ /born-on/01-01   「korean actors born on january 1」  — 생일 물음. 겨루는 자가 얇다
🔴 /tag/netflix     「netflix tag …」                    — 아무도 이렇게 안 찾는다.
                                                          태그는 «안쪽 길»이지 검색 대상이 아니다
🔴 /born-year/1995  「korean actors born in 1995」       — 물음은 있지만 큰 목록 사이트와 겨룬다
```

⭐ 그래서 **태그 archive 를 더 만들지 않는다.** 문 노릇으로는 값이 있으나 손님을 안 데려온다.

## 5. ⚠ 우리 CTR 을 그대로 읽으면 안 된다 — 노출의 셋 중 하나가 «죽은 물음»이다

구글이 이름을 준 물음(전체 노출의 22%)만 갈라 보면 이렇다.

```
                    쌍     노출   클릭    CTR
전체               488    1,130     3   0.27%
주소꼴 물음          44      376     0   0.00%   ← 33.3%
진짜 물음           444      754     3   0.40%
```

「주소꼴 물음」은 이런 것이다 — 사람이 **넷플릭스 주소를 검색창에 그대로 붙여 넣은** 것.

```
https://www.netflix.com/tudum/top10?week=2024-11-03
"netflix.com/tudum/top10/data/all-weeks-global.tsv"
```

우리가 그 자리에 뜨는 까닭은 **우리 지면이 그 주소를 출처로 적어 놓았기 때문**이다.
⛔ 그 물음은 어떤 제목으로도 못 이긴다 — 손님은 netflix.com 을 누른다.
⚠ 그것을 받는 갈래가 `/market`(189) · `/about`(91) · `/title`(75) 이다.
  ⭐ `/market` 이 노출 516에 클릭 0인 까닭의 큰 몫이 이것이다.

✅ 그래도 **출처 주소를 지우지 않는다.** 출처를 적는 것이 우리 강령이다.
  대신 **우리 CTR 을 볼 때 이 몫을 덜어 놓고 본다.**

## 6. 우리에게 «클릭을 준» 물음은 한 꼴이다

28일 동안 이름이 붙은 물음에서 온 클릭은 셋뿐이고, **셋이 다 같은 꼴**이었다.

```
클릭 1 · 노출 10 · 자리 7.8  │ a girl who deserves to die netflix
클릭 1 · 노출  8 · 자리 6.8  │ my lovely liar netflix country
클릭 1 · 노출 25 · 자리 11.1 │ project wolf hunting netflix
```

「거의 뜨는」 자리(11~30위)에도 같은 꼴이 줄지어 있다.

```
5  자리 17.2 │ what countries can i watch behind your touch on netflix
4  자리 11.5 │ 18 again netflix countries
3  자리 11.0 │ 12.12 the day netflix
2  자리 11.0 │ beasts clawing at straws netflix
```

⭐ **꼴은 이것이다 — 「〈한국 작품〉 netflix country / countries / which country」.**
  뜻은 하나다: *이 작품을 어느 나라에서 볼 수 있나.*

⚠ 그 물음에 답하는 지면은 이미 있다 — `/title/*` 546장 · `/where-to-watch` · `/netflix-which-country`.
  ⛔ 새로 만들지 않는다. 있는 것을 안 보고 또 만드는 것이 더 나쁘다.

### 그러면 물음은 오는데 «지면이 없는» 작품이 있나 — 재 봤다. **없다**

```
작품 974편 중 지면을 낸 것 546편 (차트 줄 6줄 문턱)
지면이 없는 428편 가운데 «물음이 온» 것 → 4편 · 노출 합 5
   그중 셋은 엉뚱한 맞춤(Hometown·Live Stream·Streaming)
```

⭐ **문턱 6줄이 검색 수요를 깎고 있지 않다.** 이 갈래는 닫는다.

## 7. 그래서 무엇을 만드나 — **한 장이 아니라 «갈래»를 만든다**

이것이 이 측정에서 나온 가장 큰 것이다.

```
지면 한 장을 내면        노출을 받는 지면이 1장 늘 수 있다
갈래(366장)를 내면       노출을 받는 지면이 270장 늘었다   ← /born-on 실측
```

⚠ 오늘 낸 세 장(`/generations`·`/attention-share`·`/desktop-or-phone`)은 다 **한 장짜리**다.
  좋은 지면이지만, 손님 수로 보면 366장짜리 갈래 하나가 훨씬 크다.

### 새 갈래를 낼 때 통과해야 하는 세 가지 (실측에서 나온 것)

```
1. 사람이 «그 꼴로» 검색하나        — /tag 는 여기서 걸린다
2. 그 물음에 답할 자료를 우리가 쥐고 있나
3. 그 자리에 큰 사이트가 이미 서 있지 않나  — /person·/born-year 는 여기서 걸린다
```

⛔ 셋을 다 통과하지 못하면 **몇 백 장을 내고도 노출 0** 이다. 이미 502장을 그렇게 냈다
  (`/week` 269 · `/tag` 117 · `/born-year` 78 · `/from` 37).
