## 7. 권한 설정 — klifemap 세션이 처리했다 (2026-08-02 KST)

**A안으로 진행됐다.** 전역 `~/.claude/settings.json` 에 적용돼 **양쪽 세션에 걸린다.**

```
defaultMode   bypassPermissions      프롬프트 없음
deny 9건      ctype ls -o (8/1 에 키가 세 번 샌 명령) · rm -rf ·
              git push --force · .env 읽기 4종
```

**`deny` 가 `bypassPermissions` 보다 우선한다는 것을 문서로 확인했다** —
「Rules are evaluated in order: deny, then ask, then allow」.
bypassPermissions 가 건너뛰는 것은 **프롬프트**이고 deny 는 묻는 게 아니라 막는 것이다.

### ⚠ `ctype` 은 deny 로 못 막았다 — 훅으로 풀었다

「a deny rule can't carry allowlist exceptions」라 `Bash(ctype update*)` 를 막으면
**`-t` 붙인 정상 배포까지 막힌다.** 7/31 사고는 「ctype 을 쓴 것」이 아니라
**「`-t` 없이 쓴 것」**이라 조건부 판단이 필요했다.

→ **PreToolUse 훅** `~/.claude/hooks/ctype-guard.js` 로 만들었고 11건 실제로 돌려 확인했다.

```
차단   ctype update klifemap-app · ctype apply -f x.yaml
통과   … -t @parkintaek2/klifemap:main · ctype list · ctype logs
통과   echo ctype update · grep 'ctype update'      ← 「명령 자리」로 좁혔다
```

처음엔 `echo ctype update` 까지 막혔다고 한다.
**거짓 차단이 쌓이면 사람이 훅을 꺼 버리고, 그러면 진짜 사고를 못 막는다.**
(내가 위기 감지 모듈에서 「배고파 죽겠다가 걸리면 아무도 안 켠다」고 한 것과 같은 원리다)
