## 4. ⚠ 사장님 아이디어 중 **지금은 안 되는 것** — 데이터로

> 사장님: 「**별로인 건 얘기를 해야 돼. 근거는 너의 추측이 아니야, 데이터로**」

### ⛔ ① 「이달의 기자상 언론사 순위」 — **수집 경로가 없다**

```
/mybbs/bbs.html               🚫 Disallow  ← 회차별 수상 명단이 여기 있다
/news/section_list_all.html   🚫 Disallow  ← 수상작 목록
/news/section1.html           ✅ 허용 — 그런데 **응모 요강**이지 수상자 목록이 아니다
/news/article.html?no=        ✅ 허용 — 그런데 **열거할 방법이 없다**
                                 (목록 지면에서 링크 추출 0개)
rss/allArticle.xml · sitemap.xml · rss.xml   ← **전부 404**
```

**허용된 경로만으로는 「어느 언론사가 몇 번 받았나」를 못 센다.**
협회 협조가 전제인데 **우리는 아직 언론사가 아니다.**
→ 순서를 뒤로 미룬다. 다른 것부터 한다.

### ⛔ ② 「질환별 의사 Top5」 — 개인 단위 데이터가 없다

심평원 공개분은 **전부 요양기관 단위**다. 「병원 × 진료과」까지가 한계다.
개인 의사 이름은 어떤 공개 데이터에도 없다.

### ⚠ ③ 「대표이사 재직년수 순위」 — 된다. 다만 **표본이 절반이다**

```
대표이사 식별       1,162명 / 임원 11,460명
그중 재직기간 있음   1,007명
그중 오너/전문 판정   625명 (382명은 관계 표기가 애매해 판정 불가)
```

**오너 대 전문경영인 비교는 625명 표본**이다. 「재벌 대표이사」로 좁히면 더 준다.
쓸 수 있지만 **「전수」라고 쓰면 안 된다.** 표본 수를 같이 밝힌다.

### ⚠ ④ 「소속사별 연예인 전수조사」 — 상장사만 된다

사업보고서에 있는 건 **상장 기획사**뿐이다. 하이브·SM·YG·JYP 등.
매니지먼트 대부분은 비상장이라 공시 의무가 없다.
→ 「전수」가 아니라 **「상장 기획사 전수」**다. 그것도 값이 있지만 이름을 정확히 쓴다.

### 7-2. ⭐ 업종·그룹 축 — DART 에 이미 있다

> 「DART 공시하고 기업보고서를 **하나의 기업, 하나의 종목으로만 가공하지 말고
>  업종이라든가 어떤 그룹을 잇는 데이터로도 가공**하라고」

**`company.json` 한 번 호출로 다 온다. 새로 뚫을 게 없다.**

```
induty_code  업종코드      ← ⭐ 업종별 집계의 열쇠
adres        본사 주소     ← 「어디 있다?」의 답

hm_url ir_url phn_no      홈페이지·IR·연락처
jurir_no bizr_no          법인등록번호·사업자번호 ← 다른 DB 와 잇는 열쇠
corp_cls                  Y(유가) K(코스닥) N(코넥스) E(기타)
```

⚠ **업종코드 자릿수가 제각각이다.** 실측 — 삼성전자 `264` · 하이브 `592` · NAVER `63120`.

그래서 그대로 묶으면 안 되고 **앞 2자리(대분류)로 정규화**해야 한다.

**그러면 이런 표가 나온다** — 지금 축을 그대로 쓰고 집계 단위만 바꾸면 된다.
