# 결제 막힘 — 원인과 조치 (2026년 10월 24일)

## 1. 무엇이 있었나

사주 지면에서 **결제 단추가 하나도 그려지지 않았습니다.** 손님이 살 수가 없었습니다.

서버는 멀쩡했습니다. 토스도 멀쩡했습니다. 지면만 깨져 있었습니다.

## 2. 원인

지면 코드에서 스크립트 블록이 **988줄 일찍 닫혀** 있었습니다.

```
})();
</script>        ← 여기서 닫혔습니다
(주석 조각)       ← 주석을 여는 표시가 사라졌습니다
let currentLang = …   ← 이 아래 988줄이 전부 «코드 밖»
```

브라우저는 그 988줄을 코드가 아니라 **그냥 글자**로 읽었습니다.
그 안에 있던 함수가 전부 없는 것이 되었고, 화면에 오류가 뜨면서
그 뒤 코드가 멈췄습니다. 결제 단추를 그리는 코드까지 못 돌았습니다.

주석을 여는 표시(`/*`)가 사라지면서 닫는 태그가 그 자리를 차지한 것입니다.

## 3. 조치

### 고쳤습니다

그 한 줄을 바로잡았습니다. 지금 **결제창이 실제로 열립니다**(650px 확인).

```
전   함수 없음 · 화면 오류 2개 · 결제 단추 0개
후   함수 있음 · 화면 오류 없음 · 결제창 열림
```

### 고치다가 제가 같은 실수를 두 번 했습니다

설명 주석을 길게 달았는데, 그 안에 닫는 태그를 글자 그대로 적었습니다.
HTML은 주석 안이든 문자열 안이든 가리지 않고 그것을 보면 블록을 닫습니다.
**제가 막 고친 바로 그 결함을 고치면서 되풀이했습니다.** 주석을 두 줄로 줄여 해결했습니다.

### 되돌릴 수 없게 — 자물쇠 둘을 새로 만들었습니다

**① 코드가 블록 밖으로 새지 않았나**

같은 일이 또 생기면 배포 전에 걸립니다. 몇 줄째인지도 알려줍니다.

**② 라이브를 받아 문법 검사**

화면 오류만 보면 어느 줄인지 모릅니다. 라이브 지면을 받아 블록마다
문법을 검사하니 깨진 자리가 바로 나왔습니다. 이 방법을 앞으로 씁니다.

## 4. 더 큰 문제 — 자물쇠가 눈을 감고 있었습니다

### 결제 검사

```
🔴 결제창   ⬜ 못 쟀다 — Attempted to use detached Frame …
✅ 팔린다 — 손님이 들어와서 돈을 내고 다시 볼 수 있다
```

**「못 쟀다」고 해 놓고 「팔린다」를 찍었습니다.** 그 자리가 빈 줄 알면서 통과시켰습니다.

### 공짜 관문 검사

사장님이 「공짜로 풀린 거 있으면 막아」 하셔서 돌려 보니,
**15자리를 재려다 2자리만 재고 멈췄는데** 갈무리는 이랬습니다.

```
■ 갈무리 — 2 / 2 자리가 막혀 있다
   ✅ 값 매긴 것이 전부 돈을 받고 나간다
```

13자리를 안 재 놓고 다 괜찮다고 말했습니다.

### 고쳤습니다

- 한 자리에서 터져도 멈추지 않고 다음 자리로 갑니다
- 「잴 수」와 「잰 수」가 다르면 갈무리에서 먼저 말합니다
- 적게 잰 것은 잘 막힌 것이 아닙니다

고친 뒤 다시 돌렸습니다.

```
■ 갈무리 — 15 / 15 자리가 막혀 있다
   ✅ 값 매긴 것이 전부 돈을 받고 나간다
```

**공짜로 새는 곳은 없습니다.** 사주·궁합·택일·작명·별자리·코칭 열다섯 자리
전부 돈을 받고 나갑니다.

## 5. 왜 자꾸 이러는가

오늘 하루에 같은 병이 세 번 나왔습니다.

| 어디 | 무엇을 | 어떻게 읽었나 |
|---|---|---|
| 결제 검사 | 결제창을 못 쟀다 | 「팔린다」로 |
| 공짜 관문 | 15자리 중 2자리만 쟀다 | 「다 막혔다」로 |
| 기사 거두기 | 회차가 아직 쓰는 중이다 | 「기사다」로 (메일 세 통이 나갔습니다) |

**못 잰 것을 「괜찮다」로 읽는 버릇입니다.**
자물쇠가 모르는 것을 통과로 찍으면 자물쇠가 아니라 거짓 안심입니다.

셋 다 고쳤고, 각각 자가시험에 그날 실제로 있던 꼴을 박아 두었습니다.
