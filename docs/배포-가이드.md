|---|---|

| 호스팅 | Cloudtype — **신청 필요** (아래 2번) |

호스팅은 사장님 지시대로 **Cloudtype**으로 간다 (klifemap.ai와 동일).

> 한 가지만 기록해 둡니다. 이 사이트는 서버 로직이 없는 정적 HTML이라 Cloudtype에서는
> 하는 일 없는 컨테이너를 24시간 띄워두게 됩니다. 그래도 klifemap.ai와 운영을 한 곳에서
> 관리하는 편익이 더 크다고 판단하셨으니 그대로 진행했습니다. 나중에 비용이 부담되면
> 코드 변경 없이 Cloudflare Pages로 옮길 수 있습니다 (`public/_headers` 를 그대로 남겨둔 이유).

## 정적 사이트를 Node 호스팅에 올리는 법 — 이미 처리해둠

Cloudflare Pages는 `/equities` 요청에 `equities.html` 을 알아서 내주지만, 일반 Node 호스팅은
그러지 않는다. 그대로 올리면 **사이트맵과 canonical 이 가리키는 URL이 전부 404** 가 난다.

그래서 의존성 0개짜리 정적 서버 `server.mjs` 를 넣어뒀다. 하는 일:

- `/equities` → `dist/equities.html` (clean URL)
- `/equities.html`, `/equities/`, `/index.html` → 확장자 없는 정본으로 **301**
- 없는 경로 → `404.html` 을 404 상태로
- `_astro/*` 는 1년 immutable 캐시, HTML 은 no-cache
- 보안 헤더(nosniff, frame-options, referrer-policy) 부착
- 디렉터리 탈출 차단

`PORT` 환경변수를 읽으므로 Cloudtype이 주는 포트를 그대로 쓴다.

## 1. GitHub 저장소 올리기

```bash
# GitHub 웹에서 빈 저장소 seoulmarkets 를 먼저 만든 뒤
git remote add origin https://github.com/<계정>/seoulmarkets.git
git push -u origin master
```

## 2. Cloudtype 앱 생성

1. https://cloudtype.io 로그인 (klifemap.ai 쓰던 계정)
2. **새 프로젝트** → **Node.js** 템플릿 선택
3. **GitHub 저장소 연결** → 위에서 올린 `seoulmarkets` 선택
4. 설정값 — 이대로 넣으면 된다.

   | 항목 | 값 |
   |---|---|
   | 빌드 명령어 | `npm ci && npm run build` |
   | 시작 명령어 | `npm start` |
   | 포트 | `3000` (또는 Cloudtype 기본값 그대로 — `PORT` 를 읽는다) |
   | Node 버전 | `22` 이상 |

5. **배포하기** → 완료되면 `*.cloudtype.app` 프리뷰 주소가 나온다. 거기서 먼저 확인한다.

> ⚠ 요금제 선택과 결제는 제가 대신 하지 않았습니다. 무료 플랜은 트래픽·상시가동에 제한이
> 있어 공개 매체 운영에는 유료 플랜이 필요합니다. 어느 플랜으로 갈지는 직접 정해주십시오.

## 3. 도메인 연결

Cloudtype 프로젝트 → 해당 서비스 → **도메인** 탭 → 좌측 상단 버튼 → `seoulmarkets.com` 입력.
Cloudtype이 **CNAME 값과 TXT 값**을 보여준다. 그 값을 Spaceship에 넣는다.

**Spaceship** → Domains → seoulmarkets.com → **Advanced DNS**

| Type | Name | Value |
|---|---|---|
| TXT | (Cloudtype이 지정한 이름) | (Cloudtype이 준 인증 값) |
| CNAME | `www` | (Cloudtype이 준 CNAME 값) |
| A 또는 ALIAS | `@` | (Cloudtype이 준 값) |

### apex 도메인(`www` 없는 주소) 주의

Cloudtype 문서는 "도메인 자체(PQDN 없는 apex)는 제공업체에 따라 CNAME 설정이 안 될 수 있으니
`www` 를 쓰라"고 안내한다. **다만 klifemap.ai 는 이미 apex 에 A 레코드(`34.8.247.175`)로 붙어
있다.** 즉 Cloudtype이 apex용 값을 준다는 뜻이므로 `seoulmarkets.com` 도 같은 방식이 된다.
도메인 탭이 주는 값을 그대로 쓰면 된다.

만약 apex 연결이 끝내 안 되면 **`www.seoulmarkets.com` 을 정본으로 바꾼다.**
그 경우 `src/consts.ts` 의 `SITE_URL` 을 `https://www.seoulmarkets.com` 으로 고치고
apex 는 Spaceship의 URL 포워딩으로 www 에 넘긴다.
**이 한 줄을 안 고치면 canonical 이 접속 안 되는 주소를 가리켜 색인이 꼬인다.**

### Cloudflare 프록시 주의

Cloudtype 문서 경고 — 프록시(주황색 구름)를 켜면 인증서 발급이 실패할 수 있다.
지금은 Spaceship 네임서버를 쓰고 있어 해당 없다. 나중에 네임서버를 Cloudflare로 옮기면
이 레코드들은 **DNS only(회색 구름)** 로 둘 것.

## 4. 도메인이 바뀌면 고칠 곳

세 군데뿐이다.

- `src/consts.ts` → `SITE_URL`
- `public/robots.txt` → Sitemap 줄
- `scripts/ping-indexnow.mjs` → `HOST`

바꾼 뒤 `npm run og` 를 한 번 돌려 OG 카드의 도메인 표기도 갱신한다.
