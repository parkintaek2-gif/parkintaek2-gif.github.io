# API로 못 받는 데이터 — 합법 수집 플레이북 (전 세션 공유)

> 사장님 지시(2026-08-08): 「API로 수집 못 하는 데이터에 대해 **합법적인 수집 노하우를 데이터 수집이 필요한 곳에 공유**하라.」
> 6번(SeoulMarkets)이 증권사 리서치·금융데이터 수집에서 겪은 실전 교훈을 일반 원칙으로 압축했다. 상세 실례는 [[데이터-출처-라이선스]].
> ⛔ 위장(사람인 척)은 안 한다. 시비를 원천 차단하는 건 **적법·투명·사실**이다. 위장은 발각되면 사실 문제를 기만 문제로 키운다.

## 0. 수집 전 판정 순서 (이 순서를 어기지 마라)
```
① 공공 API 로 「제한 없음」이 있나  → 있으면 그걸로 끝. 긁지 마라
② 없으면 원출처(생산기관 자사)에 직접 있나
③ robots.txt 를 RFC 9309 대로 정확히 판정
④ 사실만인가 / 저작물인가 가른다
⑤ 그 페이지의 명시 고지문을 읽는다
⑥ provenance(출처 URL·수집일) 를 값마다 남길 수 있나
전부 통과할 때만 수집한다. 하나라도 막히면 멈추고 대안.
```

## 1. 공공 API 「제한 없음」이 최우선 — 긁기 전에 포털부터
- 같은 데이터라도 **경로에 따라 라이선스가 다르다.** 예: DART·KRX시세·금투협 데이터가 **공공데이터포털(data.go.kr)에 금융위/금감원 명의로 「이용허락범위 제한 없음」**으로 열려 있다 → 이걸 쓰면 재배포·상업 이용 자유.
- ⚠ **포털이 「제한 없음」인데 직접 창구는 「승낙 필요」인 경우가 있다**(관세청 UNIPASS = 영리·재배포에 사전승낙). **포털이 막혀도 조건 나쁜 우회로를 타지 마라. 기다렸다 한 번에 받는다.**
- 원칙: **열려 있다 ≠ 써도 된다.** 접근 가능 여부가 아니라 **약관부터** 본다.

## 2. robots.txt 는 그룹 단위로 읽는다 (여기서 제일 많이 틀린다)
```
User-agent: *          ← 우리 봇은 여기 걸린다
Disallow: /            ← 전부 금지

User-agent: yeti       ← 네이버 자사 크롤러 (우리 아님)
Allow: /research/      ← 이 Allow 는 yeti 그룹 것. 우리한테 적용 안 됨
```
- **Allow 줄만 보고 「허용」이라 하지 마라.** 그 Allow 가 **어느 `User-agent` 그룹 소속**인지 봐야 한다. `*` 그룹에 `Disallow: /` 뿐이면 우리는 전면 금지다.
- 네이버·한경컨센서스·FnGuide·한국노동연구원 등이 이 패턴(검색엔진만 열고 나머지 차단).
- **「거부 기본 + 허용목록」형**(`Disallow: /` 밑에 특정 경로 Allow)은 허용목록까지 읽고 판정.

## 3. 사실 vs 저작물 — 선은 「전재」이지 「인용」이 아니다
```
✅ 가져온다(사실)   날짜·기관·종목·수치·목표주가·투자의견·성명 — 저작권 대상 아님
✗ 안 가져온다(저작물)  본문·요약 전문·표·차트·PDF — 표현이 저작물
```
- 사실을 꺼내 **우리 구성으로 다시 쓴다**(남의 표를 옮기지 않는다). "목표주가 80,000원·의견 중립" = 사실의 재진술이지 표현의 복제가 아니다.
- ⚠ **데이터베이스권**(저작권법 §93)은 별개다 — DB 전체/상당부분의 복제·재배포는 사실이라도 걸릴 수 있다. **선별 인용 + 우리 파생지표**로 간다. 전 항목 나열식 덤프는 안 한다.

## 4. 원출처 우선 — 집계사이트보다 생산기관 자사
- 증권사 리서치는 **네이버 집계화면**보다 **증권사 자사 페이지의 공표 요약줄**에서 직접 받는 게 논쟁이 없고, **발행 시각에 받아 T+1 제약도 풀린다.**
- 원출처가 자사 사이트에 스스로 공표한 사실은 방어력이 가장 높다.

## 5. 명시 고지문을 읽고, 지목된 행위를 피한다
- 예(미래에셋): 「다운로드·**자동 대량 수집**하여 무단 전재 및 **상업적 재배포**하는 행위 금지」.
  - 금지되는 **행위**는 "전재·재배포", "대량 수집"은 그 **수단**으로 열거. → 보호 대상(리포트 본문)을 **아예 안 받으면** 저촉되지 않는다.
- **분량도 수단이다.** 하루 1페이지(약 10건)로 스스로 묶어 「대량」이 안 되게 한다.
- 명시적으로 「무단 AI 스크랩 차단」한 곳(예: 한국투자증권)은 **논쟁 여지 없이 뺀다.**

## 6. 수집 매너 (기술)
```
· 신원 밝힌 User-Agent   예: SeoulMarketsBot/0.1 (+https://seoulmarkets.com/about)
· 요청 간격 두기          예: 0.9초 이상
· 분량 자제               하루 1페이지 등, 대량이 안 되게
· ⛔ UA 위장·헤드리스로 사람 흉내 금지 — 발각 시 최악
```

## 7. provenance — 「사람이 하나하나 확인한 수준」의 근거
- 값마다 **출처 URL·수집일시**를 저장한다. 사는 쪽 법무가 "이 숫자 어디서?"라고 물으면 한 줄로 답이 나오게.
- 정정 이력(corrections)도 남긴다 — 우리가 파는 게 신뢰라서, 정정 공개가 비용이 아니라 신용이다.

## 8. 안 하는 것 (한 줄 요약)
```
✗ robots 로 비허용한 곳 수집   ✗ 본문·PDF·표·차트 저장   ✗ 전 항목 DB 덤프
✗ UA 위장·수동인 척 허위표기   ✗ 조건 나쁜 우회로       ✗ 명시 차단처
```

## 9. 흔한 함정 — 「부분을 보고 전체라 하기」
6번이 하루에 세 번 틀린 실수다: ① 루트만 보고 하위도메인 안 봄 ② robots Allow 줄만 보고 그룹헤더 안 봄 ③ 한 곳 고지 보고 전체라 함.
→ **한 곳/한 줄을 보고 전체라 단정하지 마라.** 사이트 추가할 때마다 그 사이트의 robots·고지문을 새로 읽고 기록한다.
