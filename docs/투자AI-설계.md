# 투자 AI — 설계

작성 2026-08-02 · **담당: 나** · 사장님 지시

> 「서울마켓츠에서 추가로 할 게 **투자AI**야. 아카이브, 데이터 원천.
> **세계 각국, 국내의 모든 리포트·보도·금융시장을 훑어 알아서 투자하는 AI**를 만들어.
> **이 AI가 투자업을 담당해야 해.**」

---

## 0. 이것이 회사의 본체다 — 그리고 지수·운용과 **같은 엔진**이다

따로 만들 것이 아니다. **신호를 만드는 기계 하나에서 세 가지가 나온다.**

```
             ┌─→ 자기자금 매매      (등록 불요 · 오늘 가능)
신호 엔진 ───┼─→ 지수 산출·라이선스  (지수료)
             └─→ 운용 상품          (일본 등록 후 · 운용보수)
```

**같은 신호를 세 번 판다.** 만드는 비용은 한 번이다.
이것이 1인·무자본 회사가 세 매출원을 동시에 가질 수 있는 유일한 이유다.

---

## 1. 규제 경계를 먼저 긋는다 — 여기가 설계를 결정한다

`docs/연구-AI운용사와-관할권.md` 에서 확인한 것을 그대로 적용한다.

| | 판정 |
|---|---|
| **자기 자금으로 자기 계산 매매** | **등록 불요.** 사람도 자본 요건도 없다 |
| 남의 돈을 굴린다 | 投資運用業 등록 · 자본금 · 인적 요건 |
| **알고리즘 고속거래 + 직접전자접근** | **高速取引行為者 등록 대상일 수 있다** |

### 그래서 두 가지를 설계에 박는다

**① 속도를 의도적으로 낮춘다.** 밀리초 자동 발주를 하지 않는다.
**분·시간 단위**로 판단하고 발주한다. 고속거래 등록 요건을 건드리지 않기 위해서고,
어차피 우리 신호는 뉴스·공시·리포트 기반이라 초 단위로 갱신되지 않는다.

**② 모든 판단을 재현 가능하게 남긴다.** 지금은 등록이 필요 없지만,
**2028년 운용업 등록 심사에서 이 기록이 트랙레코드가 된다.**
사후에 못 만든다. **첫 주문부터 남긴다.**

## 2. 구조 — **두 층으로 나눈다. 이게 핵심이다**

일본 금융청 AI 문서가 못 박은 것이 있다.

> 생성형 AI 는 **「같은 입력에 대해 다른 결과가 나올 수 있다」**는 특성을 갖기 때문에
> 종래와 같은 방법으로는 관리할 수 없다

**「AI 가 알아서 사고판다」를 그대로 만들면 재현이 안 되고, 재현이 안 되면
백테스트도 감사도 운용업 등록도 안 된다.** 그래서 층을 가른다.

```
① 판독층 (LLM)          비정형 → 구조화된 신호
   뉴스·공시·리포트를 읽고 「무슨 일이 있었나」를 레코드로 만든다
   출력은 저장된다. 같은 기사를 다시 읽혀도 저장된 레코드를 쓴다
                    ↓
   [ 신호 저장소 ]  ← 여기가 아카이브다. 되돌릴 수 없는 자산
                    ↓
② 매매층 (결정론)        신호 → 포지션
   공개된 규칙이 신호를 받아 종목·비중·타이밍을 정한다
   같은 신호 집합이면 언제 돌려도 같은 답이 나온다
```

**LLM 은 「읽는 사람」이고 매매 결정은 「규칙」이 한다.**

### 왜 이 구조여야 하나

| | 한 덩어리 LLM 이 매매 | **두 층** |
|---|---|---|
| 재현성 | 없다 | **있다** — 신호가 고정되면 결과가 고정 |
| 백테스트 | 불가능 | **가능** — 과거 신호로 규칙만 다시 돌린다 |
| 감사·설명 | 「모델이 그랬다」 | **어느 기사가 어느 신호를 만들었고 어느 규칙이 샀는지** |
| 지수로 전환 | 불가능 | **규칙을 공개하면 그대로 지수가 된다** |
| 개선 | 통째로 다시 | 판독층과 매매층을 따로 고친다 |

**마지막 줄이 특히 크다.** 규칙 기반 매매층은 그 자체가 지수 규칙서다.
투자 AI 를 만들면 지수가 따라 나온다.

## 2-2. ⭐ 세 AI — 애널리스트 · 펀드매니저 · **리스크 관리자**

> 사장님 지시(2026-08-02 KST): 「투자관련 AI(**애널, 펀드매니저, 리스크 관리자**) 셋을
> 만들 수 있도록 하는 걸 **한시도 잊으면 안 된다**」

**앞 절의 두 층 설계에 ③이 빠져 있었다.** 판독층·매매층 둘만 있었고,
**손실 통제를 매매층 안에 넣어 뒀다.** 그건 통제가 아니다 —
**같은 것이 사고 같은 것이 「괜찮다」고 하는 구조**다.

| | 하는 일 | 성질 | 무엇을 못 하나 |
|---|---|---|---|
| **① 애널리스트** | 뉴스·공시·리포트를 읽어 **신호**를 만든다 | LLM (판독) | **매매를 못 한다** |
| **② 펀드매니저** | 신호를 받아 **포지션**을 정한다 | 규칙 (결정론) | **신호를 만들지 못한다** |
| **③ 리스크 관리자** | **한도를 감시하고 멈춘다** | 규칙 (결정론) | **매매를 못 한다. 멈추기만 한다** |

**「못 하는 것」 칸이 이 설계의 핵심이다.** 권한을 겹치지 않게 자른다.

### ③ 리스크 관리자가 왜 독립이어야 하나

```
같은 층에 두면    「이번엔 예외로」가 코드 안에서 일어난다.  그리고 아무도 모른다
독립시키면        멈춤이 기록으로 남고, 왜 멈췄는지 되짚을 수 있다
```

그리고 **운용업 등록의 내부통제 요건**이기도 하다.
2028년 일본 適格投資家向け 등록 심사에서 「리스크 관리가 운용과 분리돼 있는가」를 본다.
**나중에 붙이면 그때 다시 만들어야 한다. 처음부터 가른다.**

### ③이 실제로 하는 일

```
포지션 상한       한 종목이 전체의 N% 를 못 넘는다
일일 손실 한도    넘으면 그날 발주를 멈춘다
최대낙폭 한도     넘으면 전 포지션 정리 후 **사람이 다시 켜야** 돈다
집중도 한도       한 섹터·한 시장에 몰리지 않는다
신호 신선도       오래된 신호로는 발주하지 않는다
모델 변경 감시    ①의 모델이 바뀌면 표시한다 — 성과 비교가 깨지지 않게
```

**최대낙폭 스위치는 자동으로 다시 켜지지 않는다.** 자동 복구는 같은 손실을 반복한다.

### 셋이 주고받는 것

```
①애널리스트 ──신호──▶ ②펀드매니저 ──주문──▶ 시장
                          │                    │
                          └──▶ ③리스크 관리자 ◀──┘
                                  │
                                  └── 한도 위반이면 ②를 멈춘다
                                      (②는 ③을 못 멈춘다)
```

**②는 ③을 못 멈춘다.** 이 한 줄이 통제를 통제로 만든다.

### KLifeMap 3층 구조와 같은 원칙이다

```
KLifeMap   판정(규칙) · 설명(LLM) · 대화(LLM)      「판단은 엔진이 하고 AI는 대답만」
투자 AI     애널(LLM) · 펀드매니저(규칙) · 리스크(규칙)  「판단은 규칙이 하고 LLM은 읽는다」
```

**LLM 이 있는 자리는 ①뿐이다.** 돈이 움직이는 자리(②③)는 전부 결정론이다.

## 3. 신호 — 무엇을 뽑을 것인가

판독층이 만드는 레코드의 뼈대. **스키마를 먼저 고정한다** — 나중에 바꾸면 과거 신호가 무용지물이 된다.

```
{
  ts:        신호 시각 (원문 발표 시각. 우리가 읽은 시각이 아니다)
  source:    출처 (DART · 리서치 · 뉴스 · 통계)
  sourceId:  원문 식별자 — 되짚어갈 수 있어야 한다
  entity:    { market: 'KR', code: '005930' }   ← 이름이 아니라 코드
  kind:      이벤트 종류 (실적 · 가이던스 · 수급 · 정책 · 공급망 …)
  direction: +1 / 0 / -1
  strength:  0~3
  horizon:   예상 반영 기간 (일)
  evidence:  판단 근거가 된 원문의 짧은 인용
  model:     판독에 쓴 모델과 버전   ← 이게 없으면 나중에 비교가 안 된다
}
```

**`evidence` 와 `model` 이 감사 가능성의 핵심이다.**
「왜 샀나」를 물으면 기사 원문까지 되짚어갈 수 있어야 한다.

⚠ **원문 본문을 저장하지 않는다.** 그건 남의 저작물이다.
**식별자와 짧은 인용만** 남긴다. `docs/데이터-출처-라이선스.md` 의 원칙 그대로다.

## 4. 데이터 원천 — 무엇을 훑을 수 있나

### 이미 손에 있는 것

| | 규모 |
|---|---|
| **리서치 목표주가·투자의견** | **66,071건 · 2014~2026 · 12년** |
| 종목코드 대응표 | 86,925건 · 종목 2,624개 |

**12년치가 오늘 이미 있다는 것이 이 계획 전체의 출발점이다.**

### 지금 붙일 수 있는 것 (전부 무료)

| 출처 | 무엇 | 특징 |
|---|---|---|
| **DART** | 국내 공시 | **실시간.** T+1 제약이 없는 유일한 국내 원천 |
| **EDGAR** | 미국 공시 | 무료·재배포 가능 |
| 공공데이터포털 | 시세·거시 | T+1 |
| **관세청 10일 속보** | 품목×국가 수출입 | **한국 수출은 세계 수요의 선행지표다** |
| FRED · 각국 중앙은행 | 금리·통화·거시 | 무료 |
| 언론 RSS | 국내외 보도 | **읽는 것은 되고 본문 재배포는 안 된다** |

### 유료 — 경계를 코드로 가른다

실시간 시세는 증권사 계좌 API 로 얻는다. **매매용은 되고 기사·API 재배포는 안 된다.**

```
실시간 시세  →  매매층만 접근      (재배포 금지)
T+1 공개데이터 →  기사·상품·백테스트  (재배포 가능)
```

**이 경계를 모듈 수준에서 분리한다.** 섞이면 라이선스 위반이고,
한 번 섞이면 어디서 왔는지 되짚을 수 없게 된다.

## 5. ⚠ 가장 급한 것 — **뉴스·공시 아카이빙을 오늘 시작한다**

**신호는 과거 데이터가 있어야 만들 수 있는데, 뉴스는 소급이 안 된다.**

```
2026-08-02 에 시작하면  →  2027-08 에 1년치 신호로 백테스트
2027-02 에 시작하면    →  2028-02 에야 1년치
```

**여섯 달을 늦으면 여섯 달이 영영 빈다.** 리서치 아카이브를 오늘 돌리는 것과
정확히 같은 이유이고, **돈이 안 드는데 되돌릴 수 없는 유일한 항목**이다.

리서치 백필이 끝나는 대로 **DART 실시간 수집기**를 붙인다.

## 6. 검증 — 세 단계를 건너뛰지 않는다

```
① 백테스트     12년 리서치 + 쌓이는 신호로 규칙을 시험한다.    돈 0원
② 페이퍼       실시간 신호로 모의 발주. 슬리피지·체결까지 모사.  돈 0원
③ 소액 실거래   법인 자금 일부로. 매출 안에서만.
```

**②를 충분히 돌리기 전에 ③으로 안 간다.**
백테스트가 좋다는 이유로 원금을 넣는 것이 이 사업에서 가장 흔한 사고다.
슬리피지·수수료·체결 실패·유동성은 백테스트에 안 나온다.

### 성과를 처음부터 감사 가능하게 남긴다

| | 왜 |
|---|---|
| **매매 전용 계좌를 따로 연다** | 미디어 매출과 섞이면 성과 측정이 불가능해진다 |
| **벤치마크를 먼저 정한다** | 나중에 정하면 유리한 것을 고른 것이 된다 |
| **모든 주문·체결·신호를 로그로** | 「그때 왜 샀나」는 사후에 못 만든다 |
| 회계 계정과목 분리 | 세무·감사에서도 갈려야 한다 |

## 7. 손실 통제 — **③ 리스크 관리자가 하는 일이다** (2-2절 참조)

아래는 그 구체 항목이다. **②펀드매니저 안에 두지 않는다** — 2-2절에 적은 이유 그대로다.


**남의 돈이면 수수료만 잃지만 우리 돈이면 원금을 잃는다.**
그리고 **원금은 벌어서 만든 것이라 다시 채우는 데 몇 달이 걸린다.**

코드에 박는다. 사람의 판단에 맡기지 않는다.

```
포지션 상한       한 종목이 전체의 N% 를 못 넘는다
일일 손실 한도    넘으면 그날 발주를 멈춘다
최대낙폭 한도     넘으면 전 포지션 정리 후 사람이 다시 켜야 돈다
집중도 한도       한 섹터·한 시장에 몰리지 않는다
신호 신선도       오래된 신호로는 발주하지 않는다
```

**마지막 스위치(최대낙폭)는 자동으로 다시 켜지지 않게 한다.**
자동 복구는 같은 손실을 반복한다.

| 순서 | 할 것 | 언제 |

| 2 | **신호 스키마 확정** + 저장소 | 2026-08 |
| 3 | **DART 실시간 수집기** — 소급이 안 되니 먼저 | 2026-08 |
| 4 | 판독층 v1 — 공시 → 신호 | 2026 Q3 |
| 5 | 매매층 v1 — 규칙 + 백테스트(12년 리서치) | 2026 Q4 |
| 6 | 뉴스·해외 원천 확대 | 2026 Q4 |
| 7 | **페이퍼 트레이딩 개시** | 2026 Q4 |
| 8 | 규칙 공개 → **지수 산출** (같은 매매층이다) | 2027 상 |
| 9 | 소액 실거래 | 2027 하 |

**1~8 이 전부 돈이 안 든다.** 9번만 원금이 필요하고, 그건 매출 안에서 낸다.

## 9. 정직하게 — 이 설계의 약한 곳

**① 「알아서 투자한다」는 재현성과 상충한다.**
완전 자율 재량을 주면 감사·백테스트·운용업 등록이 전부 막힌다.
그래서 **자율성을 판독층에 두고 매매층은 규칙으로 묶었다.**
이건 타협이 아니라 **유일하게 작동하는 형태**다.

**② LLM 판독의 품질이 검증되지 않았다.**
같은 기사를 다르게 읽을 수 있다. 그래서 **판독 결과를 저장하고 모델 버전을 기록**한다.
모델을 바꾸면 과거 신호를 다시 만들지 말고 **새 버전으로 병기**한다 —
그래야 「모델을 바꿨더니 과거 성과가 좋아졌다」는 착시를 막는다.

**③ 백테스트는 실거래가 아니다.**
12년 리서치로 좋은 결과가 나와도 그건 과거에 맞춘 것일 수 있다.
**페이퍼 트레이딩 기간을 충분히 두는 것 말고 방법이 없다.**

**④ 실시간 시세 비용.** 매매를 시작하면 증권사 계좌가 필요하고,
그 시세는 재배포가 안 된다. **모듈을 처음부터 갈라 놓지 않으면 나중에 못 가른다.**
