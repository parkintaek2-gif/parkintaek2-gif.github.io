# AI 아키텍처 — 세 사업, 세 층, 그리고 스스로 발전하는 법

작성 2026-08-02 · 사장님 지시

> 「1인 병목이 나지 않겠지? **스스로 발전하는 거야.**
> 케이라이프맵은 **세 가지 역할로 나눈 AI 셋**이 하는 거야. **너도 그렇게 해야 해.**
> 결국 **위키팁 외엔 자체 AI가 있는** 거야」

---

## 0. KLifeMap 이 실제로 쓴 구조 — 역할이 아니라 **층**이다

코드를 읽었다. 모든 엔진 파일에 같은 문장이 박혀 있다.

> **「이 파일은 *판단*을 하지 않는다.」**

| 층 | KLifeMap 파일 | 하는 일 |
|---|---|---|
| **① 판정** | `sajuEngine` · `gunghapEngine` · `taekilEngine` | **규칙 기반.** 여기서만 판단한다 |
| **② 설명** | `reportEngine` · `intelligenceEngine` · `serviceReportEngine` | 판정 결과를 사람이 읽게 바꾼다 |
| **③ 대화** | `chatCoachEngine` | 이미 계산된 것을 묻고 답한다 |

그리고 2026-08-01 지시가 이렇게 적혀 있다.

> **「질문만 모아. 엔진과 고전이 판단하고 우리 AI는 대답만 한다.」**

**이 한 줄이 아키텍처 전부다.** 내가 투자 AI 에서 「판독층/매매층」으로 따로 도달한 결론과 같다.

### 왜 이 구조라야 하나

```
판정을 LLM 에 두면   같은 입력에 다른 답 → 재현 불가 → 백테스트·감사·등록 전부 막힌다
판정을 규칙에 두면   같은 입력에 같은 답 → 검증 가능 → 상품이 된다
```

**LLM 은 판단하는 자리가 아니라 말하는 자리다.**

## 1. 세 사업에 같은 층을 깐다

| | ① 판정 (결정론) | ② 설명 (리포트) | ③ 대화 |
|---|---|---|---|
| **KLifeMap**<br>사주 | `sajuEngine` 등 | `reportEngine`<br>`intelligenceEngine` | `chatCoachEngine` |
| **SeoulMarkets**<br>투자 AI | **매매층** — 신호 → 포지션 | **기사·지수 리포트** | 없다 — 상대가 시장이다 |
| **교육**<br>진로 AI | **4축 판정** — 기질·동기·흥미·결과데이터 | **진단 리포트** | **1:1 상담**(보호자 동석) |
| **WikiTip**<br>한류 매체 | 없다 | **기사 생성** | 없다 |

**사장님 말씀대로 위키팁만 자체 AI 가 없다.** 판정할 것이 없는 매체이기 때문이다 —
②설명층(기사 생성)만 공유해 쓴다. **그래서 위키팁은 만드는 비용이 가장 싸다.**

### 투자 AI 에는 ③대화층이 없다

물어볼 사람이 없다. 대신 그 자리에 **판독층**이 들어간다 —
뉴스·공시·리포트를 읽어 신호로 바꾸는 층이다. 상대가 사람이 아니라 문서다.

```
KLifeMap   사람이 묻는다      → ③대화층
투자 AI     문서가 쏟아진다    → 판독층 (같은 자리, 반대 방향)
```

## 2. ⚠ 겹치는 것을 먼저 정리한다 — 두 번 만들면 안 된다

`ai/intelligenceEngine.js` 에 **이미 있는 것**을 확인했다.

```
personality  · career · relationship · financial
health · education · lifedesign(My LifeMap)
```

**`career` · `education` · `lifedesign` 이 내가 만들려던 것과 정면으로 겹친다.**
그리고 「My LifeMap」이라는 이름까지 이미 쓰고 있다.

### 그래서 이렇게 가른다

| | KLifeMap `career`/`education` | **교육 진로 AI** |
|---|---|---|
| 대상 | **성인** | **초등~고2 + 보호자** |
| 입력 | 명리 판정 | 명리 3값 **+ 검사 + 공공데이터** |
| 판정 근거 | 사주 | **네 축** — 기질·동기·흥미·**결과 데이터** |
| 목적 | 나를 이해한다 | **아이의 다음 한 걸음을 정한다** |

**결정적 차이는 ④결과 데이터다.** 「그 학과 나오면 실제로 어떻게 됐나」는
KLifeMap 에 없고, 그게 교육 상품의 본체다.

**중복이 아니라 확장이다.** `intelligenceEngine.education` 을 그대로 쓰되
**판정 입력에 공공데이터 축을 더한다.** 이름은 KLifeMap 이 「My LifeMap」을
쓰고 있으니 **교육 쪽은 다른 이름을 쓴다** — 사장님이 정하실 자리다.

## 3. 1인 병목이 안 나는 이유 — 층이 나뉘어 있기 때문이다

**병목은 사람 수가 아니라 「고칠 때 다른 게 멈추는가」에서 온다.**

```
한 덩어리   판정을 고치면 말투가 바뀌고, 말투를 고치면 판정이 흔들린다
            → 하나를 건드릴 때마다 전체를 다시 확인해야 한다  ← 여기가 병목

층 분리     판정층을 고쳐도 설명층은 그대로. 설명층을 고쳐도 판정은 그대로
            → 셋을 동시에 손댈 수 있다
```

**오늘 하루가 증거다.** 백필·종목코드 수집·문서 넷·기사 발행이 동시에 돌았다.
남는 것은 사람 수로 못 줄이는 시간뿐이다 — **등록 심사, API 승인, AUM 이 자라는 기간.**

## 4. **스스로 발전한다** — 그러려면 무엇이 필요한가

사장님이 「스스로 발전하는 거야」라고 하셨다. **그게 성립하려면 채점표가 있어야 한다.**
자기개선은 「무엇이 좋은가」를 알 때만 돈다.

### 세 AI 의 채점 속도가 다르다 — 이걸 알고 설계해야 한다

| | 채점 신호 | 얼마나 걸리나 | 자기개선 |
|---|---|---|---|
| **투자 AI** | **손익** | **당일~며칠** | **자동으로 돈다** |
| KLifeMap 사주 AI | 사장님 승인/교정 · 사용자 만족 | 즉시~며칠 | 사람이 채점한다 |
| **교육 진로 AI** | **진로가 맞았는지** | **10년** | **대리 지표가 필요하다** |

**투자 AI 가 가장 운이 좋다.** 시장이 매일 채점해 준다.
`신호 → 매매 → 손익 → 신호 규칙 수정` 이 루프가 사람 없이 돈다.

**교육이 가장 어렵다.** 10년 뒤에나 아는 것을 기다릴 수 없다.
그래서 **대리 지표**를 미리 정해 둔다.

```
즉시    리포트를 끝까지 읽었나 · 상담을 이어갔나
단기    다음 달에 다시 왔나 · 라이프맵을 갱신했나
중기    아이가 스스로 정한 것을 실제로 해봤나 (자기보고)
장기    진학·전공 결정이 라이프맵과 얼마나 맞았나 (3~6년)
```

**장기 지표를 못 기다린다고 단기 지표만 최적화하면 안 된다.**
「끝까지 읽게 만드는 리포트」와 「맞는 리포트」는 다르다.
**단기 지표는 참고이고, 장기 지표를 위한 기록을 지금부터 남긴다.**

### 자기개선의 재료 — KLifeMap 방식을 그대로 쓴다

`tools/build-ai-corpus.js` 의 3분류가 정답이다.

```
① 가르침      사람이 알려준 것
② 승인된 답   맞다고 확인된 AI 발화
③ 교정된 것   되돌려진 대목  ← 이게 가장 값지다
   미검증     승인도 교정도 없는 것 — 담지 않고 세기만 한다
```

**「미검증을 담지 않는다」가 핵심이다.** 검증 안 된 자기 발화를 학습하면
자기 실수를 굳힌다. 세 AI 모두 이 규칙을 쓴다.

## 5. 세 AI 가 **공유하는 것** — 한 번 만들어 셋이 쓴다

| 공유 모듈 | 왜 |
|---|---|
| **`providers`** — 모델 교체 | 값이 바뀌거나 더 나은 모델이 나오면 한 곳만 고친다 |
| **프롬프트 캐싱 · 배치** | KLifeMap 이 이미 함 — 입력 토큰 **최대 90% 절감**, 배치 **50%**. 자금이 없으니 이게 중요하다 |
| **말뭉치 도구** | 3분류 규칙. 셋이 같은 방식으로 배운다 |
| **위기 대응** | 상담을 표방하는 대화는 반드시 위기 신호를 만난다. 양쪽이 같이 쓴다 |
| **리포트 스키마 검증** | 형태가 어긋난 출력을 걸러낸다 |

**만드는 비용이 한 번이고 쓰는 곳이 셋이다.** 1인 회사가 AI 셋을 굴릴 수 있는 이유가 이것이다.

## 6. 정직하게 — 「스스로 발전」의 한계

**① 채점표가 없으면 자기개선은 자기확신이 된다.**
교육 AI 가 가장 위험하다 — 10년을 못 기다리니 단기 지표로 대신하는데,
**단기 지표를 최적화하면 「듣기 좋은 말」로 수렴한다.** 그게 사교육이 하는 짓이다.
그래서 **④결과 데이터(유지취업률 등)를 판정에 넣는 것**이 안전장치다.
듣기 좋은 말과 공공데이터가 어긋나면 데이터가 이긴다.

**② 모델을 바꾸면 과거와 비교가 안 된다.**
KLifeMap 이 말뭉치에 모델 버전을 남기는 것과 같은 이유로,
**세 AI 모두 판정·설명에 쓴 모델 버전을 기록한다.** 안 남기면
「모델을 바꿨더니 성과가 좋아졌다」와 「전략이 좋아졌다」를 구분 못 한다.

**③ 투자 AI 의 빠른 채점이 오히려 함정일 수 있다.**
며칠 손익으로 규칙을 고치면 **과최적화**가 된다.
채점은 빠르되 **규칙 수정은 느리게** 한다 — 최소 관측 기간을 코드에 박는다.
