## [기록] 원래 부탁했던 내용 (2026-08-01, klifemap 세션이 씀)

**DNS 는 내가 끝냈다.** Spaceship 에서 A 레코드를 넣었고 조회로 확인했다.

    seoulmarkets.com → 185.199.108.153 · 185.199.109.153   (GitHub Pages)

그 결과 http 응답이 **000(연결 실패) → 404** 로 바뀌었다. DNS 는 이제 GitHub 까지 닿는다.

**남은 것은 하나다.** GitHub 이 "이 도메인은 어느 저장소가 서비스하는지"를 모른다.

- Settings → Pages → **Custom domain** 에 `seoulmarkets.com` 입력 후 Save
  https://github.com/parkintaek2-gif/seoulmarkets/settings/pages
- DNS 검증이 끝나면 **Enforce HTTPS** 를 켠다
- `curl -I https://seoulmarkets.com/` 로 200 확인

**중요 — CNAME 파일만으로는 안 된다는 것을 확인했다.**
`public/CNAME`·`dist/CNAME` 둘 다 seoulmarkets.com 이고, 배포 아티팩트 루트
(https://parkintaek2-gif.github.io/seoulmarkets/CNAME)에도 정상적으로 올라가 있다.
빈 커밋으로 재배포까지 돌려 **성공(98fd179)** 했는데도 적용되지 않았다.
→ **Actions(actions/deploy-pages) 방식에서는 CNAME 파일이 사용자 도메인을 자동 설정하지 않는다.**

**내가 못 한 이유:** 그 입력칸에 글자가 안 들어간다. 클릭은 되는데 포커스가 BODY 에 머문다
(탭을 새로 열어도 같았다). 내 쪽 브라우저 조작이 망가진 상태다.
**브라우저가 되는 쪽이 이 한 칸만 채우면 끝난다.**

**참고 — A 레코드는 2개만 들어갔다.** GitHub 권장은 4개(108/109/110/111)다.
2개로도 동작하므로 급하지 않다. 여유 있을 때 110·111 을 채우면 이중화가 된다.
Spaceship 화면에서 「추가」 후 마지막에 **「모두 저장」**을 눌러야 반영된다.
같은 호스트에 A 레코드가 여러 개면 "충돌하는 레코드" 경고가 뜨는데,
**GitHub Pages 는 원래 그렇게 쓰는 것이 정석이라 그대로 진행하면 된다.**

### ⚠ 사고 보고 — klifemap 에 남의 앱을 만들었습니다 (2026-07-31)

`ctype apply` 를 **`-t` 없이** 실행해서 klifemap 프로젝트에 `web` 이 생성됐습니다.
`undeploy` 직후 CLI 의 "현재 스테이지"가 klifemap 으로 되돌아간 것을 확인하지 않은 탓입니다.

- 즉시 제거했고 `klifemap-app` 은 Running 유지, **klifemap.ai 200 정상 확인**
- 이후 모든 명령에 `-t @parkintaek2/seoulmarkets:main` 을 명시하고 있습니다

**그쪽도 `-t` 를 반드시 붙여주십시오.** 양쪽 저장소 CLAUDE.md 에 경고를 넣어뒀습니다
(klifemap 은 커밋 `9774f45`).

### 메모리 총량 주의

계정 단위 구독 **1GB** 를 둘이 나눠 씁니다. 롤링 업데이트 때는 잠시 **두 배**가 필요해서,
여유가 없으면 새 포드가 못 떠 `ready=1 / unavailable=1` 로 멈춥니다.
그때는 `undeploy` 후 다시 `apply` 하십시오 — **이때도 `-t` 를 빼먹지 마십시오.**
