# Claude Code 작업 지시서 — 영문 데이터저널리즘 홈페이지 구축

## 프로젝트 개요

한국 증시·커머디티·금융 데이터를 영문으로 가공해 발행하는 데이터저널리즘 사이트를
만든다. 기사는 별도 스킬(`market-data-article`)로 AI가 생성하며, 이 홈페이지는
**그 결과물을 깔끔하게 발행·아카이빙·검색엔진에 노출시키는 역할**만 한다.
복잡한 기획 없이 단순하게 간다 — 이게 요구사항이다.

## 하지 않는 것 (Non-goals)

- **유료 결제/구독/페이월 없음.** 전 콘텐츠 무료 공개, 광고 기반.
- **회원가입/로그인 없음.**
- **포털 제휴 연동 없음.** 검색엔진 자연 유입과 신디케이션 네트워크(Benzinga·IBN 등)
  경유 유입만 고려한다.
- **투자자문·개인화 추천 기능 없음.** 정적 콘텐츠 발행 사이트다.
- 복잡한 CMS 관리자 화면 없음 — 기사는 마크다운/JSON 파일로 넣으면 자동 반영되는
  구조면 충분하다.

## 기술 스택 제안

콘텐츠가 전부 정적 기사(빈번히 갱신되지만 사용자별 개인화는 없음)이므로,
KLifeMap처럼 무거운 Node/Express + SQLite 스택 대신 **정적 사이트 생성 방식**을
권장한다. 이유: 서버 비용·유지보수 부담이 거의 없고, SEO에 유리하고, 배포가 단순하다.

- **정적 사이트 생성기**: Next.js(정적 export 모드) 또는 Astro 중 하나를 골라라.
  콘텐츠 갱신 빈도가 높으므로(하루 여러 건) 빌드 속도가 빠른 쪽을 우선한다.
- **콘텐츠 저장**: 기사 1건 = Markdown 파일 1개 + frontmatter(YAML)로 메타데이터
  (제목, 부제, 발행일, 카테고리, 데이터 출처 목록, 데이터 기준시각) 저장.
  `/content/articles/{slug}.md` 구조.
- **차트/그래픽**: 기존 `assets/template.html` 방식(SVG/Canvas 인라인)을 그대로
  마크다운 기사 안에 임베드 가능한 형태로 이식.
- **배포**: Cloudflare Pages 또는 Vercel — 정적 사이트라 무료/저비용 티어로 충분하다.
  KLifeMap의 Cloudtype+Litestream 같은 상시 서버·DB 인프라는 이 프로젝트엔 불필요하다.
- **도메인**: 별도 도메인 사용(KLifeMap과 브랜드 분리 권장, 도메인명은 아직 미정이면
  가제로 진행하고 나중에 치환).

## 사이트 구조 (단순하게)

```
/                     홈 — 최신 기사 리스트(카테고리 무관, 시간순)
/equities             증시 카테고리
/commodities          커머디티 카테고리
/macro                거시경제 카테고리
/article/{slug}       기사 상세
/about                소개 + 데이터 방법론(Methodology) 고정 페이지
/sitemap.xml          자동 생성
/rss.xml              자동 생성 (신디케이션 네트워크 연동에 유용)
```

카테고리는 3개로 시작(증시/커머디티/거시경제), 나중에 늘어나면 추가한다.
내비게이션은 로고 + 카테고리 3개 + About, 그 이상 늘리지 않는다.

## 홈페이지 요구사항

- 헤더: 로고/사이트명(영문), 카테고리 내비게이션 3개, About 링크
- 본문: 최신 기사 카드 리스트(제목, 부제 1줄, 발행일, 카테고리 태그, 데이터 기준시각)
- 푸터: About, 데이터 출처 고지, 저작권, RSS 링크
- 다크/라이트 모드는 선택사항(있으면 좋지만 필수 아님)
- 광고 슬롯: 헤더 아래 배너 1개, 기사 본문 중간 1개, 이렇게만 — 과도한 광고 배치 금지
- 반응형 필수(모바일 우선 — 해외 독자도 모바일 비중 높음)

## 기사 상세 페이지 요구사항

- 스킬 파일(`article-form.md`)의 6단 구조를 그대로 렌더링: 리드/현상정의/메커니즘/
  취약점/증거/판정
- 하단에 **"Data & Verification Notes"** 섹션 고정 — 기준시각, 출처(기관명+API명),
  교차검증 항목, 제외한 수치. 이건 법적 방어 장치이므로 매 기사 반드시 노출.
- Schema.org `NewsArticle` JSON-LD 마크업 필수 (검색엔진 노출 최적화)
- Open Graph 태그 필수 (소셜 공유 시 미리보기)
- 기사 상단에 "AI-assisted, human-reviewed sourcing" 같은 투명성 고지 문구 고정 배치

## SEO / 크롤러 정책

- `robots.txt`는 모든 검색엔진·신디케이션 봇에 개방(포털 제휴 없이 검색 유입이
  핵심 채널이므로 크롤링을 막지 않는다)
- 정적 사이트라 서버사이드 렌더링 이슈 없음 — 크롤러가 완전한 HTML을 바로 받는다
- 사이트맵은 카테고리별로 분리 생성(articles가 많아지면 단일 사이트맵 비대해지는 것 방지)

## 콘텐츠 파이프라인 연동

1. Claude가 `market-data-article`/`sports-data-article` 스킬로 기사를 생성하면
   `/content/articles/{slug}.md`에 frontmatter 포함해 저장
2. 빌드 시 이 폴더를 스캔해 자동으로 페이지·리스트·사이트맵·RSS에 반영
3. 관리자 화면은 없음 — 파일 추가/삭제가 곧 발행/비공개 처리

## 작업 순서 (Claude Code가 진행할 순서)

1. Next.js(정적 export) 또는 Astro 프로젝트 스캐폴딩
2. 콘텐츠 스키마 정의(frontmatter 필드 확정) 및 샘플 기사 1~2건으로 렌더링 검증
3. 홈/카테고리/기사상세/About 페이지 구현
4. Schema.org, OG 태그, sitemap, rss 자동 생성 로직
5. 반응형 스타일링(단순하고 신뢰감 있는 톤 — 화려한 애니메이션 지양, 가독성 우선)
6. 로컬 빌드 확인 후 Cloudflare Pages(또는 Vercel) 배포 설정
7. 완료 후 도메인 연결 가이드 별도 정리

## 참고 — 하지 말아야 할 것

- KLifeMap 수준의 회원/구독/결제 시스템을 이식하지 않는다 — 이 프로젝트는 무료 발행
  매체이지 SaaS가 아니다
- 기사 자동생성 로직(스킬 파일)은 이 저장소에 포함하지 않는다 — 홈페이지 저장소는
  발행된 결과물(md 파일)만 받는 소비자다
- 투자자문·유료 콘텐츠·매매 신호 관련 페이지/기능 요청이 나중에 들어와도 만들지
  않는다(이 프로젝트의 정의상 범위 밖)

## Ⅰ. 회사의 정의

### 1-1. 우리는 무엇을 파는가

> 「우리는 이렇게 **raw data 를 가공하는 데이터저널리즘 + 서비스/컨설팅**」

- 발행만 하는 매체가 **아니다.** 원자료를 받아 가공해 파는 것이 본체다
- 남의 완성된 표를 받아 쓰지 않는다 — 받아 쓰면 우리 방식대로 못 쪼갠다
- 같은 원자료 한 벌로 매체별 화면을 각각 만든다 (수집은 한 번)

### 1-2. 경쟁사와 갈리는 지점

- 그들(CEO스코어·CEO랭킹)은 **재무**를 한다 — 매출·순이익·성장성·수익성·안전성
- 우리는 **사람**을 한다 — 근속·급여·성별격차·임원 재직기간·학력·오너 여부
- ⭐ **1인평균급여 순위를 아무도 안 한다.** 재무 등급 항목이 아니어서다
- ⚠ 그들은 **외감법인 32,000개**를 다룬다. 우리는 상장 3,925개다

## Ⅱ. 발행 형태

### 2-1. 동적 순위 표그래프를 기본으로 한다

> 「**동적 표그래프**를 만들어. 내가 보고 싶은 순위를 선택하면 순위가 쭉 뜨는 내림차순/오름차순」

- 기준(축)을 고르면 그 순위로 다시 선다
- 표 머리를 누르면 뒤집힌다
- 칸 안에 막대를 깐다 — 표(정확한 값)와 그래프(크기 비교)를 **둘 다** 준다
- 차트 라이브러리를 쓰지 않는다. 자기완결 지면이어야 한다
- 구현 → `scripts/render-ranking.mjs`

### 2-2. 집계 단위를 기업 하나로 끝내지 않는다

> 「하나의 기업, 하나의 종목으로만 가공하지 말고 **업종이라든가 그룹을 잇는 데이터로도**」

- 기업별 → **업종별** → **그룹별** → 지역별 → 업력별
- ⚠ `induty_code` 는 자릿수가 2~5자리로 섞인다. **앞 2자리로 정규화**한 뒤 묶는다
- ⚠ 네이버금융·FnGuide 는 `Disallow: /` — **못 쓴다.** KRX·KIND 는 열려 있다
- ⬜ 그룹 묶기는 아직 방법이 없다. 공정위 기업집단이나 최대주주 관계가 필요하다

### 2-3. 첫 화면

- SeoulMarkets — 그래픽을 앞에 싣되 **정적으로 가볍게.** 무겁게 만들지 않는다
- WikiTip — ⛔ 소속사 사진은 **Ⅴ-2 가 풀리기 전까지 쓰지 않는다.**
  대신 **데이터 자체를 그림으로** 쓴다 (레이블 계보도·데뷔 연표·매출 흐름)

## Ⅲ. 편집 규칙

### 3-1. 종목코드

> 「상장사는 **종목 코드를 집어넣어놔라. 한 번만, 앞부분에**」

- `Samsung Electronics (005930) reported ...`
- 첫 등장 때 한 번. 그 뒤로는 붙이지 않는다
- **영문 독자는 한글 회사명을 모른다. 종목코드가 유일한 확인 수단이다**

### 3-2. 좋은 것만 쓰지 않는다

> 「**주자고, 광고를 정보를**」

- 회사 소개를 홍보물이 아니라 **정보**로 준다
- 하이브 영업이익 급감·순손실도 똑같이 쓴다. **좋은 것만 쓰면 그건 광고다**

## Ⅳ. 데이터 축

### 4-1. 「대학 이후」 — 백년지도의 모토

> 「**긍·부정 다 공개돼야 대학 이후를 더 알차진다.** 대학 이후 = 백년지도의 모토」

- **긍정(시상)** — 그 직업에서 무엇을 하면 인정받는가
- **부정(징계)** — 그 직업에서 무엇을 하면 잘리는가
- 둘 다 있어야 실상이 보인다. **상만 보면 미화, 징계만 보면 험담이다**
- 평가가 아니라 사실이라 반발할 대상이 없다

### 4-2. 시상 데이터는 옥석을 가린 뒤 쓴다

> 「언론사들이 **상을 만들어서 돈을 벌지.** 관련 기사에 **본사 기자가 없으면 광고**라고 보면 됨.
>  **광고성이라도 좋은 상도 있거든**」

- 처리 순서 — 수상 데이터 → **상의 등급 판정** → 집계 → 순위
- ⭐ 1순위 지표는 **바이라인** — 자사 기자 이름 없이 자기 상을 보도했으면 보도자료 전재다
- 보조 지표 — 참가비·수상 개수·부문 세분화·주최 구조·반복 수상·심사위원 공개·심사평 구체성
- ⚠ 이분법이 아니라 **합산 점수**다. 돈 받아도 좋은 상이 실제로 있다
- ⛔ 발행할 때 특정 상을 「광고다」라고 **단정하지 않는다.** 지표만 보이고 판단은 독자가 한다
- ⛔ **우리가 시상을 만들지 않는다.** 평가 대상에게 상을 주면 적중률 데이터의 신뢰가 죽는다

### 4-3. 용어를 흐리지 않는다

- **근속연수 ≠ 이직률.** 빠르게 채용한 회사는 평균이 내려간다
- **「전수」를 함부로 쓰지 않는다.** 상장 기획사 전수이지 기획사 전수가 아니다
- 표본 수를 늘 같이 밝힌다

## Ⅴ. 지위와 한계

### 5-1. 데이터를 몰래 고치지 않는다

- DART 신고 단위가 회사마다 다르다 (개월↔년, 천원↔원, 1인평균↔총액)
- ⛔ **추측으로 고치지 않는다.** 걸러내고, **거른 사실을 화면에 밝힌다**
- 순위표는 **1위가 쓰레기면 표 전체를 못 믿게 된다**

### 5-2. ⚠ 우리는 아직 언론사가 아니다

> 「**아직은 언론사 아님에 유의**」

- ⛔ 「우리는 언론사다」를 자료 요청·소개·고지 어디에도 쓰지 않는다
- ⛔ 「언론 보도용」 라이선스 조건(KCMI 등)에 기대지 않는다
- ⛔ 소속사 사진 등 「언론 관행」에 기대는 이미지 사용을 하지 않는다
- ✅ 대신 **보도자료를 배포하는 쪽**에 선다 — 「언론이 아닌 곳은 보도자료를 배포함」
- 인터넷신문 등록을 하면 위가 다 풀린다 → Ⅵ-1

### 5-3. robots 를 우회하지 않는다

- 막힌 곳은 **안 쓴다.** 열린 경로로 같은 걸 만들 수 있는지만 본다
- 안 되면 **정식으로 요청**하거나 순서를 미룬다

## Ⅵ. 일하는 방식

### 6-1. 별로면 말한다 — 단 근거는 데이터로

> 「**내 아이디어를 무조건 수용하지 말고 별로인 건 얘기를 해야 돼.
>  대신 근거를 대고, 근거는 너의 추측이 아니야, 데이터로 갖고**」

- ✅ 「채움률 67.1%, 표본 1,007명 — 쓸 수 있지만 전수는 아니다」
- ⛔ 「어려울 것 같다」·「위험해 보인다」 — 이건 내 추측이다
- ⬜ 못 재 봤으면 **「아직 못 쟀다」**고 한다. 재기 전에 좋다/나쁘다를 말하지 않는다
- ⚠ 단, **사장님의 업계 판단은 내 추정보다 낫다.**
  데이터로 못 재는 관행은 사장님 말씀이 1차 정보다. 내가 반박하는 건 **잴 수 있는 것**에 한한다

### 6-2. 문서를 새로 만들지 않는다

- 기존 문서가 있으면 **그것을 고친다.** 오늘도 새로 만들 뻔했다
- 요구사항은 **이 파일**, 진행 상태는 `작업목록-*.md`, 인계는 `인계-*.md`

### 6-3. 보고 형식

> 「큰 제목 하나만 두지 말고, **큰 제목 있고 세부 내역을 작은 제목으로 해서 리스트업**해」
