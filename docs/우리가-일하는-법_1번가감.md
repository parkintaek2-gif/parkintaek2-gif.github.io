## ⭐ 가장 크게 보태고 싶은 것 — **5장에 「검사가 거짓말한다」를 넣자**

5장은 「했다가 아니라 봤다」인데, 그다음 층이 빠져 있다.
**보긴 봤는데 엉뚱한 걸 봤을 수 있다.** 나는 이걸 **하루에 다섯 번** 겪었다(2026-08-04~05).

```
① 뽑는 폴더와 검사하는 폴더가 달랐다   ← 제일 컸다
   render-reports → 「감수용 리포트」에 쓰고
   verify-reports ← 「리포트-감수용」에서 읽었다   낱말 순서만 뒤집힌 폴더 둘
   → 「33종 통과」·「눈으로 20종 봤다」가 전부 **하루 전 PDF** 기준이었다
② 렌더 도구가 `ok=true` 를 무조건 줬다 → 전문가 감정서가 일반과 **글자 하나까지 같은데 ✅**
③ 명암비 검사가 SVG 를 `color` 로 읽었다(색은 `fill` 에 있다) → **거짓 경보 40건**
④ PDF 를 `-layout` 없이 읽어 2단 배치를 오독 → 「내용 없음」인데 **멀쩡히 있었다**
⑤ 넓은 정규식이 오류 상자보다 먼저 걸려 **틀린 진단명**을 붙였다
```

**교훈 셋**

```
· 거짓 경보는 진짜 한 건을 **묻는다.** ③ 밑에 진짜 넘침 한 건이 깔려 있었다
· 틀린 진단명은 없는 것보다 **나쁘다** — 엉뚱한 데를 고치게 만든다
· 그래서 **검사가 헛도는지 먼저 확인한다** — 일부러 틀린 값을 넣어 **실제로 실패하는지** 본다
  (가격 테스트에 「12,345원」을 넣어 봤고, DB 수정을 되돌려 3건이 실패하는 걸 확인했다)
```

## 5장에 하나 더 — **fixture 로 만든 테스트는 거짓 안심이다**

**같은 사고를 두 번 냈다.**

```
8/1  상담 AI 에 격국 한 줄만 나가고 왕쇠·대운·세운이 하나도 안 갔다. 고쳤다
8/4  감수본을 눈으로 보니 AI 코치가 고객에게 **「당신 격국이 뭐냐」고 되묻고** 있었다
     → 8/1 의 수정은 **운영에서 한 번도 동작한 적이 없었다**
```

함수는 맞았다. **데이터가 거기까지 안 갔다.**
그리고 **두 번 다 테스트는 통과했다** — 내가 **내 코드에 맞춰 fixture 를 만들었기 때문**이다.

```
⛔ 실제 저장 경로를 한 번도 안 거친 테스트는 없는 것보다 나쁘다
✅ 진짜 DB 에 저장하고 진짜 조회를 거치게 짠다
✅ fixture 를 쓸 수밖에 없으면 **실제 저장 코드를 열어 보고** 그 모양으로 만든다
```

## 3장에 보탤 것 — 「한 곳에서 고친다」가 **실제로 되는지 재야 한다**

문서 3-3 은 「규칙은 파일에 남긴다」인데, **파일에 남겼다고 걸리는 게 아니다.**

```
· 공통 부품을 만들어 뒀는데 화면마다 **그릇 이름이 셋**이라 두 화면에 안 걸렸다
  (명반: `.myeongban-grid` / `#palaceCards` / `.saju-4col-grid`)
· 사장님 지적을 반영했는데 AI 프롬프트가 **두 갈래**인 걸 몰라 **절반만** 반영됐다
· CSS 를 고쳤는데 안 바뀌었다 — **같은 셀렉터가 뒤에 또 있어** 계속 덮고 있었다
```

→ **「부품을 쓰는가」를 기계로 세는 검사**를 따로 만들었다(부품 7종 × 화면 71회).
  없었으면 「공통이니까 다 바뀌었겠지」로 계속 갔다.

## 3-4 수정 제안 — 크론은 **바로 걸면 안 된다**

원문 12장에 승격 조건이 있는데 우리 문서에 안 들어갔다. 그리고 **내가 오늘 그걸 어겼다** —
검증 없이 크론 셋을 바로 걸었다.

> *"Scheduled 로 승격하기 전에는 **서로 다른 정상 입력 3건**에서 같은 기준을 통과하고,
>  **멈춰야 할 예외 1건**에서 안전하게 중단하는지 확인한다."*
> *"운영 중인 skill 을 바로 덮어쓰지 마라. **실행 루프와 개선 루프를 분리**해야
>  예약 작업의 품질이 갑자기 흔들리지 않는다."*

우리 4-1(1번 손으로 · 2번 스크립트 · 3번 예약)에 **이 한 줄을 더하면** 완성된다.

## 6장(디자인)에 보탤 잣대 — **활자 위계는 「종류 수」로 잰다**

6-2 의 여섯에 하나 더 제안한다. 재기 쉽고 효과가 크다.

```
활자   글자 크기가 **몇 종류** 쓰이는가
```

우리 리포트 8화면을 재 보니 **23종**이었다.
`9 · 9.5 · 10 · 10.5 · 11 · 11.5 · 12 · 12.5 · 13 · 13.5 · 14 · 14.5 · 15 · 16 · 17 · 18 · 19 · 20 · 21 · 22 · 24 · 26 · 38px`
사주 화면 **한 장에만 16종**. 13px 과 13.5px 이 나란히 있으면
눈에는 위계가 아니라 **잡음**으로 보인다. **0.5px 차이는 「다른 단」이 아니라 「어긋난 것」이다.**

→ 사장님 지시로 **네 단**만 남겼다: `제목 19 > 부제1 15 > 부제2 13 > 본문=표 11.5` (+주 10).
  단 사이 비율 약 1.28. **본문과 표를 같은 크기로** 둔 것이 핵심이다 —
  표만 작게 하면 표가 부록처럼 보인다.

6-3(「트렌드 말고 원칙」)에도 하나 — **크기만으로 세운 위계는 흑백 인쇄에서 약하다.**
제목 계열에 **명조(Noto Serif KR)** 를 주면 크기가 비슷해도 층이 산다.

## 6장에 또 하나 — **화면에서 절대 안 드러나는 결함이 있다**

6-1 의 「눈대중으로는 반대로 판단했다」에 이어서.

```
· 심리검사 점수 막대가 **인쇄에서 통째로 사라졌다** — 배경색으로만 그렸기 때문이다
  숫자만 남았는데 아래 해석 절이 같은 숫자를 또 찍어 **같은 표가 두 번** 나왔다
· 금색(#c9a84c)이 종이에서 **대비 2.1** 이었다. 화면에서는 멀쩡하다
· Tailwind `md:grid-cols-2` 는 **화면 폭**에 반응한다 — 인쇄에서는 규칙이 꺼져
  화면에선 나란하던 두 칸이 **종이에서만** 위아래로 쌓였다
```

→ **인쇄는 「보면 안다」가 안 통한다.** 반드시 **PDF 로 뽑아서** 본다.
  (6-2 에 「인쇄」가 이미 있는데, **화면으로는 원리적으로 못 잡는다**는 걸 한 줄 강조하면 좋겠다)
