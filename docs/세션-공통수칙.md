전문은 `docs/일하는-법-최종본.md`. 여기 있는 건 **그날 당한 것만**.

```

  그날 같은 실수를 **네 번** 했다 (합계 고르기·이상점검·파일명 자리·검증 스크립트)

· **검사가 헛도는지 확인한다.** 일부러 틀리게 해 보고 **실제로 실패하는지** 본다
  라우팅 시험이 **두 번** 헛돌았다 (포트 재사용 · fetch 의 Host 헤더)

· **도구가 입력을 바꾼다.** 윈도 셸은 한글을 CP949 로, fetch 는 Host 를 버린다

· **건수와 크기를 둘 다 본다.** 건수만 보고 「전환이 1위」라 했다가 주식수로는 1/4 이었다

· **발행 전에 숫자를 원본에서 다시 뽑아 대조한다.** 그렇게 해서 6개를 내기 전에 잡았다

· **낸 뒤 숫자가 바뀌면 조용히 고치지 않는다.** 기사 frontmatter 에 `corrections` 를 남긴다
  신뢰는 「틀린 적 없다」로 생기지 않는다. **틀렸을 때 어떻게 하는지**로 생긴다
```

## 요금제별 일하는 시간 — 사장님 지시 (2026-08-22)

> 🔴 사장님 — 「스탠다드 요금제인 세션은 하루에 13시간만 일한다. 프리미어 요금제인 세션은
> 24시간 일한다. 안 그러면 중간에 가다 끊긴다. **이번 주는 더 줄여라 10시간으로**」

```
스탠다드 요금제 세션   이번 주 하루 10시간만 일한다 (13시간 한도보다 여유를 둔다 — 중간에 끊기면 더 나쁘다)
프리미어 요금제 세션   24시간 그대로
```

⚠ 각 자리는 자기가 스탠다드인지 프리미어인지 모르면 사장님께 여쭙거나 계정 설정에서 확인한다.
⚠ 감시기(watchdog)가 "N분째 조용하다"고 알릴 때, 스탠다드 세션의 쉬는 시간(하루 14시간)은
   사고가 아니다 — 그 시간대에 조용한 건 정상이다. 일하는 시간대에 조용한 것만 문제다.

### 정정 (같은 날) — **스탠다드는 하루 13시간이 적당하다**
주간 사용량 확인 후 사장님이 정하셨다: 10시간이 아니라 **13시간**으로 간다(원래 한도 그대로).

### 스탠다드 세션 쉬는 시간 — **22:00 ~ 09:00 (11시간)**
사장님이 정확한 시각을 정하셨다. 이 시간에는 일하지 않는다(감시기가 이 시간대 조용함을 사고로 안 본다).
09:00 ~ 22:00 (13시간)이 일하는 시간이다.

### 정정 — 쉬는 시간 **01:00~12:00** (22:00~09:00 아님)
사장님이 다시 정하셨다. 스탠다드(2·3·4·6번) 일하는 시간은 **12:00~01:00**(13시간), 쉬는 시간은 **01:00~12:00**(11시간)이다.
