## ✅ 판정 ② — EDINET 코드리스트(금융청)는 **상업적 이용 가능**

같은 「종목코드·영문명·시장구분·업종」을 **거래소가 아니라 정부 규제기관**
(금융청 · Financial Services Agency — 한국의 DART/금융위와 같은 자리)이 별도로
공개하는 자료로 받을 수 있다는 것을 확인했다.

```
다운로드 안내       https://disclosure2.edinet-fsa.go.jp/weee0010.aspx
받는 파일           Edinetcode_<날짜>.zip → EdinetcodeDlInfo.csv (Shift-JIS)
e-Gov 데이터포털 등록  https://data.e-gov.go.jp/data/dataset/fsa_20140901_0095/
                    resource/de39fd6a-54e4-48ca-b79b-057f7793fa03
                    → 라이선스 "CC BY" (2026-09-20 확인)
```

EDINET 자체 이용규약(2026-09-20 curl 로 직접 읽음,
`https://disclosure2dl.edinet-fsa.go.jp/guide/static/disclosure/WZEK0030.html`,
최종개정 令和7年4月25日) 원문 —

> 「本ウェブサイトで公開している情報（本コンテンツ）は、どなたでも
> 『公共データ利用規約（第1.0版）』（PDL1.0）に準拠した利用条件の下で、
> 利用することができます。」

PDL1.0 이 요구하는 것 — **가공해서 쓸 때 지켜야 하는 조건이다.**

```
① 출처를 적는다.  예: 出典：EDINET閲覧（提出）サイト（URL）、PDL1.0（規約URL）
② 가공했으면 「가공했다는 사실 + 가공한 주체」를 출처와 별도로 적는다.
   가공물을 국(정부기관)이 만든 원본인 것처럼 내면 안 된다.
```

PDL1.0 이 적용되지 «않는» 예외(1.4항) — 로고·심볼·캐릭터, EDINET 택소노미,
XBRL 작성툴, 대량보유보고서 서식(엑셀). **EDINET 코드리스트는 이 예외에 들지
않는다** — 다운로드 페이지 자체가 코드리스트를 예외 목록과 나란히 두지 않고
별도 항목(「EDINETコードリスト」)으로 다룬다.

⚠ 이용규약 2.2항 — 「웹사이트에서 정보를 추출하는 소프트웨어 기술(스크레이핑
등)로 콘텐츠를 기계적으로 취득하는 것은 금지한다. 다만 API 기능을 쓰는 경우나
API 로 못 받는 콘텐츠를 받는 경우는 예외다」. 코드리스트는 API 가 아니라
다운로드 페이지의 단추(zip)로만 받을 수 있어 후자(API 로 못 받는 콘텐츠)에
해당한다고 읽었다 — 렌더링된 지면을 파싱해 값을 긁어내는 것이 아니라, 페이지가
제공하는 «내려받기 단추» 하나를 눌러 그 결과물(zip)을 그대로 받는 것이기 때문이다.

## 실측 — 받은 자료

```
받은 날     2026-09-20 · archive/raw/japan-jpx-companies/20260920.json

상장 행수    3,818건 (上場 + 증권코드 있음)
칸          edinetCode·submitterType·listingStatus·consolidated·capital·
            fiscalYearEnd·name(일문)·nameEn(영문)·nameReading·address·
            industry·securitiesCode·corporateNumber
```

3,818건은 JPX 파일의 4,441행(REIT·ETF·PRO 마켓 등 포함)보다 적다 — **EDINET
코드리스트는 유가증권보고서 제출 의무가 있는 일반 상장기업 위주**이고, ETF·
REIT·PRO 마켓 등 일부 상품은 별도 서류 체계라 이 코드리스트에 안 잡힐 수
있다. 이 차이는 **「일본 상장 종목 전부」가 아니라 「EDINET 코드리스트가 잡는
범위」**로 적는다 — 못 잰 것은 못 쟀다고 적는다.
