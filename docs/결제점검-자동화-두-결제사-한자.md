# 결제 점검을 **두 결제사 한 자**로 묶고 자동으로 돌린다

> 2026-09-20 · 5번(총괄) · 사장님 지시 「**빠진 시각 안 생기게 두 자 묶어서 자동화해**」

---

## Ⅰ. 왜 묶었나

### 1-1. 자가 둘로 갈려 있으니 한쪽만 돌린 시각이 생겼다

돈이 들어오는 길이 둘인데 재는 자도 둘이었고, 사람이 두 번 쳐야 했다.
그래서 바쁜 시각에 한쪽이 빠졌다. 2026-09-20 하루를 세어 봤다 —

```
토스 (KLifeMap · 원화)        13번   빠진 시각 1·8·13·14시
페이팔 (SeoulMarkets · 달러)   10번   빠진 시각 0·3·5·7·8·10·11시
```

### 1-2. 그리고 보고에서도 한쪽만 이름을 댔다

마커 이름이 서로 달라서 그렇다.

```
klifemap      「HH시-결제점검」          ← 어느 사이트인지 이름에 없다
seoulmarkets  「HH시-서울마켓츠결제점검」  ← 이쪽만 사이트 이름이 붙는다
```

그래서 16시 보고에 페이팔만 적었고, 사장님이 **「토스페이먼츠는 점검을 정기적으로
안하나?」**라고 되물으셨다. 재고 있었는데도 안 재는 것으로 보였다.

⛔ **돈이 들어오는 길이 둘 이상이면 보고에 그 전부를 세워 놓는다.**
  하나만 보이면 나머지는 안 보는 것으로 읽힌다.

---

## Ⅱ. 무엇을 만들었나

### 2-1. 자 하나 — `scripts/check-결제-둘다.mjs` (자가시험 17개)

```bash
node scripts/check-결제-둘다.mjs              둘 다 잰다
node scripts/check-결제-둘다.mjs --빈시각만    오늘 빠진 시각만 본다 (자를 안 돌린다)
node scripts/check-결제-둘다.mjs --자가시험
```

하는 일 넷.

```
1. 자식 자 둘을 차례로 돌린다 (check-klifemap-payment · check-seoulmarkets-payment)
   ⛔ 승인(capture)은 부르지 않는다 — 자식 자들이 이미 그 선을 지킨다. 여기서 더 하지 않는다
2. 마커 하나를 남긴다 — docs/고정업무-마커/<날짜>-<시>시-결제둘다.txt
3. 오늘 «빠진 시각»을 스스로 세어 화면과 마커에 적는다
   ⚠ 묶기 «전»에 남은 옛 마커 두 꼴도 함께 센다. 안 세면 오늘 오전이 통째로 빵꾸로 보인다
   ⚠ 아직 오지 않은 시각은 빵꾸로 세지 않는다
4. 지난 시각 마커가 없으면 「지난 N시를 놓쳤다」를 그 자리에 적는다 — 조용히 넘어가지 않는다
```

### 2-2. 언제 사장님께 알리나 — 🔴 **두 번 잇따라 막혔을 때만**

```
한 번 막힘   ⚠ 화면에만 적고 넘어간다 — 그물이 흔들린 것일 수 있다
두 번 잇따라 🔴 docs/결제-빨간불.txt 를 세우고 사장님께 알린다. 매출이 0 이라는 뜻이다
다시 팔리면   그 빨간불 파일을 스스로 치운다
```

⛔ 잘 팔리는 날의 초록불을 사장님 편지함으로 보내지 않는다 — 우리 살림을 보는 알림은
우리가 받는다. 사장님께 가는 것은 **매출이 실제로 멈췄을 때**뿐이다.

⭐ 이것이 「리스크관리」 자리다. 앞의 둘(잰다·판정한다)만 있으면 확신만 커진다.
  셋째는 **그 판정이 틀렸을 때 무엇을 잃는가**를 본다 — 여기서는 「한 번의 흔들림으로
  사장님을 깨우는 것」과 「진짜 멈춤을 놓치는 것」 사이를 잡는 일이다.

## Ⅲ. 자동으로 어떻게 도나

### 3-1. 윈도 작업 스케줄러 — 매시 :05

```
이름       결제점검-둘다
부르는 것   cmd /c cd /d <저장소> && node scripts\check-결제-둘다.mjs >> .결제점검.log 2>&1
주기       0시 05분부터 60분마다 (하루 24번)
설정       배터리로도 돈다 · 놓친 판은 깨어날 때 따라잡는다 · 10분 넘으면 끊는다 ·
           이미 도는 판이 있으면 새 판을 띄우지 않는다
```

실측(2026-09-20 16:26) — 손으로 한 번 돌려 **LastTaskResult 0 · NextRunTime 17:05** 확인.
로그 꼬리에 「✅ 둘 다 팔린다」가 찍혔다.

### 3-2. ⛔ `CronCreate` 로 하지 않은 까닭

`CronCreate` 예약은 **세션 메모리에만** 있다. 세션이 바뀌면 사라지고, 7일 뒤 만료되며,
세션이 바쁘면 그 시각에 안 뜬다. **오늘 빠진 시각들이 바로 그렇게 생겼다.**
작업 스케줄러는 세션이 죽어도 PC 가 켜져 있으면 돈다.

### 3-3. 손으로 확인하는 법

```powershell
Get-ScheduledTaskInfo -TaskName "결제점검-둘다"        # LastTaskResult 0 이어야 한다
```

```bash
node scripts/check-결제-둘다.mjs --빈시각만            # 오늘 빵꾸가 있나
tail -20 .결제점검.log                                 # 무엇이 찍혔나 (커밋 안 한다)
```

## Ⅳ. 세션이 지킬 것

```
✅ 매시 결제 점검은 이제 «자동»이다. 손으로 또 돌리지 않아도 된다
✅ 다만 «봤다»는 내 몫이다 — 깨어나면 --빈시각만 으로 빵꾸를 한 번 본다
✅ 보고할 때는 토스와 페이팔을 «두 줄»로 낸다. 한쪽만 이름 대지 않는다
⛔ 자식 자 둘을 지우거나 이름을 바꾸지 않는다 — 이 자가 그 이름으로 부른다
   (바꿔야 하면 check-결제-둘다.mjs 의 `결제사들` 배열을 같이 고친다. 자가시험이 잡는다)
⛔ 결제사를 새로 붙이면(예: 원화 다른 PG) `결제사들` 에 한 줄 더한다.
   그것 하나로 점검·마커·빵꾸 세기·알림이 다 따라온다
```
