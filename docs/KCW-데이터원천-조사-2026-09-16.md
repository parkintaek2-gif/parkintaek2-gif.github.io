## Ⅱ. ✅ 쓸 수 있다

### 2-1. MusicBrainz API

```
라이선스   핵심 데이터 CC0(퍼블릭 도메인) — "anyone can download and use ... in any way"
          보충 데이터(주석 등)는 CC BY-NC-SA — 비상업. 핵심 필드만 쓰면 문제없다
살아있음   musicbrainz.org/ws/2/artist/?query=... → 실측 중 「서버가 바쁘다」 429 유사 응답
          (요청 속도를 늦춰 재시도 필요 — 문서상 권장 1req/sec)
쓸 거리   아티스트·그룹 메타데이터, 디스코그래피, 관계(멤버-그룹) — 우리 `collect-kpop-members`·
          `collect-korean-groups` 류의 «검증 크로스체크» 용도로 맞다. K팝 커버리지 자체를
          표본 조회로 다음에 확인해야 한다(오늘은 rate limit 때문에 못 쟀다)
```

## Ⅲ. 🟡 조건부

### 3-1. KOFIC(영화진흥위원회) 박스오피스 Open API

```
살아있음   https://www.kobis.or.kr/kobisopenapi/... → 200 (테스트 키로 "유효하지않은 키값" 응답,
          즉 서버는 살아 있고 무료 키 발급 절차만 남았다)
조건      공공데이터포털 계열 정부 공공 API — 보통 KOGL(공공누리) 자유이용이나, 이 API 자체의
          이용약관 조문은 이번 조사에서 직접 열어 확인하지 못했다(다음 걸음)
쓸 거리   일별·주간 박스오피스(관객수·매출) — K-드라마/영화 축(우리 사업계획 Ⅳ장에 없는 새 갈래)에
          정확히 맞는다. 넷플릭스 차트(93개국 주간)와 짝지으면 "국내 흥행 vs 해외 스트리밍"
          대조 기사가 가능해진다
⬜ 남은 일  무료 키 신청 · 이용약관 원문 확인(다음 세션)
```

### 3-2. AniList API (웹툰/애니 원작 크로스오버 보강)

```
살아있음   POST https://graphql.anilist.co 실측 확인 — 200, 정상 데이터 반환(Solo Leveling 조회)
조건      **서비스 매출 $150/월 미만이면 무료, 넘으면 상업 라이선스 필요**
          (KCW 는 애드센스 승인됐지만 채워짐 0 — 지금은 미만이 확실하다. 다만 매출이 늘면
          다시 봐야 한다 — 사장님의 9월 목표·2031년 매출 목표와 방향이 맞으면 이 조건은
          «성장하면 다시 걸리는 문」이다)
          rate limit 90회/분 — 넉넉하다
          "hoarding·mass collection 금지" — 전체 카탈로그 벌크 다운로드는 안 되고, 필요한
          제목만 골라 조회해야 한다(이미 있는 `collect-kcw-webtoon-adaptations.mjs` 방식과 맞다)
```

### 3-3. Ticketmaster Discovery API (투어·공연 도시 보강)

```
살아있음   401(키 필요, 엔드포인트는 응답함) — https://app.ticketmaster.com/discovery/v2/events.json
조건      약관은 "API 를 판매·재라이선스·그로 수익을 뽑아내는 것"을 금지한다. 우리처럼
          «가공해 편집 기사로 쓰는 것»이 여기 걸리는지는 조문이 명시하지 않는다 — 회색지대.
          요청 한도(rate limit)도 이 약관 페이지에는 숫자가 없다(별도 API 가이드 확인 필요)
쓸 거리   기존 `collect-kcw-tour-city-languages.mjs`(투어 도시별 언어) 축을 실제 공연 일정·
          도시로 보강할 수 있다
⬜ 남은 일  무료 키로 실제 K팝 아티스트 검색 결과 확인 · 정확한 rate limit 문서 확인
```

### 3-4. Google Trends — 공식 API(alpha)

```
상태      2025-07 공개, «신청제»(자기서비스 키 발급 아님) — 2026-08 기준으로도 여전히 alpha,
          가격·일반공개 시점 미공개(Scrapfly 벤더 확인, 2026-08)
판정 근거  아직 못 써본다(승인 대기가 전제) — 지금 당장 쓸 수 있다고 적으면 틀린다
⛔ 대안 경고 pytrends 등 «비공식 스크래핑»은 이 alpha API 와 별개다. Google 이용약관상
          자동화 스크래핑은 금지 소지가 크다 — 이번 조사에서는 **쓰지 않는 쪽으로 판정**한다
✅ 할 일   신청서를 넣어 두는 것은 무료이고 리스크가 없다 — 다음 세션이 신청 폼을 채워도 된다
```

### 3-5. KOCCA 공공데이터(data.kocca.kr)

```
확인 못함  이번 조사에서 이 사이트 자체를 열어보지 못했다(⬜ 로 남긴다)
⚠ 겹침 경고 우리는 이미 `collect-bigdata-culture.mjs`(bigdata-culture.kr)와
          `collect-culture-portal.mjs`(culture.go.kr, 문화공공데이터광장) 로 문체부 산하
          공공 문화데이터를 갈래별로 훑고 있다. KOCCA(한국콘텐츠진흥원)도 문체부 산하이므로
          data.kocca.kr 이 이미 훑은 두 포털과 같은 자료를 다른 창구로 보여줄 가능성이 크다.
          **새로 붙이기 전에 두 수집기의 archive 목록에 KOCCA 표를 검색해 겹치는지 먼저 본다**
```

## Ⅴ. ❌ 못 쓴다 (근거 원문 포함)

### 5-1. Spotify Web API

```
Developer Policy III.13  "Do not analyze the Spotify Content or the Spotify Service for any
  purpose, including without limitation, creating new or derived listenership metrics,
  benchmarking, functionality, usage statistics, user metrics"
Developer Policy III.12  "Do not generate news media, or commercial product offers."
```
우리가 하려는 일(순위·통계 재가공 + 뉴스 기사화) 정확히 둘 다에 걸린다. **가공 자체가 금지 조항의 핵심어와 일치**한다.

### 5-2. Last.fm API

```
ToS 3.1  "You are permitted to use the Last.fm Data solely for non-commercial purposes"
ToS 3.2  상업적 이용은 "commercial use agreement" 별도 신청 필요
```
우리는 애드센스 승인을 받은 광고 매체다 — 상업으로 분류된다. 무료 등급으로는 못 쓴다.

### 5-3. TMDb API

```
약관 원문  "Using TMDB...on or in connection with a 'destination' website...or for driving
  traffic or generating revenue for a website...including from advertising displayed on or
  by the website" 를 상업적 사용의 예로 명시
약관 원문  "Make derivatives of the TMDB APIs or TMDB Content" 금지
```
광고 수익이 있는 사이트가 명시적 예시로 걸려 있다. 무료 등급으로는 못 쓴다 — 상업 계약이 필요.
