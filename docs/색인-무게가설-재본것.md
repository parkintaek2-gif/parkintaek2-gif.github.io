# 「사이트 무게(바깥 링크)가 원인이다」 — 재 보고 **안 된다고 적는다**

> 2026-10-13 12:5x · 5번

## 왜 쟀나

오늘 새벽 메모에 이렇게 적었다 —

> 네 사이트 색인: 글 길이·중복·링크·robots 다 아니다 ⇒ **남는 것은 사이트 무게(바깥 링크)**
> ⛔ 이것은 «잰» 것이 아니라 «남은» 것.

「남은 것」으로 두면 그 위에 올린 판단이 다 흔들린다.
**구글 URL 검사 API 가 `referringUrls` 를 준다.** 그것으로 재 봤다.

## 어떻게 쟀나

색인된 지면과 안 된 지면의 `referringUrls` 수를 견줬다 (표본 9장).

```
✅ 제출되고 색인이 생성되었습니다.     3개  seoulmarkets.com/
✅ 제출되고 색인이 생성되었습니다.     1개  seoulmarkets.com/data
✅ 제출되고 색인이 생성되었습니다.     1개  klifemap.ai/
🔴 크롤링됨 - 현재 색인이 생성되지 않음  2개  klifemap.ai/saju.html
🔴 Google에는 아직 알려지지 않은 URL   못 쟀다  seoulmarkets.com/data/ceo-tenure
🔴 Google에는 아직 알려지지 않은 URL   못 쟀다  seoulmarkets.com/data/gold-bar-premium
🔴 Google에는 아직 알려지지 않은 URL   못 쟀다  seoulmarkets.com/article/korea-household-debt-who-holds-it
🔴 Google에는 아직 알려지지 않은 URL   못 쟀다  klifemap.ai/tti-2026-tokki
🔴 Google에는 아직 알려지지 않은 URL   못 쟀다  klifemap.ai/ttigh-so-so

색인된 것 3장 — 링크 가운뎃값 1
안 된 것  1장 — 링크 가운뎃값 2      ← 안 된 쪽이 «더 많다»
못 쟨 것  5장 — ⛔ 「링크 0」으로 세지 않았다
```

## ⇒ 결론 — **못 쟀다**

🔴 **`referringUrls` 로는 「무게가 원인인가」를 못 가린다.** 까닭이 둘이다 —

1. **안 된 지면은 링크 수가 «아예 안 온다».** 구글이 모르는 URL 이니 당연하다.
   그래서 비교할 짝이 없다. 가장 알고 싶은 쪽이 바로 못 재는 쪽이다.
2. 잰 넷에서는 **안 된 쪽이 오히려 더 많았다**(2 대 1). 표본이 좁아 뜻을 두지 않는다.

⛔ 그러니 「무게가 원인이다」도 「아니다」도 적지 않는다. **「이 자로는 못 쟀다」가 답이다.**
⭐ 재 보고 안 된다고 적는 것도 결과다.

## ⚠ 덤으로 알게 된 것 둘

**① 이 API 의 답이 흔들린다.**
같은 주소(`/article/korea-household-debt-who-holds-it`)를 2분 사이에 두 번 물었는데
한 번은 「발견됨 - 현재 색인이 생성되지 않음」, 한 번은 「아직 알려지지 않은 URL」이었다.
⇒ **한 번 물어 본 답으로 판단하지 않는다.** 날짜를 두고 거듭 물어 같은 답이 오는지 본다.

**② 내 자가 또 한국어를 못 읽었다.**
판정 정규식을 `Submitted and indexed` 같은 영어로만 짜 두어,
「제출되고 색인이 생성되었습니다」를 **🔴 로 찍었다.** 색인된 지면 셋이 전부 빨강이었다.
⭐ 자가 보여 주는 것과 재는 것이 다르면 그 자는 사람을 속인다 — 이 세션에서 열여덟 번째다.
⇒ GSC 응답은 `languageCode` 에 따라 한국어로 온다. **영어만 보는 정규식을 쓰지 않는다.**

## 그러면 남은 길은

```
⛔ 더 쓴다          — 아니다. 띠 102장은 글이 아니라 «구글이 안 온» 것이었다
⛔ 겹침을 줄인다    — 했다(tti 54%→5%). 구글이 온 뒤에야 값이 드러난다
✅ 구글이 «오게» 한다 — 사이트맵 여덟 개를 다시 냈다(10-13 11:03). 사흘을 기다린다
✅ 색인 요청        — 하루 열 장. 고르는 차례를 「길을 여는 장」이 먼저가 되게 고쳤다
⬜ 바깥 링크        — 못 쟀다. 재는 길을 아직 못 찾았다
```

⚠ 바깥 링크를 「못 쟀다」로 둔 채 그 쪽에 일을 쏟지 않는다.
먼저 **구글이 오는지**를 사흘 재고, 와도 색인이 안 되면 그때 다시 가린다.

## ⭐ 인용한 곳까지 따라갔다 (강령 ⑤)

내 임시 자가 한국어를 못 읽었으니, **같은 흠이 다른 자에도 있나** 훑었다.
`Submitted and indexed` 같은 영어 문자열을 쓰는 자가 여덟이었다.

```
check-100y-indexed          languageCode: en-US    ✅ 영어로 물으니 영어 판정이 맞다
check-data지면-색인됐나      languageCode: ko       ✅ 판정은 verdict === PASS 로 한다
check-색인-얼마나-됐나        languageCode: ko       ✅ 한국어·영어 둘 다 받는 정규식이다
check-kcw-indexed           주석에 까닭이 적혀 있다  ✅ 이미 겪고 고친 자리다
나머지 넷                    languageCode 를 안 준다  ✅ 기본은 영어다
```

⇒ **오늘 깨진 것은 내 임시 자 하나뿐이었다.** 그래도 규칙은 남긴다 —

```
✅ 판정은 verdict 로 한다        PASS · NEUTRAL · FAIL — 말에 안 매인다
⛔ coverageState 로 판정하지 않는다  languageCode 에 따라 글이 통째로 바뀐다
✅ coverageState 는 «사람이 읽는 줄»로만 쓴다
⚠ 꼭 글로 가려야 하면 한국어와 영어를 «둘 다» 받는다
  (check-색인-얼마나-됐나 의 /^제출.*색인|Submitted and indexed/i 가 본보기다)
```
