## 3부. 브라우저 여는 법 (2번께 · 다른 유닛도 같습니다)

⛔ 사장님 크롬 프로필 «원본»을 열지 않습니다 — 전용 프로필을 씁니다.

```js
import { createRequire } from 'node:module';
const require = createRequire('file:///C:/Users/User/Documents/GitHub/dataeconomics/package.json');
const puppeteer = require('puppeteer-core');   // klifemap/node_modules 에 이미 있다 (23.11.1)

const 브 = await puppeteer.launch({
  executablePath: 'C:/Program Files/Google/Chrome/Application/chrome.exe',
  headless: 'new',
  userDataDir: 'C:/Users/User/claude-<내이름>',   // ⚠ 유닛마다 «다른» 폴더를 쓴다
  args: ['--no-first-run', '--no-default-browser-check'],
  ignoreDefaultArgs: ['--enable-automation'],     // 자동화 띠를 없앤다
  defaultViewport: { width: 1440, height: 1200 },
});
const 쪽 = await 브.newPage();
쪽.on('dialog', async (d) => { console.log('[알림]', d.message()); await d.accept(); });
```

  그래서 «사장님 로그인 세션»은 못 물려받습니다. **로그인이 필요 없는 신청부터** 하십시오.

## 4부. 다음에 할 일 — 순서

```
1. 각 유닛이 «자기 몫 포털»의 신청 조건을 잰다 — 계정이 필요한가, 무엇이 필수인가
   ⛔ 「필요하다더라」로 적지 않는다. 열어 보고 «필수 칸»을 적는다
2. 로그인이 필요 없는 것부터 신청한다. 받는 주소는 admin@ 또는 u4@
3. 키가 오면 .env 에 넣고 «실제로 불러» 확인한다
   ⛔ 「신청 완료」를 「쓸 수 있다」로 읽지 않는다. 오늘 그걸로 한 번 속을 뻔했다
4. 되는 것만 수집기로 만든다. 안 되는 것은 «왜 안 되는지»를 적는다
5. 각자 새로 확인한 것은 docs/발견/ 에 «제목이 결론인» 문서로 낸다
```

⚠ **막힌 우물마다 「무엇을 대신 찾았는지」를 적습니다.** 사장님이 잡아 주신 것 —
「데이터가 좋은지 안 좋은지 떠나서 **파악**했어야지」. 닫기 전에 대안을 세는 것이 그 뜻입니다.
