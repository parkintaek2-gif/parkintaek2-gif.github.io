
⚠ 우리 `/data` 는 지금 **주제로** 묶여 있다(리서치·목표주가·업종·사람·무역).

⭐ **두 번째 제목이 우리 사업의 문장이다.** 모형은 흔하고 «믿을 수 있는 자료»가 자산이라는 것.
🔴 그리고 이것이 사장님 물음의 답에 영향을 준다 — 콘텐트와 상품을 «다른 사이트로 가르는 것»이

## Ⅳ. 사장님이 물으신 것 둘 — 답할 물음을 못박는다

### 4-1. 물음 하나 — 지금 콘텐트를 **홈에 노출할 것인가**

이 물음은 「좋아 보이나」로 답하지 않는다. **답에 필요한 수를 먼저 적는다.**

| 알아야 하는 수 | 누가 잰다 | 왜 필요한가 |
|---|---|---|
| 지면별 열린 횟수 (28일) | **4번** | 아무도 안 여는 지면을 홈에 올리면 홈이 낭비된다 |
| 손님이 «어디서» 들어오나 | **4번** | 검색으로 바로 들어오면 홈은 첫 화면이 아니다 |
| 홈에서 다음 클릭이 무엇인가 | **4번** | 홈이 실제로 무슨 일을 하는지가 그것이다 |
| 상품 문의가 어느 지면에서 오나 | 5번 | 파는 데 실제로 쓰인 지면이 무엇인지 |

⛔ 위 넷이 없으면 이 물음에 답하지 않는다. **「못 쟀다」로 두고 기다린다.**

### 4-2. 물음 둘 — 노출한다면 **어떻게**

지금 세운 가설 셋. ⛔ 아직 «고른 것»이 아니다 — 위 수를 받고 고른다.

```
가설 A  홈 = 상품 장터        QUICK 꼴. 첫 화면이 상품 목록과 필터다
        ⭐ 파는 데 가장 곧다   ⛔ 검색으로 오는 손님에게는 낯설다
가설 B  홈 = 무료 콘텐트      Japan Markets View 꼴. 기사·데이터 지면이 앞에 서고 상품은 뒤
        ⭐ 방문자에 유리하다   ⛔ 「이 회사가 무엇을 파나」가 안 보인다
가설 C  둘로 나눈다           홈은 콘텐트, /data 를 상품 장터로 «따로» 세운다
        ⭐ QUICK 이 실제로 이렇게 한다 (사이트를 둘로 나눴다)
        ⛔ 우리 손이 둘을 다 돌볼 수 있나 — 그것을 먼저 재야 한다
```

⚠ 사장님 지시 「방문자에 올인」(2026-08-26)과 「데이터 사업 본격화」(2026-09-09)가 여기서 만난다.
  **둘을 한 화면에서 다투게 두지 않는 것**이 이 기획의 핵심이다.

### 4-3. 🔴 실측이 가설 목록을 바꿨다 — 가설 D 를 더한다

3-1-b 에서 LSEG 가 상품 허브에 «기사를 같이» 싣는 것을 봤다. QUICK 은 사이트를 갈랐고
LSEG 는 합쳤다 — **업계가 한 답을 주지 않는다.** 그런데 셋 다 공통인 것이 하나 있었다.

```
가설 D  홈은 그대로 두고, «묶는 축»을 바꾼다
        지금 /data 는 «주제»로 묶여 있다 — 리서치 · 목표주가 · 업종 · 사람 · 무역
        세계 최고는 «어떻게 받아 가나»로 묶는다 — File · API · 지수 · 실시간
        ⭐ 화면을 뒤집지 않고 축만 바꾸는 것이라 «가장 싸고 가장 확실하다»
        ⭐ 그리고 상품 개발이 끝나기 «전에도» 할 수 있다 — 축은 상품 수와 무관하다
        ⛔ 다만 이것만으로는 「홈에 무엇을 낼까」가 안 풀린다. A·B·C 와 같이 쓴다
```

⭐ **지금 고른 것: D 를 먼저 하고, A·B·C 는 4번의 수를 받아 고른다.**
  까닭 — D 는 손님이 우리에게 오는 «말»에 맞추는 일이라 어느 가설을 골라도 필요하고,
  A·B·C 는 수 없이는 취향 싸움이 된다.

⚠ 이 결정은 **내 앞선 판단을 약화시키는 실측을 그대로 받아들인 것**이다.
  나는 3-1 에서 QUICK 의 「사이트를 가른다」를 배울 점으로 적었는데, LSEG 는 반대로 한다.
  ⛔ 먼저 적은 쪽을 편들지 않는다.
