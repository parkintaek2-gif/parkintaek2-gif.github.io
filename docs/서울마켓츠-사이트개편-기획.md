### 2-1-b. 4번 실측 (2026-09-10) — 지면열림·유입경로·다음클릭·이탈 (GA4, 28일·어제까지)

**① 지면별 열린 횟수 (screenPageViews, 28일)**

```
전체 200 = 홈(/) 105 · /data 계열 합 6 · 그 밖(기사·API 등) 89
/data 계열 안 — /data 4 · /data/concentration 1 · /data/pension-wage-panel 1
             (나머지 상품 지면 여덟 개는 이 28일 동안 열림 0)
```
🔴 **/data 계열은 전체 열림의 3%뿐이다.** 홈이 105로 절반이 넘는다. 상품지면 열 개 중
  여덟 개는 이 창에서 «한 번도 안 열렸다» — 상품이 안 좋아서가 아니라 **아직 아무도
  그 문 앞까지 안 갔다**는 뜻일 수 있다(아래 ②·③과 같이 읽는다).

**② 유입 경로 — 검색이 어디로 바로 들어오나**

```
전체 세션 132 = 홈 착지 85 · /data 로 «바로» 착지 1 · 그 밖(기사 등) 46
⇒ /data 로 바로 들어오는 세션은 1%뿐이다. 지금은 «홈을 거쳐야 /data 에 닿는» 구조다
   (아직 /data 를 직접 검색해서 오는 손님이 없다는 뜻이지, 홈이 잘 이끈다는 뜻은 아니다
    — ③을 같이 봐야 한다)

유입 출처 상위(세션) — 95 (direct) │ (none) · 11 (not set) · 10 chatgpt.com(ai-assistant)
                     · 9 bing(organic) · 4 google(organic)
```
⭐ **direct 가 압도적**이다(72%). 검색 유입은 아직 작다(구글 4 · 빙 9). 다만 **ChatGPT
  경유가 10건**으로 구글보다 많다 — AI 도우미 인용이 검색엔진보다 먼저 자리 잡고 있다.

**③ 홈에서 다음 클릭 — «근사치»다 (GA4 Data API 엔 공식 「다음 페이지」 차원이 없다)**

```
pageReferrer 가 홈 URL 과 정확히 같은 페이지뷰를 모은 근사치(확정 아님) —
상위: /article/korea-leading-index-climbs-coincident-flat(2) · /equities(2) ·
      기사 다섯 편(각 1) · /data/concentration(1)
```
⭐ 홈에서 다음으로 가는 곳은 **기사·시황(/equities)이 대부분**이고 **/data 계열은
  열 건 중 한 건뿐**이다. 지금 홈이 손님을 상품지면으로 거의 안 이끌고 있다는 근거다.

**④ 이탈 — GA4 표준 지표에 「퇴장 지면(exit page)」이 없다 (metadata 로 확인)**

```
⛔ exits·entrances 지표 자체가 이 속성엔 없다(metadata 엔드포인트로 직접 확인·검증됨).
   bounceRate·engagementRate 뿐이다. 「퇴장 지면」은 지어내지 않고 못 쟀다로 둔다.
⭐ 대신 «착지 지면별 이탈률»(다른 개념 — 시작하자마자 끝난 지면) —
   홈(/) 착지 이탈률 66%(세션 76) · 그 밖 상위: 여러 기사 지면 33~100%(표본 1~4건뿐이라 흔들림 큼)
```

### ⭐ 4번이 읽은 것 — 「홈에 지금 콘텐트를 낼까」에 대한 실측 근거

```
① /data 계열은 지금 홈·유입·다음클릭 어디서도 압도적 소수다(3%대). 「손님이 안 찾는다」가
   아니라 «아직 문 앞으로 안 끌려간다»에 가깝다 — 홈이 기사·시황 쪽으로만 이끌고 있다
② 검색(구글 4 · 빙 9)보다 direct(95)·AI도우미(10)가 크다 — 지금은 «아는 사람이 직접 옴»
   단계다. 표본이 작아(전체 132세션) 이 비율이 다음 28일에도 그대로일지는 못 쟀다
③ 판정(«그래서 홈에 어떻게 낼까»)은 5번·2번 몫이다 — 4번은 수만 낸다(5번 원문 그대로)
```

### 4-1. 물음 하나 — 지금 콘텐트를 **홈에 노출할 것인가**

이 물음은 「좋아 보이나」로 답하지 않는다. **답에 필요한 수를 먼저 적는다.**

| 알아야 하는 수 | 누가 잰다 | 왜 필요한가 |
|---|---|---|
| 지면별 열린 횟수 (28일) | **4번** | 아무도 안 여는 지면을 홈에 올리면 홈이 낭비된다 |
| 손님이 «어디서» 들어오나 | **4번** | 검색으로 바로 들어오면 홈은 첫 화면이 아니다 |
| 홈에서 다음 클릭이 무엇인가 | **4번** | 홈이 실제로 무슨 일을 하는지가 그것이다 |
| 상품 문의가 어느 지면에서 오나 | 5번 | 파는 데 실제로 쓰인 지면이 무엇인지 |

⛔ 위 넷이 없으면 이 물음에 답하지 않는다. **「못 쟀다」로 두고 기다린다.**

### 4-2. 물음 둘 — 노출한다면 **어떻게**

지금 세운 가설 셋. ⛔ 아직 «고른 것»이 아니다 — 위 수를 받고 고른다.

```
가설 A  홈 = 상품 장터        QUICK 꼴. 첫 화면이 상품 목록과 필터다
        ⭐ 파는 데 가장 곧다   ⛔ 검색으로 오는 손님에게는 낯설다
가설 B  홈 = 무료 콘텐트      Japan Markets View 꼴. 기사·데이터 지면이 앞에 서고 상품은 뒤
        ⭐ 방문자에 유리하다   ⛔ 「이 회사가 무엇을 파나」가 안 보인다
가설 C  둘로 나눈다           홈은 콘텐트, /data 를 상품 장터로 «따로» 세운다
        ⭐ QUICK 이 실제로 이렇게 한다 (사이트를 둘로 나눴다)
        ⛔ 우리 손이 둘을 다 돌볼 수 있나 — 그것을 먼저 재야 한다
```

⚠ 사장님 지시 「방문자에 올인」(2026-08-26)과 「데이터 사업 본격화」(2026-09-09)가 여기서 만난다.
  **둘을 한 화면에서 다투게 두지 않는 것**이 이 기획의 핵심이다.

### 4-3. 🔴 실측이 가설 목록을 바꿨다 — 가설 D 를 더한다

3-1-b 에서 LSEG 가 상품 허브에 «기사를 같이» 싣는 것을 봤다. QUICK 은 사이트를 갈랐고
LSEG 는 합쳤다 — **업계가 한 답을 주지 않는다.** 그런데 셋 다 공통인 것이 하나 있었다.

```
가설 D  홈은 그대로 두고, «묶는 축»을 바꾼다
        지금 /data 는 «주제»로 묶여 있다 — 리서치 · 목표주가 · 업종 · 사람 · 무역
        세계 최고는 «어떻게 받아 가나»로 묶는다 — File · API · 지수 · 실시간
        ⭐ 화면을 뒤집지 않고 축만 바꾸는 것이라 «가장 싸고 가장 확실하다»
        ⭐ 그리고 상품 개발이 끝나기 «전에도» 할 수 있다 — 축은 상품 수와 무관하다
        ⛔ 다만 이것만으로는 「홈에 무엇을 낼까」가 안 풀린다. A·B·C 와 같이 쓴다
```

⭐ **지금 고른 것: D 를 먼저 하고, A·B·C 는 4번의 수를 받아 고른다.**
  까닭 — D 는 손님이 우리에게 오는 «말»에 맞추는 일이라 어느 가설을 골라도 필요하고,
  A·B·C 는 수 없이는 취향 싸움이 된다.

⚠ 이 결정은 **내 앞선 판단을 약화시키는 실측을 그대로 받아들인 것**이다.
  나는 3-1 에서 QUICK 의 「사이트를 가른다」를 배울 점으로 적었는데, LSEG 는 반대로 한다.
  ⛔ 먼저 적은 쪽을 편들지 않는다.
