## 0. 먼저 — **이 사이트에서 가장 위험한 것 하나**

```
🔴 DB 가 «컨테이너 안»에 있다. 영구 디스크(볼륨)가 없다.
   .cloudtype/app.yaml 에 volume 선언이 아예 없다 — 재배포하면 파일이 사라진다.
   버티게 하는 것은 litestream → R2 복제 «하나»뿐이다.
```

2026-09-11 에 이것이 실제로 터졌다 — R2 열쇠가 지워지자 `docker-entrypoint.sh` 가
`litestream restore … || rm -f "$DB"` 로 **DB 파일을 지웠고**, 다음에 뜰 때 빈 DB 로 시작했다.

⛔ **그래서 klifemap 에는 `ctype apply` 를 치지 않는다.** 콘솔 환경변수가 통째로 지워지고,
  그중 R2 열쇠 넷이 사라지면 위 사고가 그대로 재현된다.
✅ 배포는 **Cloudtype 대시보드**에서 한다(아래 3-2).

## Ⅱ. 손님이 걷는 길 세 징검다리 — **여기만 지키면 매출은 산다**

### 2-1. 들어오기

```
✅ 열려 있다   google · kakao
🔴 내렸다      naver — 이 서버에서 네이버에 «아예 안 닿는다»(www.naver.com 조차)
```

`setDefaultResultOrder('ipv4first')` 를 넣어도 같았다. 서버 IP 는 34.8.247.175(Google Cloud).
재는 자를 서버에 붙여 놨다 — `GET /api/health?probe=1` 이면 다섯 곳 도달 여부가 그대로 나온다.

✅ **네이버로 가입한 손님은 «0명»이다 — 세어서 확인했다 (2026-09-17 18:4x).**

세는 창구가 없어서 그날 만들었다 — `GET /api/admin/users-by-provider`.
⛔ 「없을 것이다」로 넘기면 있는 손님을 버리는 것이라, 짐작하지 않고 **셌다.**

```
email            5명 (살아있는 5)
google           4명 (살아있는 4)
guest_checkout   4명 (살아있는 3)
naver            0명   ← 이관할 것이 없다. 이대로 둔다
합계            13명
```

⚠ 다시 네이버 문을 열 날이 오면, 열기 «전»에 `/api/health?probe=1` 로 닿는지부터 본다.
  지금은 안 닿는다 — 열쇠 문제가 아니라 **이 서버에서 네이버가 안 잡히는 것**이다.

### 2-2. 돈 내기 — 🔴 오늘 겪은 함정

```
토스 라이브 열쇠는 live_gck_ 다 = «주문서형·결제창형(위젯)»
  ✅ tp.widgets()  를 써야 한다
  ⛔ tp.payment()  를 쓰면 토스가 거부한다 — 손님 화면엔 「결제창을 열지 못했습니다」만 뜬다
```

이것 때문에 **손님이 아무도 결제를 못 하고 있었다.** 설정은 전부 정상이었다 —
`enabled:true · live:true · 실키`. **설정을 아무리 읽어도 안 보인다.**

그리고 위젯은 **보이는 자리에 그려야 한다.** `hidden` 인 부모 안에서 그리면 높이가 0 이 된다.
`classList.remove('hidden')` 을 **먼저** 하고 그다음 `renderPaymentMethods()` 다.

⚠ 사장님 계정으로 눌러 보면 「관리자라 0원 즉시 처리」로 빠져 **결제 경로를 아예 안 탄다.**
  반드시 **로그인 안 한 손님**으로 재야 한다.

### 2-3. 다시 보기

로그인한 회원의 「감명 내역」이다. 무인증으로 `/api/my/sessions`·`/api/my/payments` 를 부르면
**401 이어야 한다** — 200 이면 남의 것이 새는 반대 방향 사고다(검사가 이것도 본다).

## Ⅲ. 날마다 / 손댈 때마다 하는 것

### 3-1. 재는 자

```bash
node scripts/check-klifemap-payment.mjs     # 손님으로 결제창까지 «눌러» 본다 (자가시험 27)
node scripts/check-klifemap-login.mjs       # 가짜 코드로 토큰 교환까지 실제로 밟는다
node scripts/check-klifemap-health.mjs      # degraded 면 그 자리에서 멈춘다
node tools/klifemap-visitors.mjs            # 순방문자 (bj_vid 쿠키 기준)
```

⛔ **「단추가 보인다」를 「결제가 된다」로 읽지 않는다.** 그 착각이 이번 사고를 만들었다.
⛔ 승인(capture)은 부르지 않는다. 카드번호를 넣지 않는다. 결제창이 «뜨는 것»까지만 본다.

klifemap 저장소 자체 검사는 **96개**이고 `npm test`(`node --test`)로 돈다.

### 3-2. 배포 — ⛔ `ctype apply` 금지

```
app.cloudtype.io → 구글 로그인(parkintaek2@gmail.com) → @parkintaek2/klifemap
  → 서비스 「klifemap-app」 클릭 → 「재배포」 → 확인창 «OK»
```

⚠ `options.start` 를 채우면 안 된다 — ENTRYPOINT 가 덮여 litestream 이 안 뜨고 R2 복제가 끊긴다.

### 3-3. 시각

컨테이너는 **UTC** 다. 날짜로 무엇을 판정하면 반드시 KST 로 옮긴다 —
`Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Seoul' })`.
2026-09-17 에 이것 때문에 **이벤트가 하루 늦게 켜질 뻔했다.**
