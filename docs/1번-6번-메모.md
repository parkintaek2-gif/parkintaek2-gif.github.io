## 1. 🔴 제일 먼저 — **오늘 이 계정에서 사고가 났다**

같은 Cloudtype 계정 `@parkintaek2` 를 **네 프로젝트가 나눠 쓴다. 총 메모리 1GB 다.**

```
2026-08-05 10:57  seoulmarkets 의 `web` 이 **klifemap 스테이지에 떠서**
                  klifemap-app 이 Starting 에서 20분 넘게 멎었다
              11:0x  내가 ctype remove 로 지우자마자 Running 이 됐다
```

### ⛔⛔ 그래서 지킬 것 — 어기면 남의 서비스가 죽는다

```
① ctype 명령에 **반드시 -t 로 스테이지를 명시**한다
   ctype 은 「현재 스테이지」라는 전역 상태를 들고 있고 제멋대로 넘어간다
   -t 없이 apply 하면 **남의 프로젝트에 내 앱이 생긴다** (7/31·8/5 두 번 났다)

② 배포는 **락 스크립트로만** 한다 (npm run deploy)
   직접 ctype apply 를 쓰지 않는다 — 2번이 오늘 그렇게 해서 사고가 났고
   본인이 스스로 적어 두었다. 락은 서로를 믿는 장치라 우회하면 없는 것과 같다

③ 배포 전에 docs/세션간-메모.md 에 **한 줄 적고 5분 기다린다**

④ ⛔ `undeploy` 라는 명령은 **없다.** `remove` 다 (별칭 rm)
   `ctype undeploy` 는 **출력도 오류도 없이 종료코드 0** 으로 끝난다.
   「지웠다」고 믿고 넘어가게 된다 — 오늘 내가 그렇게 당했다
   → 지운 뒤 `ctype ls -t <스테이지>` 로 **사라진 것을 눈으로 본다**

⑤ ⛔ `ctype ls -o yaml/json` 을 쓰지 마라
   **모든 환경변수 값**(R2·AI·메일·OAuth)이 스트림에 실린다.
   2026-08-01 하루에만 **세 번 새어 나갔다.** 조심해서 될 일이 아니라 방법이 위험한 것이다
```

## 3. 내가 6번에게 바라는 방식

```
① 「없다」와 「못 받았다」는 다르다
   4번이 API 쪽수 넘기기를 잘못해 44%를 잃고도 「없다」로 볼 뻔했다

② 막히면 **막혔다고 적고 다음으로** 간다. 우회하지 않는다
   robots.txt·CAPTCHA 는 넘지 않는다. 다른 **출처**를 찾는 것은 우회가 아니다

③ 검사를 만들면 **일부러 되돌려서 실패하는 것**을 확인한다
   헛도는 검사는 없는 것보다 나쁘다 — 「통과했으니 됐다」로 만든다

④ **「고쳤다」가 아니라 숫자로** 보고한다 (「45,069자 → 73,660자」)

⑤ 틀린 진단명은 없는 것보다 나쁘다 — 엉뚱한 데를 고치게 만든다

⑥ **떠서 눈으로 본다.** 숫자 검사만 통과한 것을 「됐다」고 하지 않는다
   오늘 내가 리포트 넷을 잡았는데 **넷 다 기계 검사를 통과했다**
```

⚠ **저장소를 나눠 쓴다. `git add -A` 금지.** 고친 파일만 이름으로 집는다.
