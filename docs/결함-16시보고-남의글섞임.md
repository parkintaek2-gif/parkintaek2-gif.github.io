# 16시 통합 보고 모으는 자에 «남의 글이 섞이는» 결함

> 적은 날 2026-09-08 · 적은 자 5번 · 대상 `scripts/collect-1600-report.mjs`
> 🔴 **아직 안 고쳤다.** 두 번 고쳐 보고 두 번 되돌렸다. 그 기록이다.

## 무엇이 일어났나

16시 보고를 마감 전에 만들어 보니 **1번 슬라이드에 1번 보고가 아니라 5번(내) 글**이 실려 있었다.

까닭은 내가 재촉 글에 «예시»를 넣은 것이다 —

    ```
    ## [업무보고] 1번 KLifeMap · 2026-09-08
    ```

이 자는 코드 울타리를 안 보고 그 줄을 **진짜 1번 보고 머리**로 잡았고,
그 뒤에 오는 내 글 전부를 1번 보고 본문으로 담았다.

⚠ 이대로 보내면 사장님이 1번 자리에서 남의 글을 읽는다.
9/05 에 「업무보고에 1번 것 하나만 들어 있었다」로 지적받은 것과 **같은 갈래**의 사고다.

## 고쳐 보고 두 번 되돌렸다 — 그 까닭

### 첫 시도 — 울타리 안에서 `continue`

```
결과: 6/6 → 4/6.  2번·3번의 진짜 보고를 «잃었다»
까닭: 울타리 안에서 continue 를 해 «닫는 규칙»까지 건너뛰었고,
      여닫이가 홀수인 글 하나 때문에 그 뒤 전부가 울타리 안이 됐다
```

### 두 번째 시도 — 머리 판정에만 울타리를 보고, 새 머리에서 리셋

```
결과: 여전히 4/6. 1번도 여전히 샌다
까닭: 이 메모는 20만 줄이 넘고 여섯 자리가 이어 쓴다.
      그 안의 ``` 짝은 «어느 지점에서든 홀짝이 뒤집혀 있다».
      ⇒ 전역 울타리 짝세기 자체가 이 자료에 맞지 않는 자다
```

⛔ 마감 25분 전이었고, 손으로 짠 슬라이드가 이미 옳게 나와 있었다.
**세 번째 시도를 하지 않았다.** 시간에 밀려 고치면 더 나쁜 것을 내보낸다.

✅ 원본과 PDF 를 docs/보고/16시-통합/ 에 남겼다

## 다음에 고칠 사람에게 — 두 갈래가 보인다

### 갈래 하나: 트리거를 없앤다 (지금 당장 되는 것)

```
⛔ 메모에 «예시 제목»을 적지 않는다. 「## [업무보고] N번 …」 꼴을 예시로 쓰지 않는다
✅ 예시가 필요하면 머리 글자를 바꿔 적는다 — 「(예) 업무보고 N번 …」
```

⭐ 이것만으로 오늘 사고는 안 난다. 내가 오늘부터 지킨다.

### 갈래 둘: 자를 고친다 (조심해서)

⛔ 전역 울타리 짝세기로 가지 말 것. 두 번 다 그것 때문에 실패했다.
✅ 대신 이 둘 중 하나를 재 보라 —

```
· «그 줄이 들여쓰기 되어 있나» — 예시는 보통 들여쓰기 안에 있다.
  오늘 내 예시는 울타리 «안»이었고 들여쓰기는 없었다 — 그러니 이것만으론 부족하다
· «그 줄을 누가 커밋했나» — git blame 으로 그 줄의 저자를 본다.
  1번 보고 머리를 5번이 커밋했으면 그것은 «예시»다. 이것이 가장 확실하다
  ⚠ 다만 느리다. 오늘 날짜 구간의 «머리 줄들»만 blame 하면 된다(수십 줄이다)
```

## 고쳤는지 재는 법 — 둘을 «다» 봐야 한다

```
1. node scripts/collect-1600-report.mjs 2026-09-08
   → 「6/6 유닛 찾음」이 그대로 나오나 (첫 시도는 여기서 4/6 으로 떨어졌다)
2. 1번 칸에 「함께 여쭙는 것」·「채워 주실 칸」 같은 5번 글이 섞이나
   → 섞이면 아직 안 고쳐진 것이다
```

⛔ 1번만 보고 「고쳤다」고 하지 말 것. 첫 시도가 그렇게 통과할 뻔했다.
