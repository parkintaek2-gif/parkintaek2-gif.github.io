## Ⅴ. 다음에 확인하는 사람이 알아야 할 것

### 1. **400 과 403 을 반드시 가른다**
```
400 / NO_OPENAPI_SERVICE_ERROR  →  **내 URL 이 틀렸다.** 미승인이 아니다
403                              →  경로는 맞고 권한이 없다. 이때만 「대기」
```
이걸 섞어서 **승인된 API 6개를 몇 주째 「미승인」으로 보고**했다.

### 2. `DATAGO_KEY` 는 **이미 URL 인코딩된 값**이다
`encodeURIComponent` 를 한 번 더 걸면 403 이고, 승인됐는데도 미승인으로 읽힌다.

### 3. **오퍼레이션 이름을 지어내지 않는다**
포털 상세 화면에서 긁는다. 지어내면 400 이 나고 그걸 또 미승인으로 읽게 된다.
```js
[...new Set((document.body.textContent.match(/\/get[A-Za-z0-9_]+/g)||[]).map(s=>s.slice(1)))]
```

### 4. 포털 신청은 **자동화된다** (2026-08-04 확인)
`fn_save()` 가 네이티브 `confirm("신청하시겠습니까?")` 를 띄운다.
그게 뜨면 **브라우저 자동화가 통째로 멎는다. 에러도 안 난다.**
```js
window.confirm = () => true; window.alert = () => {}; fn_save();
```
곁들여 — 「전체 선택」은 안 먹는다(개별 `click()`), textarea 는 네이티브 setter + input/change 이벤트.
목록→상세 `fn_detail(pk, reqstNo, '0', 'PR0027')` · 상세→변경 `fn_reqst('change', '변경')`.

### 5. **상세기능은 기능 단위로 감시한다**
하나만 승인돼도 데이터셋 단위로는 「승인」으로 보인다.
국민연금이 그랬다 — 3종 중 1종만 열린 채 반나절.
`watch-approvals.mjs` 에 기능별 줄을 따로 넣어 뒀다.

### 6. 대학알리미는 **응답 구조가 다르다**
최상위가 `response` 로 안 싸여 있고 `{header, body}` 다.
그리고 오퍼레이션 27개 중 **Regional 12개만 파라미터 없이 되고**,
Comparison·Notice 15개는 **학교아이디가 필수**라 0건이 온다(에러가 아니다).
