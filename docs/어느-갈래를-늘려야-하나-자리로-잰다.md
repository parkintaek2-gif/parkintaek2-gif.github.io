## Ⅱ. 🔴 `/person` — 지면 635장에서 노출 51

```
노출에 «오른» 지면      21장 / 만든 635장
그중 노출 1회뿐인 장    14장 (67%)
클릭이 있는 장          0장
평균 자리               73.5위
```

### 2-1. 제 가설이 틀렸습니다

저는 「사람 이름 그대로를 노려서 위키백과·IMDb 에 밀린다」고 생각했습니다. **아니었습니다.**

```
검색어가 «이름 그대로»인 것       0 / 28건
검색어가 «네 낱말 이상»(롱테일)   23 / 28건
```

이미 롱테일로 뜨고 있습니다. 그런데 **그 롱테일에서 67~99위**입니다.

```
「kim woo-bin movies」                        자리 70.7
「byeon woo-seok movies and tv shows」        자리 82.8
「woo do hwan netflix」                       자리 68.3
「ji chang wook netflix dramas」              자리 87.0
```

### 2-2. 지면이 얇아서도 아닙니다

`/person/kim-woo-bin` 을 열어 봤습니다. 제목이 검색 의도와 **정확히** 맞습니다.

```
<title>Kim Woo-bin movies and TV shows — 90 countries on Netflix</title>
설명    4편 · 691 chart places · 90 countries · Every title is listed
본문    작품 표(자리·나라·주·최고순위·첫 차트일) · 별자리 · 나이 · 다음 갈 곳 링크
정직함  「This is a floor, not a filmography」를 스스로 적어 뒀다
```

⭐ 바로 그 정직함이 이 질의에서 **불리하게** 작동합니다. 손님이 「movies」로 물을 때 원하는 것은
**전체 작품 목록**이고, IMDb·위키백과·MyDramaList 가 그것을 가지고 있습니다.
우리는 **차트에 오른 4편**만 가지고 있고, 그것을 숨기지 않고 적었습니다.

⬜ **못 쟀습니다** — 도메인 신뢰도(새 도메인이라 깊이 밀리는 것)가 얼마나 작용하는지는
  우리 자료로 잴 수 없습니다. 「지면 품질 탓」이라고도, 「도메인 탓」이라고도 단정하지 않습니다.

## Ⅲ. ⭐ 되는 것은 `/title` 입니다 — 그리고 그 까닭이 분명합니다

```
「project wolf hunting netflix」                자리 11.1 · 노출 25
「the killer: a girl who deserves to die netflix」 자리  8.7 · 노출 21
「decision to leave netflix country」           자리  8.5 · 노출 13
```

⭐ **작품 이름 + netflix** 는 우리가 이깁니다. 그 질의에 인기 상대가 얇고, 「어느 나라에서
차트에 올랐나」는 **우리 자료가 실제로 가장 좋은 답**입니다.
사람 이름은 백과사전이 쥐고 있고, 작품의 «나라별 자취»는 아무도 안 셉니다.

### 3-1. ⛔ 제가 쓰다가 한 번 잘못 짚었고 스스로 정정했습니다

처음에 「`/market` 이 자리 8.7 로 가장 좋으니 그것을 본보기로 삼자」고 적었습니다. **틀렸습니다.**
검색어를 열어 보니 이랬습니다.

```
「https://www.netflix.com/tudum/top10?week=2024-11-03」   노출 62 · 자리 7.7
「"netflix.com/tudum/top10?week=2024-11-03"」            노출 15 · 자리 6.7
```

⛔ **붙여넣은 주소**입니다. 수요가 아니고, 상대가 없어서 자리가 좋아 보이는 것입니다.
⭐ 자리만 보고 갈래를 고르면 이렇게 속습니다. **자리와 «검색어의 꼴»을 함께 봐야 합니다.**

### 3-2. 🔴🔴 그리고 두 축의 합계가 다릅니다 — 섞어 쓰면 수가 틀립니다

같은 사이트를 두 축으로 받아 합계를 대 봤습니다.

| 축 | 행 | 노출 | 클릭 | 클릭률 |
|---|---:|---:|---:|---:|
| `--축=page` (지면축) | 890 | **5,124** | **34** | 0.66% |
| 기본 (검색어×지면축) | 488 | 1,130 | 3 | 0.27% |

⇒ **검색어축이 노출의 78%, 클릭의 91% 를 안 보여 줍니다.** 구글이 «드문 검색어»를
개인정보로 감추기 때문입니다.

⛔ **오늘 저도 이 함정에 빠졌습니다.** 「붙여넣은 주소가 «우리 노출»의 33%」라고 적었는데,
바른 말은 **「검색어가 보이는 1,130노출의 33%」**입니다. 전체 5,124노출에 대한 몫이 아닙니다.

```
✅ 노출·클릭·클릭률의 «합계»는 반드시 --축=page 로 잰다
✅ 검색어축은 «무엇을 물어보나»(꼴·낱말)를 보는 데만 쓴다. 몫을 옮기지 않는다
⛔ 두 축의 창(날짜)도 다를 수 있다 — 파일 이름의 날을 함께 적는다
```

⭐ 이것을 `scripts/search-console-report.mjs` 머리글에 못박아 뒀습니다.

### 3-3. ⬜ 그래서 「클릭률이 낮다」의 «까닭»은 못 쟀습니다

지면축으로 자리 띠별 클릭률을 재 보니 이랬습니다.

```
자리 4~6    노출  438 · 클릭 4 · 0.91%
자리 7~10   노출 1485 · 클릭 9 · 0.61%
자리 11~15  노출  846 · 클릭 8 · 0.95%
자리 26~50  노출  601 · 클릭 2 · 0.33%
```

⭐ 자리와 거의 무관하게 평평합니다. 보통은 자리가 앞이면 클릭률이 크게 높습니다.
⬜ 그런데 **클릭이 통틀어 34건**입니다. 이 수로 「제목 탓」인지 「질의 탓」인지 가를 수 없습니다.
⛔ 그래서 까닭을 단정하지 않고 **다시 재는 날에 클릭이 더 모인 뒤에 봅니다.**

## Ⅳ. 그래서 정한 것

```
✅ 다음 장을 만들 때 «/title» 을 늘린다 — 실제 수요에서 8~11위다
   지금 나가는 /title 지면 560장 · 우리가 아는 한국 차트 작품 974편
   ⚠ 다만 주간자료 문턱을 넘는 것만 낸다(/titles 목록은 421편) — 문턱을 낮추지 않는다

⛔ «/person» 을 더 늘리지 않는다 — 635장이 노출 51을 낸다. 장을 더해도 8쪽에 쌓인다
   ⛔ 지우지도 않는다. 내부 링크와 구조화 데이터로 /title 을 받쳐 주는 몫이 있다
   ⭐ 다시 노릴 자리가 있다면 「movies」가 아니라 «우리만 세는 축»이다 —
      「어느 배우의 작품이 가장 많은 나라에 갔나」 같은 질의에는 인기 상대가 없다

⛔ «/market» 을 본보기로 삼지 않는다 — 좋은 자리가 붙여넣은 주소에서 온 것이다
```

### 4-1. 다시 재는 날

**2026-10-07** — 한 달 뒤에 같은 두 파일을 다시 받아 자리를 견준다.
⛔ 그 전에 「좋아졌다/나빠졌다」를 말하지 않는다. 한 달은 색인이 움직이는 데 걸리는 시간이다.

## Ⅴ. 다시 재는 법

```bash
node scripts/search-console-report.mjs sc-domain:kculturewire.com --days 28 --축=page --행수=1000
```

⛔ **주소 꼴(`https://www.kculturewire.com/`)로 부르면 안 된다.**
2026-09-09 에 내가 그렇게 불러 이 답을 받았다 —
`User does not have sufficient permission for site 'https://www.kculturewire.com/'`

한때 나는 그것을 「자를 고쳐야 한다」로 문서에 적었다. **자는 멀쩡했다.**
이 사이트는 **도메인 속성**(`sc-domain:kculturewire.com`)으로 등록돼 있고,
자는 그 꼴을 이미 받는다(`search-console-report.mjs` 40줄이 `sc-domain:` 을 검사한다).
**내가 부르는 법을 틀린 것이었다.**

⭐ 「막혔다」를 「자가 안 된다」로 읽지 않는다. **부르는 법을 먼저 본다.**

### 5-1. ⛔ 그리고 여기서 내가 «또» 재기 전에 적었다

나는 위에 「다른 세 사이트는 주소 꼴로 등록돼 있다 — 사이트마다 속성 꼴이 다르다」고 적었다.
**재 보니 틀렸다.** 셋을 다 불러 봤다.

```
주소 꼴                          도메인 꼴(sc-domain:)
https://seoulmarkets.com/   🔴   sc-domain:seoulmarkets.com   ✅
https://100yearmap.com/     🔴   sc-domain:100yearmap.com     ✅
https://www.kculturewire.com/ 🔴 sc-domain:kculturewire.com   ✅
```

⭐ **세 사이트 «모두» 도메인 속성이다.** 주소 꼴은 하나도 안 된다.
⛔ 그런데 자의 쓰는 법 예시가 주소 꼴로 적혀 있었다 —
   `node scripts/search-console-report.mjs https://seoulmarkets.com/ --days 28`
   ⇒ **그 예시를 그대로 따라 부른 유닛은 전부 「권한이 없다」를 받았을 것이다.**
   자를 고쳐 예시를 도메인 꼴로 바꿨다.
