## Ⅱ. 이 검사가 «보는 것» / «안 보는 것»

```
✅ 본다   밑감 파일이 있나 · 파싱되나 · 핵심칸 채움률 90% 이상인가 · 최신 날짜가
          «참는 날» 안에 있나(자료 안의 날짜칸을 직접 읽는다 — 라이브 서버에 curl 안 한다)
⛔ 안 본다  값 하나하나의 «정확성»(가령 삼성전자 인원수가 진짜 맞나) — 그건 그 밑감을
          만드는 수집기·빌더 자신의 자가시험 몫이다. 이 자는 «공급 사고»만 잡는다
⛔ 안 본다  시계열 «내부» 결손(예: 어느 하루가 통째로 빠짐) — 2026-09-17에 일곱 밑감을
          직접 열어 실측했다. 전부 «최신 스냅숏 한 장»(파일 안 날짜칸이 전부 같은 값)
          구조라, 애초에 안에서 빠질 «날짜 구간» 자체가 없다. 그래서 참는 날(최신성)
          검사 하나로 충분하다 — 더 손댈 필요가 없다는 뜻이지, 안 만들어서가 아니다
```

## Ⅲ. 날마다 / 손댈 때마다 하는 것

```bash
node scripts/check-f7-data-quality.mjs     # 맨몸으로 돌린다. 이것이 «실제 검사»다
npm test                                    # 전체 검사 — 이 자도 자동으로 같이 돈다
```

⛔ **`--자가시험`을 붙이면 다른 것을 돈다.** 그건 이 검사기 자기 로직(날짜 파서 등)이
  맞는지 스스로 확인하는 것이지, 실제 밑감을 보는 게 아니다. 5번이 2026-09-18 새벽
  klifemap에서 이 둘을 헷갈려 「11개가 깨졌다」고 잘못 보고할 뻔했다 — 인자를 안 줘서
  자가시험 전용 검사들이 «맨몸으로 돌면 당연히 실패하는 것」을 고장으로 오인한 것이다.
  **항상 `scripts/run-all-checks.mjs`에 적힌 그 줄 그대로 돌린다.**

이 검사 자체는 배포 스크립트가 아니다 — 로컬 JSON/JS 모듈을 읽기만 하는 순수 진단
스크립트라 열쇠·계정이 필요 없다. 밑감(F7 tape json 일곱 벌) 자체를 다시 만드는 것은
`build-korea-valuation-tape.mjs` 같은 별도 스크립트들이고, 그 수집 주기·API 열쇠는
`docs/6번-seoulmarkets-인수인계.md`에 있다.

## Ⅳ. 🔴 소급이 안 되는 자료 — 가장 중요

이 검사가 보는 일곱 밑감 **자체는** 위 Ⅱ절대로 "최신 스냅숏 한 장" 구조라 검사
설계상 소급 문제가 없다. **다만** 그 밑감을 만드는 원천 수집(6번→2번 인계 대상,
예: 증권사 직접 수집 18:40·KRX 일별 시세 등)이 그날 하루를 놓치면 애초에 그 스냅숏
자체가 못 만들어진다 — 이건 이 검사의 몫이 아니라 **`docs/6번-seoulmarkets-인수인계.md`의
「날마다 도는 것」 목록**에 있는 것이니 그 문서와 반드시 함께 본다.

## Ⅴ. 겪어서 아는 함정

```
① 밑감 꼴이 셋으로 갈린다 — ① 배열(행) 꼴(F2·F4·ownership·메자닌·사람)
   ② 사전(딕셔너리) 꼴(F3 계정사전 — {accountNames:{...}})
   ③ JS 모듈(자동생성) 꼴(무역 — src/lib/trade-data.mjs를 동적 import)
   새 F7 엔드포인트가 생기면 scripts/check-f7-data-quality.mjs 130번째 줄
   `밑감들` 배열에 맞는 꼴을 골라 등록해야 한다. 안 하면 「자를 만들었다」가
   「돈다」가 되지 않는다 — 감시에 안 올라간 자료는 조용히 사고가 나도 아무도 모른다

② 참는 날(freshness tolerance)을 함부로 좁히면 오탐이 뜬다 — 2026-09-18 새벽 5번이
   klifemap 국민연금 자료에 참는 날을 35일로 뒀다가 「108일 지남」 빨간불을 만났는데,
   실은 우리가 빠뜨린 게 아니라 출처 쪽이 공표를 석 달 늦게 낸 것이었다(120일로 고침).
   새 항목을 추가할 때는 그 자료의 실제 공표 주기를 먼저 재고 참는 날을 정한다

③ 겉보기엔 무관해 보이는 공용 검사에서도 회귀가 생길 수 있다 — 2026-09-17에
   check-korean.mjs의 「제N조」(법 조항) 오탐 정규식 버그를 npm test 전체를 돌려서
   찾았다. 이 검사 하나만 보지 말고 npm test 전체를 정기적으로 돌려 보는 습관이 중요하다
```
