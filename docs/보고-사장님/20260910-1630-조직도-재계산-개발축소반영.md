# Ⅱ. 개발이 끝나면 «무엇이 남나»

이것이 조직도의 실제 바탕입니다. 개발이 줄면 남는 일의 성격이 바뀝니다.

| 남는 일 | 성격 | 줄어드나 |
|---|---|---|
| 콘텐트 (텍스트 6 · 영상 1 · 카드 1 매일) | 매일 같은 양 | ⛔ 안 줄어듭니다 — 방문자 목표가 여기 걸려 있습니다 |
| 감수 (전 유닛 결과물, 라이브 전) | 남이 내는 만큼 | ⛔ 안 줄어듭니다 |
| 아카이빙 감시 (소급 불가 다섯 갈래) | 매일 | ⛔ 안 줄어듭니다 |
| 보고·소통 | 매일 | ⛔ 안 줄어듭니다 |
| 결제·배포 운영 | 사고 날 때만 | ✅ 줄어듭니다 |
| **개발** | 만들 것이 남은 만큼 | ✅ **줄어듭니다 — 10/14 뒤 크게** |

```
⭐ 그래서 사장님 판단이 맞습니다 — 10/14 뒤에는 우리 일의 성격이
   「만드는 조직」에서 「내는 조직」으로 바뀝니다
🔴 그런데 «내는 일»의 양은 자리 수에 정비례합니다. 자리를 줄이면 콘텐트가 그만큼 줄고,
   콘텐트가 줄면 9월 목표(유닛당 하루 1,000명)에서 멀어집니다.
   ⇒ 개발이 줄어드는 것이 «자리를 줄여도 된다»는 뜻은 아닙니다. 성격이 다릅니다
```

## 4-2. 월 결제라 사장님이 잃는 것이 없습니다

사장님이 「연간 결제는 아직 할 마음이 없어... 변화가 있을 수 있어서」라고 하셨습니다. 그 판단이 이 계획과 정확히 맞습니다 —

```
월 결제  언제든 바꿉니다. 10/14 에 내려도 되고, 9/20 에 내려 보고 안 되면 되돌려도 됩니다
연간     열두 달 묶입니다. 조직이 바뀌는 달에 묶는 것은 값이 아니라 «위험»입니다
⇒ 제가 오전에 「지금 연간으로 바꾸십시오」라고 드린 것은 조직 변경을 앞둔 시점을
  고려하지 않은 권고였습니다. 사장님 판단이 맞습니다
```

⚠ 못 잰 것 하나를 적습니다 — **자리마다 결제주기를 다르게 할 수 있는지**는 공식 지면에 없습니다. 「자리 종류를 섞을 수 있다」만 있습니다. 되면 나중에 스탠다드만 연간으로 묶는 길이 생기므로, 확인해서 따로 알려 드리겠습니다.

# Ⅴ. 9/20 조직 변경을 «어떤 문제도 없이» 하는 방법

사장님 지시: 「**조직 변경할 때 철저하고 꼼꼼하게 해서 어떤 문제도 생기지 않도록 잘 계획해서 해**」

오늘 그 지시가 왜 나왔는지를 제가 실물로 보여 드렸습니다. 16시 보고를 **제 자리로 옮기고** 그것을 **보는 자를 안 고쳐서**, 15:54에 보낸 보고가 16:05에 「안 보냈다」로 사장님께 갔습니다. 사장님이 그것을 1번·4번의 태만으로 읽으셨습니다. **실제 지연보다 이 헛울음이 더 나빴습니다.**

9/20에는 같은 일이 훨씬 크게 일어날 수 있습니다. 2번·4번이 없어지면 —

| 남아서 없는 사람을 부르는 것 | 지금 몇 개인지 |
|---|---|
| 예약(OS 작업 · cron) | ⬜ 세야 합니다 |
| 검사·자물쇠가 그 유닛을 기다리는 자리 | ⬜ 세야 합니다 |
| 기록 파일(그 유닛만 적던 것) | ⬜ 세야 합니다 |
| 다른 유닛 문서가 「2번에게 물어라」로 적어 둔 자리 | ⬜ 세야 합니다 |
| 계획서에서 그 유닛이 담당인 단계 | F7 API 가 확인됨 |

## 5-1. 그래서 이 순서로 합니다

```
1  9/13 까지   「없어지는 유닛을 부르는 자리」를 세는 자를 만듭니다.
              저장소 전체에서 2번·4번을 부르는 예약·검사·기록·문서를 찾아 목록으로 냅니다
2  9/13~9/18   그 목록을 0 으로 만듭니다. 담당을 남는 넷에게 옮겨 적습니다
3  9/19        4번의 일을 1번 자리로 다시 합칩니다(오늘 한 번 했고 그날 «늘어난 것»만 다시)
              세션 예약을 다시 걸고, 기억이 «열리는지» 눈으로 봅니다
4  9/19 밤     그 자를 다시 돌려 «0 인지» 확인합니다. 0 이 아니면 삭제를 미룹니다
5  9/20        2번·4번 세션 삭제. 되돌릴 자리(백업)는 «일주일» 둡니다
```

⛔ **「옮겼다」로 끝내지 않습니다.** 옮긴 뒤 그 일을 감시하던 자를 하나씩 돌려 초록불을 눈으로 본 다음에 끝났다고 하겠습니다. 사장님 기준은 「파일이 갔다」가 아니라 「퍼포먼스가 유지되거나 더 좋아진다」이십니다.
