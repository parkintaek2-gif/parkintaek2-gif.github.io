# 1. 전략 여덟

## Ⅰ. 파는 것은 **조인**이다

원자료는 공짜다. 모아 둔 것 자체는 누구나 하고 **팔리지 않는다.** 값은 붙일 때 생긴다.

```
경쟁사   재무 × 기업        이미 다 한다
우리     **사람 × 주가**     아무도 안 한다
```

증명됐다 — 2,552곳을 붙여 **「여성이 많은 회사가 나빴다」가 업종 착시**임을 보였다.
**조인 없이는 존재할 수 없는 기사다.**

> 새 데이터를 받을 때 **「무엇과 붙일 수 있나」를 먼저 적는다.**
> 붙일 데가 없으면 수집 순위를 내린다. **안 붙는 데이터는 창고 비용이다.**

## Ⅱ. 우리가 파는 건 숫자가 아니라 **「믿을 수 있는 숫자」**다 (3번)

```
공짜 원자료 → 가공 → 우리 지면              여기까지는 누구나 흉내 낸다
공짜 원자료 → 가공 → **어떻게 쟀는지 함께**   여기부터가 우리 것이다
```

**B2B 가 돈을 내는 이유는 숫자가 없어서가 아니라 틀릴까 봐다.**
그래서 **검증은 원가가 아니라 상품 사양**이다. (→ 6장)

## Ⅲ. ⭐ 지면을 내면 **그 표도 같이 낸다** — 추가 비용 0의 재고 (3번)

**B2B 는 지면을 안 산다. 표를 산다.** 그런데 그 표를 우리는 이미 갖고 있고 안 내놓고 있을 뿐이다.

```
지금    빌드 → 지면만
바꾸면  빌드 → 지면 + **CSV·JSON**     (코드 몇 줄)
```

> **모든 사이트 규칙 — 지면을 내면 원본 표도 같이 낸다.**
> 무료/유료 경계는 나중에 그어도 된다. **재고부터 쌓인다.**

## Ⅳ. **결정론이 해자**다

경쟁자가 LLM 하나로 만들면 같은 질문에 매번 다르게 답한다. 그건 상품이 못 된다.

```
판정  규칙 엔진   같은 입력 → **언제나 같은 결과**
설명  LLM        판정을 바꾸지 않는다
검증  **독립**    판정에 없는 말을 하면 잡는다
```

붙여 놓으면 하루면 흉내 내지만 **나눠 놓으면 엔진을 만들어야** 따라온다.
「LLM 이 더 잘하니까」로 판정을 넘기는 순간 **해자가 사라진다.**

⭐ **그리고 이게 곧 매출이 된다** (1번) — 대운·세운은 시간이 지나면 바뀐다.
**「작년 감정서가 올해 어떻게 달라졌는지」**를 보낼 수 있다. 재구매가 아니라 **갱신**이고 구독의 근거다.
판정이 흔들리는 곳은 이걸 하면 「작년과 말이 다르다」가 되어 신뢰를 깎는다.
우리는 **왜 달라졌는지 정확히 말할 수 있다.**

## Ⅴ. **엔진이 글감을 낳는다** (1번)

```
택일 엔진 × (목적 5 × 월 12)   = 60편, 매년 새로
사주 엔진 × (일간 10 × 격국 10) = 100편
일진 엔진 × 365일              = 매일 자동
```

**AI 가 글을 지어내지 않는다.** 날짜·판정은 엔진 실계산값이고 AI 는 문장만 쓴다.
사실 오류가 원천 차단되고 **날짜가 지나면 자동으로 새 글감**이 생긴다 — 마르지 않는다.

## Ⅵ. 사람을 안 거치는 것이 **비용 우위**다

한계비용이 0 에 가까우니 **경쟁사가 안 쓰는 주제**를 쓸 수 있고, 그게 쌓이면
**검색에서 우리만 있는 자리**가 된다.

⭐ 다음 걸음 (1번) — 자동화를 **「사람이 볼 것을 줄이는」** 쪽으로 설계한다.

```
지금    33종을 뽑고 → 내가 다 본다        사람 시간이 **종수**에 비례
앞으로  33종을 뽑고 → **달라진 곳만** 본다  사람 시간이 **변화량**에 비례
```

**24시간 작업의 진짜 지렛대는 오래 일하는 게 아니라 볼 것을 줄이는 것이다.**

## Ⅶ. 무료 발행은 **카탈로그**다

유일한 마케팅이 검색과 **우리 사이트끼리의 유입**이다.
**기사를 낼 때 그것이 어떤 상품을 가리키는지 정하고 쓴다.** 안 정하면 트래픽만 남는다.

## Ⅷ. ⭐ **「물건이 없다」와 「살 사람이 없다」를 구분한다**

```
① 물건 됐고 팔 수 있다        KLifeMap 리포트 — **PG 만 풀리면 된다**
② 물건은 됐는데 살 사람이 없다   SeoulMarkets 데이터 — **명단·아웃리치가 없다**
③ 트래픽이 먼저다             백년지도 무료도구 → 결제
④ 아직 물건이 아니다          WikiTip
```

**②는 더 만들 게 아니라 팔러 가야 한다.** 데이터를 더 모아도 매출은 안 생긴다.
지금 SeoulMarkets 가 ②인데 ①처럼 일하고 있다 — **제일 큰 낭비다.**

⚠ **못 잰 것** — 우리는 **유입 수치를 한 번도 안 봤다.** 어느 기사가 무엇을 데려오는지 모른다.
**모르면 자원을 어디에 몰지 못 정한다.**

# 3. 병렬형 구조 — Ⅳ를 어떻게 만드나

> **읽기·조사·검증은 여럿이 동시에. 고치는 책임은 하나.**

```
① 애널리스트    신호를 만든다              ← 조사 (병렬)
② 펀드매니저    포지션을 정한다             ← 제작 (편집 책임 하나)
③ 리스크관리자   한도를 감시하고 멈춘다 **독립** ← 검증 (병렬)
```

상담 AI 도 같다 — `판정(엔진) / 설명(LLM) / 검증(독립)`.
리포트도 같다 — `사실 확인(병렬) → 초안(하나) → 대조·렌더(병렬)`.

⭐ **이 구조가 실제로 결함을 잡았다** (1번) — 상담 AI 가 엔진에 없는 판단을 말했고
**검증 AI 가 「그 판단은 엔진이 준 것이 아니다」**라고 잡았다. 원인은 데이터 파이프라인이었다.
**셋이 붙어 있었으면 아무도 못 잡았다.**

## 3-1. ⚠ 병렬의 대가는 **합류**다 (3번)

```
⛔ 나눠 놓고 합치는 건 나중에   →  전부 한 명에게 쌓이고 그만큼 출시가 밀린다
✅ **나눌 때 누가 언제 합치는지를 같이 정한다**
```

# 4. 협업

| | 규칙 |
|---|---|
| **편집 책임** | 파일마다 주인이 하나. 남의 파일은 **고치기 전에 말하고** 결과를 보고 |
| **급하면** | 고치되 메모에 남긴다. ⛔ **단 상대가 지금 작업 중인 파일은 급해도 손대지 않는다** |
| **커밋** | `git add -A` 금지. **경로를 지정한다** — 저장소를 나눠 쓴다 |
| **원인을 넘길 때** | ⭐ **무엇으로 쟀는지를 같이 적는다.** 틀린 진단을 넘기면 **두 배가 된다** |
| **창구** | **세션↔세션은 `docs/세션간-메모.md` 하나.** 사장님→세션은 폴더도 쓴다 |
| **교차 감사** | 오픈 전 1회 · 이후 주 1회. **숫자만 넘긴다.** ⛔ 고치지 않는다 ⛔ 판단하지 않는다 |

## 4-1. 승인 요청 ≠ 범위 축소 (3번)

```
✅ 실행은 묻지 않는다
⛔ **범위는 줄이지도 바꾸지도 않는다.** 사실이 지시와 어긋나 보이면
   **사실만 한 줄로 말씀드리고 물건은 그대로 만든다**
⛔ **한 지시를 끝내고 다음 일로 간다**
```

## 4-2. 규칙은 파일에 — ⚠ **남겼다고 걸리는 게 아니다** (1번)

부품을 만들어도 이름이 갈리면 안 걸리고, 프롬프트가 두 갈래면 절반만 반영된다.
→ **「부품을 실제로 쓰는가」를 기계로 센다.** 「공통이니까 다 바뀌었겠지」가 제일 위험하다.

⚠ **쓰이지 않는 도구는 없는 도구다** (3번: `npm run inbox` 를 한 번도 안 썼다).

· 다시 계산할 때 **「없어진 값」 카운터**             (42건이 조용히 사라질 뻔했다)

# 6. 검증 = **상품 사양서** (전략 Ⅱ)

이 장은 품질 관리가 아니다. **B2B 가 돈을 내는 이유**를 만드는 곳이다.

```
분모를 같이 적는다        비율만 적으면 독자가 틀리게 읽는다. **그러면 우리가 거짓말한 것이다**
출처·기준시각을 붙인다     못 쟀으면 「못 쟀다」
우리 계산은 그렇게 밝힌다   공식값이 있으면 공식값을 쓴다
안 다룬 것을 적는다       (excluded)
```

## 6-1. ⚠ 「했다」가 아니라 「봤다」, 그다음 **「엉뚱한 걸 봤을 수 있다」**

```
· **검사도 틀린다.** 일부러 틀린 값을 넣어 **실제로 실패하는지** 본다
· **도구가 입력을 바꾼다.** 남의 진단을 검증할 때 **그 사람이 쓴 도구를 쓰면 검증이 아니다**
· **넘겨받은 좌표도 내 환경에서 다시 맞춘다.** 「믿어도 된다」는 남의 판단이다
· 고객에게 나가는 **인용은 원본과 직접 대조**한다. 도구의 통과는 「봤다」가 아니다
· 실제 저장 경로를 안 거친 테스트는 **없는 것보다 나쁘다**
· **공개한 명세는 약속이다.** 지표를 올리려고 조용히 바꾸지 않는다
```

## 6-2. ⭐ 품질을 **사람이 아니라 검사에** 둔다 (3번) — 확장의 조건

```
문장으로 적은 기준 → 지침    안 걸린다
검사로 적은 기준   → 규칙    **배포가 강제한다**
```

`npm test` 에 **지면 완료 검사**를 넣는다 — 200 인가 · 본문=표인가 · 인쇄 대비 4.5인가 ·
비율에 분모가 있는가. **한 번 짜면 사이트가 열 개가 돼도 같은 비용이다.**

## 6-3. 권한은 좁게

```
⛔ .env 읽기 · rm -rf · git push --force   ⛔ ctype 에 `-t` 없으면 훅이 막는다
⛔ 저장소가 공개다. **키 값을 커밋하지 않는다**
```

# 7. 디자인 = **전달률** — 감각을 파일에 둔다

유료 전환은 엔진이 아니라 **첫 화면**에서 갈린다.

## 7-1. 감각은 **틀린 걸 알아보는 눈**이고, 그건 잴 수 있다

```
만든다 → 렌더한다 → **잰다** → 그다음 고친다
```

⚠ 눈대중은 **반대로** 판단한다. 실제로 셋 다 그랬다
(제목이 첫 화면의 56% · 표 스타일이 통째로 죽음 · 「본문이 넓다」는 오진).

## 7-2. ⭐ `DESIGN.md` — **디자인용 CLAUDE.md** (1번·3번 독립 제안)

```
DESIGN.md        분위기 · 색 · **활자 단** · 표/카드 규칙 · 여백 단위 · 인쇄 규칙
npm run design   그 규칙을 실제 지면에 대고 잰다
```

효과 둘 — ① 「예쁘게 해줘」를 매번 설명하지 않는다
② **새로 만든 화면이 자동으로 같은 옷을 입는다** (지면 377장이 빈손으로 나간 적이 있다)

## 7-3. ⭐ 따로 같은 답이 나왔다 — **그건 취향이 아니라 원칙이다**

1번과 3번이 서로 모르고 같은 결론에 닿았다.

> **「단은 넷. 본문과 표는 같은 크기. 비율은 매체가 정한다.」**
> (종이 1.28배 · 화면 1.5~1.9배 · 예: `제목 19 > 부제1 15 > 부제2 13 > 본문=표 11.5`)

**표만 작게 하면 표가 부록처럼 보인다.** 우리는 데이터를 파는 회사다.

## 7-4. 매번 재는 여덟

```
첫 화면 · 글줄(60~75자) · **활자 종류 수** · 모바일(360px 먼저) ·
다크모드 · **인쇄(PDF 로 뽑는다)** · **같은 옷을 입었나** · 무게
```

⚠ **인쇄는 화면으로 원리적으로 못 잡는다** — 배경색 막대가 통째로 사라지고,
금색이 종이에서 대비 2.1 이 되고, 화면 폭 규칙이 종이에서 꺼진다.

## 7-5. 트렌드는 베끼지 말고 **원칙으로 옮긴다**

```
⛔ 「요즘 이게 유행」  → 다음 유행이 오면 다시 만든다
✅ 「왜 좋아 보이나」  → **여백·대비·정렬·서열.** 안 바뀐다
```

크기만으로 세운 위계는 **흑백 인쇄에서 약하다** — 제목에 **명조**를 주면 층이 산다.
**브랜드는 글자만으로도 세울 수 있다** — 이미지가 안 뜨는 자리를 위해.

# 8. 한 장으로

## 전략

```
Ⅰ  파는 것은 **조인**이다. 안 붙는 데이터는 창고 비용
Ⅱ  파는 건 숫자가 아니라 **믿을 수 있는 숫자**. 검증은 원가가 아니라 **사양**
Ⅲ  **지면을 내면 표도 같이 낸다.** 추가 비용 0의 재고
Ⅳ  **결정론이 해자**다. 판정을 LLM 에 넘기면 해자가 사라진다 → **갱신·구독**으로 이어진다
Ⅴ  **엔진이 글감을 낳는다.** 마르지 않는다
Ⅵ  사람을 안 거치는 **비용 우위**. 다음은 **사람이 볼 것을 줄이는** 자동화
Ⅶ  무료 발행은 **카탈로그**. 기사가 **무엇을 가리키는지** 정하고 쓴다
Ⅷ  **「물건이 없다」와 「살 사람이 없다」를 구분한다.** 제일 부족한 건 **첫 결제**
```

## 방법

```
①  나눌 수 있는 일은 나란히. **고치는 사람은 하나.** 나눌 때 **합칠 사람도 정한다**
②  검증하는 쪽은 만드는 쪽과 **독립**
③  시작 전에 **「끝」의 정의**를 적는다. 배포가 아니라 200 이고 눈으로 본 것
④  규칙은 **파일**에 남기고 **실제로 걸렸는지 기계로 센다**
⑤  2번째면 스크립트, 3번째면 예약. **예약 전에 정상 3건·예외 1건**
⑥  자동화에는 **안전장치를 함께.** 그 안전장치도 **일부러 틀리게 해서** 확인한다
⑦  **검사도 틀린다.** 내가 쟀다는 게 근거가 아니라 **무엇으로 쟀는지**가 근거다
⑧  고치는 것보다 **못 만들게 하는 것**이 오래 간다
⑨  모든 비율에 **분모**를 적는다
⑩  디자인은 `DESIGN.md` 에 둔다. **렌더하고 재고 하나씩.** 인쇄는 **반드시 PDF 로**
```
