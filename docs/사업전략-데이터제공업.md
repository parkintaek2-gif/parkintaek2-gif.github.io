## 0. 전제 — 오늘 확인한 사실에서 출발한다

**원천 데이터는 이미 공짜다.**

| 분야 | 출처 | 라이선스 | 비용 |
|---|---|---|---|
| 주식·지수·채권·파생·상품 | 금융위 8종 | 제한 없음 | 0원 |
| 공시 32종·재무제표 | 금융위·금감원 | 제한 없음 | 0원 |
| 환율 | 수출입은행 | 제한 없음 | 0원 |
| 거시 | 한국은행 | 제한 없음 | 0원 |
| **부동산 실거래 전건** | 국토부 4종 | 제한 없음 | 0원 |
| **부동산 지수** | 한국부동산원 | 제한 없음 | 0원 |

그런데도 FnGuide 는 돈을 받고 판다. **그 차이가 사업 기회다.**

**FnGuide 가 파는 것은 데이터가 아니라 네 가지다.**

1. **20년치 정규화된 시계열** — 공공 API 는 조회 기간이 제한되고, 과거를 소급해 살 수 없다
2. **컨센서스** — 증권사 리포트를 20년간 모아 만든 것. 공공데이터에 없다
3. **표준화** — 계정과목·기업코드·업종분류를 통일한 것. 원천은 제각각이다
4. **신뢰와 관계** — 기관이 "FnGuide 숫자"를 기준으로 삼는 관성

이 중 **1·3 은 지금부터 만들 수 있고, 2 는 진입장벽이 높으며, 4 는 시간이 필요하다.**

## 1. 우리가 이길 수 있는 지점 — 네 가지

### ① 영문화 — 가장 큰 빈칸

한국 공공데이터는 **전부 한국어다.** 법정동코드, 계정과목명, 공시 유형명, 업종분류
모두 한글이다. 외국 기관이 쓰려면 사람이 번역해야 한다.

Bloomberg·Refinitiv 는 한국 대형주는 커버하지만 **중소형주, 부동산 실거래, 공시 세부,
사모펀드 통계는 얇다.** 한국 특유의 데이터일수록 비어 있다.

**이미 우리 것이다.** SeoulMarkets 가 영문 매체다. 데이터 정규화도 영문 기준으로 하면
미디어와 데이터가 같은 자산을 쓴다.

### ② 금융 × 부동산 결합 — 아무도 안 하는 것

FnGuide 는 금융, 부동산원·KB 는 부동산이다. **둘을 잇는 곳이 없다.**

그런데 실제 인과는 이어져 있다.

```
기준금리 → 대출금리 → 거래량 → 실거래가 → 건설사 실적 → 회사채 스프레드
                                    ↘ 가계부채 → 소비 → 내수주
```

한 화면에서 이 사슬을 보여주는 데이터셋은 국내에 없다.
**우리는 양쪽 원천을 「제한 없음」으로 이미 확보했다.**

### ③ 개발자 친화 — 공공 API 는 쓰기 나쁘다

공공데이터포털 API 의 실제 문제:
XML 기본 · 인증키 URL 인코딩 이슈 · 데이터셋마다 응답 구조가 다름 ·
법정동코드를 따로 구해야 함 · 페이지네이션 제각각 · 문서가 부실함 ·
**T+1 인데 화면에는 "실시간"이라 적혀 있음**

한국판 Alpha Vantage / Polygon 이 없다. **깨끗한 JSON REST 하나가 곧 제품이다.**

### ④ 아카이브 — 지금 시작해야 하는 유일한 것

**공공 API 는 과거를 소급해 주지 않는다.** 조회 기간이 제한된 데이터셋이 많고,
개편되면 옛 형식이 사라진다.

FnGuide 의 진짜 해자가 이것이다. 20년치는 돈으로 못 산다.

> **가장 시급한 실행 항목은 이것이다. 오늘부터 매일 수집해 저장한다.**
> 기사를 안 쓰는 날에도 데이터는 받는다. 1년 뒤 이 아카이브가 자산이 된다.

## 2. 우리가 못 이기는 지점 — 정직하게

| 영역 | 이유 | 대응 |
|---|---|---|
| **실시간 시세** | KRX 유료 라이선스. 재배포 불가 | 하지 않는다. T+1 로 승부 |
| **컨센서스·목표주가** | 증권사 리포트 수집 필요. 관계·비용·저작권 | 3단계 이후 판단 |
| **기관 영업** | 자산운용사·연기금 구매는 관계 기반 | 개발자·해외 먼저 |
| **예탁결제원 데이터** | 상업적 이용금지 정황 | 확인 전 사용 금지 |

**실시간을 포기하는 것이 전략이다.** 실시간은 거래 목적이고, 거래 목적 데이터는
정확성 책임(SLA·배상)이 따라온다. 우리는 **분석·리서치·연구 목적**으로 간다.

## 3. 제품 계층 — 4단

```
L0  미디어 (SeoulMarkets)          무료      신뢰·유입·SEO·브랜드
     ↓ 같은 데이터 파이프라인을 공유
L1  데이터 API                     종량제    개발자·핀테크·퀀트·학계
     ↓
L2  대시보드/터미널                 구독      리서치·중소 운용사·언론
     ↓
L3  커스텀·벌크·라이선스            계약      기관·해외 벤더
```

**미디어가 마케팅이다.** 기사마다 "이 숫자는 우리 API 에서 나왔다"가 붙는다.
FnGuide 는 미디어가 없어서 개발자에게 알려지지 않았다. 우리는 반대로 간다.

### L1 데이터 API — 첫 유료 제품

**엔드포인트 설계 원칙**
- JSON only. XML 안 준다
- 종목코드·법정동코드를 사람이 안 찾아도 되게 — 이름으로 조회 가능
- **모든 응답에 `as_of` 와 `source` 를 넣는다.** 미디어에서 하던 것과 같은 원칙
- 무료 티어를 넉넉히 — 개발자가 써보고 결정하게

**초기 셋**
```
/v1/equities/{code}/prices        일별 시세 (T+1)
/v1/disclosures?since=            공시 스트림
/v1/financials/{code}             재무제표 (표준화)
/v1/fx/krw                        환율
/v1/rates/curve                   국고채 커브
/v1/funds/{code}/returns          펀드 수익률·보수
/v1/housing/transactions?region=  실거래 (국토부)
/v1/housing/index?region=         지수 (부동산원)
```

마지막 두 개가 차별점이다. **금융 API 와 부동산 API 가 같은 스키마·같은 인증으로
나오는 곳은 없다.**

## 4. 단계별 실행

### 1단계 (0~6개월) — 파이프라인과 아카이브

- [ ] **수집기 구축.** 매일 전 데이터셋을 받아 원본 그대로 저장(raw) + 정규화(clean)
- [ ] **아카이브 시작.** 이게 최우선. 하루 늦으면 하루치를 영영 못 얻는다
- [ ] 미디어(L0) 발행 계속 — 신뢰 축적
- [ ] 영문 정규화 사전 구축: 계정과목·업종·공시유형·법정동
- 비용: 스토리지 정도. 원천이 공짜다

### 2단계 (6~12개월) — API 공개

- [ ] 무료 티어로 공개. 개발자 확보가 목적
- [ ] 문서·SDK. 한국 데이터인데 **문서는 영문**
- [ ] 미디어 기사에 API 링크 삽입 — 자연 유입
- [ ] 유료 티어 도입 (종량제)
- 이 시점에 **1년치 아카이브**가 무기가 된다. 공공 API 로는 못 얻는 구간

### 3단계 (12~24개월) — 대시보드·기관

- [ ] 금융×부동산 결합 대시보드
- [ ] 해외 기관 대상 영업 (한국 익스포저 있는 곳)
- [ ] 컨센서스 진입 여부 판단 — 그때 리포트 수집 라이선스 검토

### 4단계 — 라이선스·B2B

- 벌크 다운로드, 커스텀 지표, 화이트라벨

## 5. 반드시 먼저 확인할 것 — 법적 관문

**⚠ 이게 사업 성립 여부를 가른다. 코드보다 먼저 확인한다.**

「이용허락범위 제한 없음」은 **재배포**를 허용한다. 그런데 **가공물을 유료로 되파는 것**이
같은 범위인지는 별개 문제다. 공공데이터법상 원칙은 영리 이용 허용이지만,
데이터셋별 표기와 실제 운영이 다를 수 있다.

- [ ] 공공데이터 유료 재판매 가능 여부 — 행안부·해당 기관에 서면 질의
- [ ] 활용사례 등록 시 상업적 서비스로 신고해야 하는지
- [ ] 트래픽 한도 — 운영계정 증액 상한
- [ ] 데이터 정확성 면책 조항 설계 (B2B 는 배상책임이 따라온다)
- [ ] `제한 없음` 이 아닌 데이터셋을 파이프라인에서 물리적으로 차단

**미확인 상태로 유료화하지 않는다.** 미디어(무료)는 지금도 문제없지만,
유료 API 는 성격이 다르다.

## 6. 수익 구조 (가설 — 미검증)

| 티어 | 대상 | 가격 가설 |
|---|---|---|
| Free | 개발자·학생 | 월 1만 콜 |
| Dev | 개인·소규모 | 월 3~5만원 |
| Business | 핀테크·리서치 | 월 30~100만원 |
| Enterprise | 기관·해외 | 연 계약 |

**국내 기관 데이터 시장은 작고 관계 중심이다.** 대신 **영문·해외向이 TAM 이 크다.**
한국 익스포저를 가진 해외 헤지펀드·자산운용사·리서치가 1차 타깃이다.

⚠ 위 가격은 **가설이다.** 경쟁사 실제 가격을 확인하지 않았다.

## 7. 지금 당장 할 일 — 하나

**수집기를 만들고 아카이브를 시작한다.**

다른 건 다 나중에 해도 된다. 아카이브만은 아니다. 오늘 안 받은 데이터는
1년 뒤에 돈을 줘도 못 산다. **API 키가 열리는 즉시 이것부터 돌린다.**

미디어는 계속 돌리되, 그 자체가 목적이 아니라 **데이터 파이프라인의 첫 소비자**로
본다. 기사를 만들면서 파이프라인이 검증되고, 파이프라인이 제품이 된다.
