일부러 망가뜨려 보지 않았으면 둘 다 「통과」로 넘어갔다.

```
① EADDRINUSE 를 무시하게 적었다 → 포트가 쓰이면 **앞서 떠 있던 고쳐진 서버**를 쟀다
② fetch 가 Host 헤더를 무시했다  ← 진짜 원인
   curl -H "Host: 100yearmap.com" → 404 (재현)
   fetch({headers:{Host}})        → 200 (헤더가 안 먹었다)
   undici 가 Host 를 덮어쓴다. 이 시험의 전부가 호스트 분기인데 **호스트를 못 보냈다**
```

어제 「셸이 한글을 CP949 로 바꾼다」와 **같은 종류다.**
**도구가 입력을 바꾸면, 없는 병을 고치거나 있는 병을 못 본다.** 「일하는 법」 6-1 에 적었다.

## Ⅶ. (08:5x~09:1x) 이직률을 상품화하려다 **못 한다고 결론냈다**

국민연금 가입자수를 상장사에 붙이는 방법을 세 가지로 재 봤다.

```
① 사업장명으로만          2,451개사 붙음 · 그러나 **본사 한 곳만** 잡힌다
                          성우하이텍 DART 1,782명 → 연금 20명 (지점이 다른 이름이라)
② 사업자번호 앞6으로만     비 중앙값 **×10.18** — 남의 회사가 딸려 온다
                          효성중공업 앞6에 「(유)온누리토목」·「(주)린인바이오」가 섞인다
③ **앞6 + 이름이 회사명으로 시작**  비 중앙값 **0.955** · ±5% 안에 36.2% · 0.8~1.05 에 65%
```

③ 이 제일 낫지만 **아직 못 판다.**

```
기아      DART 36,566 · 연금  9,350  ×0.26   (사업장 3개만 잡힘)
롯데쇼핑   DART 17,712 · 연금  4,697  ×0.27
삼성전기   DART 24,346 · 연금 12,528  ×0.51
```

**오차가 한 방향(과소)이라 「지점을 못 찾은 것」과 「진짜 작은 것」이 구분되지 않는다.**
이 상태로 이직률 순위를 내면 다지점 회사가 통째로 틀린다.

### 7-1. 왜 이렇게 됐나 — **열쇠가 잘려 있다**

포털 파일의 사업자등록번호가 **앞 6자리**뿐이다. 사업장관리번호도 없다.
10자리가 있으면 한 법인의 지점이 전부 정확히 묶인다. **없는 열쇠는 만들 수 없다.**

### 7-2. 그래서 무엇을 하나

```
✅ 달치 아카이빙은 계속한다 (workplaces-YYYYMM.csv) — 소급이 안 되니 지금 쌓아야 한다
⬜ 조인 개선: 주소(법정동코드)로 지점을 더 붙일 수 있는지 본다
⬜ 어차피 **한 달치로는 이직률이라고 못 부른다.** 몇 달 쌓고 다시 본다
```

「검증 안 된 건 안 쓴다」 — 재 보고 **안 된다고 적는 것도 결과**다.
