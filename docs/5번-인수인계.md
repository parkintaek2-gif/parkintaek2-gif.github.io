# 5번 인수인계 — 예전 창 → 팀 자리 창

사장님 지시(2026-08-21 17:5x): 「팀에 있는 5번이 있어야 한다.
**예전 5번에게 인수인계 받고 예전 5번을 지워라**」

⭐ 인수인계는 폴더 복사가 아니라 **이 문서**다. 대화록은 지워질 수 있고 git 은 안 지워진다.
   새 창은 이 문서만 읽으면 바로 이어서 일한다.

---

## Ⅰ. 실측 — 어느 파일이 살아 있나 (2026-08-21 17:5x)

```

   112,180,356 바이트 · 17:51 · 14:1x 에서 멈춤                          ← 껍데기
.claude-u5/projects/C--Users-USER-Desktop-00-----/7cb66053-….jsonl
   112,180,356 바이트 · 14:26 · 같음                                     ← 껍데기
```

🔴 `CLAUDE_CONFIG_DIR` 은 `.claude-u5` 인데 **기록은 `.claude` 로 간다.**
   그래서 「팀 자리로 옮겼다」는 절반만 참이었다 — 설정은 옮겨졌고 **기록은 안 옮겨졌다.**
   ⛔ 이 상태에서 예전 것을 지우면 **도는 대화가 날아간다.** 순서를 갈라야 한다.

## Ⅱ. 지우는 순서 (이대로만)

```
① 이 문서를 커밋한다                       ← 인수인계 내용을 git 에 남긴다
② 살아 있는 대화록을 팀 폴더로 덮는다        ← 새 창이 옛 대화를 이어 볼 수 있게
③ **예전 창을 닫는다**                     ← 도는 프로세스가 그 파일을 쥐고 있다
④ 그다음에 예전 폴더의 5번 파일을 지운다     ← ③ 없이 ④ 하면 대화가 깨진다
```
⛔ ④ 를 ③ 앞에 하지 않는다. 파일을 쥔 프로세스가 있는 채로 지우면 기록이 반쪽이 된다.

```
⛔ 열쇠는 **배포 직전에** 받는다. 커밋이 바뀌면 죽는다
⛔ 남의 것을 「틀렸다」고 하기 전에 **내 자부터 의심한다** — 오늘 헛경보 여섯이 다 내 검사 탓이었다
⛔ 금칙어·이름 검사는 **주장하는 자리만** 본다. 안 그러면 자기 문장에 자기가 걸린다
⛔ 5번 창이 여럿이면 같은 dist·같은 관문에서 부딪힌다. 빌드가 죽으면 남의 동시 빌드를 먼저 의심한다
```
