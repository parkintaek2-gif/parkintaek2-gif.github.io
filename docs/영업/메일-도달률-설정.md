# 메일 도달률 — 지금 보내면 스팸함으로 갑니다

작성 2026-08-01 · 근거: 2026년 구글·야후·마이크로소프트 발신자 규칙
관련: `타깃과-아웃리치.md` (제안서·아웃리치 문안은 다 써 뒀다)

---

## 0. 문제 — 영업 자산은 만들었는데 배달 경로가 막혀 있다

영문 제안서·아웃리치 문안·타깃 리스트를 만들어 뒀다. 그런데 **보낼 수가 없다.**

```
_dmarc.seoulmarkets.com    레코드 없음
_dmarc.wiki-tip.com        레코드 없음
SPF (v=spf1 …)             둘 다 없음
```

**인증이 없는 도메인에서 온 메일은 열어보기 전에 걸러진다.**
콜드메일의 약 17%가 도메인 인증 미비로 수신함에 못 들어간다는 조사가 있다.
우리처럼 **아무도 모르는 신생 도메인**은 그보다 훨씬 나쁘다.

---

## 1. 2026년 기준 — 무엇이 바뀌었나

| 수신처 | 문턱 | 요구 |
|---|---|---|
| Google (Gmail) | 하루 **5,000통** 이상 | SPF + DKIM + DMARC **전부 정렬** |
| **Microsoft** (Outlook·Hotmail·M365) | 하루 **1,000통** 이상 | **DMARC 정렬 필수** — 2025년 5월부터 |
| Yahoo | 대량 발신 | 위와 같음 |
| 공통 | — | 스팸신고 **0.3% 미만** · 반송 **2% 미만** |

**마이크로소프트 문턱이 더 낮다(1,000통).** 그리고 우리 타깃인 해외 기관·대학은
M365 를 쓰는 곳이 대단히 많다. **우리에게 제일 중요한 수신처가 제일 까다롭다.**

> 우리는 대량 발신을 하지 않는다(하루 몇 통이다). 그래도 **인증이 없으면
> 소량 발신도 신뢰 점수가 바닥이라 스팸으로 간다.** 문턱은 「이하면 안 봐준다」가
> 아니라 「이상이면 강제한다」는 뜻이다.

## 2. 넣어야 할 DNS 레코드

⚠ **아래는 발신 경로에 따라 값이 달라진다.** 지금 우리는 `sibcheongan@gmail.com`
(구글 개인계정)으로 받고 있고, **도메인 메일 발신 경로가 아직 없다.**
그러므로 순서가 있다.

### 1단계 — 발신 경로부터 정한다

| 방법 | 비용 | 적합도 |
|---|---|---|
| **Google Workspace** | 유료 | 이미 구글을 쓰고, 설정이 표준적이다. **권장** |
| Zoho Mail | 무료 티어 있음 | 소규모에 흔히 쓴다 |
| 발신 전용(Resend·Postmark 등) | 종량 | 자동 발송용. 사람이 쓰는 메일함이 아니다 |

**정하기 전에는 SPF 를 쓸 수 없다.** SPF 는 「누가 이 도메인 이름으로 보내도 되는가」를
적는 것인데, 발신자가 없으면 적을 것이 없다.

### 2단계 — SPF (발신 경로 확정 후)

```
호스트  @
타입    TXT
값      v=spf1 include:_spf.google.com ~all      ← Google Workspace 인 경우
```

⚠ **도메인당 SPF 는 딱 하나다.** 두 개를 넣으면 둘 다 무효가 된다.
발신처가 여럿이면 `include:` 를 하나의 레코드 안에 나열한다.

### 3단계 — DKIM

Google Workspace 관리콘솔에서 키를 생성하면 `google._domainkey` TXT 값을 준다.
**그 값을 그대로 넣는다.** 우리가 만들 수 있는 값이 아니다.

### 4단계 — DMARC (지금 당장 넣어도 되는 유일한 것)

```
호스트  _dmarc
타입    TXT
값      v=DMARC1; p=none; rua=mailto:sibcheongan@gmail.com; fo=1
```

**`p=none` 으로 시작한다.** 처음부터 `p=reject` 로 걸면 설정이 덜 된 상태에서
정상 메일까지 차단된다. 리포트(`rua`)를 받아 보며 SPF·DKIM 이 정렬되는 것을
확인한 뒤 `p=quarantine` → `p=reject` 로 올린다.

> **DMARC 는 SPF·DKIM 없이 넣어도 해가 없다.** `p=none` 은 아무것도 차단하지 않고
> 리포트만 받는다. **지금 넣어 두면 발신 경로를 붙일 때 이미 관측이 되고 있다.**

### ⚠ 붙여넣을 때 — 탭·공백 사고

klifemap.ai 의 `_dmarc` 값 **맨 앞에 탭 문자**가 들어가 있었다(klifemap 세션이 발견·수정).
RFC 7489 는 이 값이 `v=DMARC1` 로 **시작**해야 한다고 정한다. 구글은 관대하게 읽었지만
**엄격한 수신 서버는 DMARC 가 아예 없는 도메인으로 취급한다.**

Spaceship UI 에 붙여넣을 때 생긴 것으로 보인다. **넣은 뒤 반드시 조회해서 확인한다.**

```
nslookup -type=TXT _dmarc.seoulmarkets.com launch1.spaceship.net
```

## 3. 인증만으로는 부족하다 — 콜드메일 실무

인증은 **입장권**이고, 도달률은 그 다음 문제다.

| 항목 | 기준 | 우리 상황 |
|---|---|---|
| 도메인 나이 | 새 도메인은 신뢰가 0 | seoulmarkets.com 은 **새 도메인이다** |
| 워밍업 | 며칠~몇 주 소량부터 | 아직 한 통도 안 보냈다 |
| 반송률 | **2% 미만** | 주소를 검증하고 보낸다 |
| 스팸신고 | **0.3% 미만** (0.1% 권장) | 대량 발송을 안 하는 것이 최선의 방어 |
| 원클릭 수신거부 | RFC 8058 | 마케팅 메일이면 필수. **개인 대 개인 메일이면 불필요** |

**우리 전략이 이 문제를 이미 상당 부분 피해 간다.**
`타깃과-아웃리치.md` 에 「한 번에 하나씩, 사람 이름으로, 대량 발송하지 않는다」고
적어 뒀다. 대량 발송을 안 하면 스팸신고율·반송률 문제가 거의 생기지 않는다.
**남는 것은 인증뿐이다.**

## 4. 실행 순서

| 순서 | 항목 | 누가 | 지금 가능? |
|---|---|---|---|
| 1 | **DMARC `p=none` 넣기** | DNS 접근자 | **지금 가능** — 해가 없다 |
| 2 | 발신 경로 결정 (Workspace 등) | 사장님 | 비용 판단 필요 |
| 3 | SPF·DKIM | DNS 접근자 | 2번 이후 |
| 4 | 도메인 워밍업 | 나 | 3번 이후, 아웃리치 시작 전 2주 |
| 5 | `p=quarantine` → `p=reject` 상향 | DNS 접근자 | 리포트 확인 후 |

**1번은 오늘 해도 된다.** 나머지는 발신 경로가 정해져야 움직인다.

---

## 5. 이 문서가 말하는 진짜 문제

**영업 자산을 만들어 두고 배달 경로를 안 만들었다.**
제안서·문안·타깃 리스트를 다 썼는데 보낼 수가 없다.

같은 종류의 구멍이 또 있는지 봐야 한다. **만들어 놓고 닿지 않는 것** —
예를 들어 클라이언트 라이브러리를 만들었지만 npm·PyPI 에 없고,
API 를 만들었지만 RapidAPI 에 안 올렸다.
**「만드는 것」과 「닿게 하는 것」은 다른 일이고, 후자를 계속 빠뜨리고 있다.**
