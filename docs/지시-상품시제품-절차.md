## Ⅰ. 🔴 먼저 지워야 할 것 — 「전문가 수작업분석」

사장님이 주신 `점성학_상품 포트폴리오(안)` 의 6·7번 상품에 이렇게 적혀 있다.

```
✓ 전문가 수작업 분석 (AI 아님)
  - 실제 점성학자가 작성
  - 당신의 출생도 정독 후 해석
  - AI 기반이 아님 (신뢰도↑)
```

⛔ **이것은 불가능하다.** 사장님: 「**사람과 일 안한다(경영 원칙)**」
   우리 경영원칙 1번이 「**사람을 거치는 계획을 세우지 않는다** — 채용·동업·중개·부탁 전제 금지」다.
   점성학자를 고용하거나 외주 주는 것은 그 원칙을 정면으로 어긴다.

### ⚠ 다만 「전문가모드」는 살아 있다 — 헷갈리지 않는다

이 둘은 **완전히 다른 것**이다. 실제로 코드를 열어 확인했다.

| | 무엇인가 | 되나 |
|---|---|---|
| **전문가 수작업 분석** | 사람(점성학자)이 손으로 쓴다 | ⛔ **안 된다** |
| **전문가모드** (KLifeMap) | **엔진**이 내는 상세 판정(`gsA`·`gsB`) · 고전 문헌 근거 | ✅ 된다. 이미 있다 |

근거: `klifemap/apiBusiness.js:401` — 「gsA·gsB 는 전문가모드 전용 **상세 판정**이다」
     `klifemap/ai/chatCoachEngine.js:238` — 「**엔진 판단**(전문가모드의 고전 문헌의 근거)」

⭐ 그러므로 6·7번 상품은 **없애지 않는다.** 팔던 말을 바꾼다 —
   「실제 점성학자가 작성」 → **「엔진의 상세 판정 + 고전 문헌 근거를 원문으로 싣는다」**
   ⛔ 「전문가가 정독」·「사람이 검토」 같은 말을 **어디에도 쓰지 않는다.** 그건 거짓이 된다.

## Ⅱ. 절차 — 사장님이 정하신 고리

```
① 1~4번        가능한 서비스를 협의한다        ← 「무엇이 실제로 되나」를 먼저 가른다
② 1~4번        시제품을 개발한다
③ 5번          쉬운말로 수정 · 분량·내용 리뷰
④ 1~4번        재수정하고, 리뷰에 대한 «의견»을 5번에 제시
⑤ 1~4번        시제품을 수정한다
⑥ 5번          리뷰
⑦ 5번          사장님께 결과 보고 — ⭐ **리포트 샘플을 첨부한다**
```

⚠ **④가 한 방향이 아니다.** 5번의 리뷰를 그냥 받는 게 아니라 **의견을 5번에게 되돌린다.**
   5번이 틀렸으면 그렇게 말해야 한다 — 사장님 지시 「아이디어를 무조건 수용하지 말고
   별로인 건 얘기를 해야 돼. 대신 근거를 대고, **근거는 데이터로**」가 여기에도 걸린다.

## Ⅲ. ①에서 가를 것 — 「가능한 서비스」의 뜻

각 상품을 이 셋으로 가른다. **「되게 하겠습니다」로 뭉개지 않는다.**

| 갈래 | 뜻 | 적는 법 |
|---|---|---|
| ✅ 된다 | 엔진·자동화로 지금 된다 | 어느 엔진·어느 파일인지 적는다 |
| ⬜ 아직 못 쟀다 | 되는지 안 되는지 **재 보지 않았다** | 「못 쟀다」로 적는다. 0 으로 채우지 않는다 |
| ⛔ 안 된다 | 사람이 필요하거나 자료 경로가 없다 | **왜** 안 되는지 적는다 |

⛔ **사람이 필요한 것은 전부 「안 된다」다.** 그것이 경영원칙이다.

## Ⅳ. ③⑥에서 5번이 보는 것

사장님 상시 지시가 그대로 검사표다.

```
① 쉬운말        「판정은 엔진이, 너는 쉽게 쓸 뿐이야」
② 단정 금지     「좋다, 좋지는 않다로 써」
③ 각주로        「각주나 제일 앞에 써…문장에 쓰지 말고, 그럼 어려워」
④ 분량          긴 글은 안 보신다. 넘치면 «줄이는 게 아니라 잘라서 알린다»
⑤ 그릇          「그릇이 내용물을 결정한다」 — 렌더해서 눈으로 보고 완료라고 한다
⑥ 사실만        못 잰 것은 「못 쟀다」. 0 으로 채우지 않는다
⑦ 사람 없음     「전문가가 검토」류의 말이 한 글자도 없어야 한다
```
